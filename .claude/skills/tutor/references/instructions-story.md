# story — 小白教学故事链

## 这是什么

生成一套完整的教学故事，放在 `output/{课程名}/teach/` 下。

**一个 Story Arc = 一个 MD 文件 = 一本"小说"。** 内部按知识点分章节，章节之间一环扣一环，连贯叙事，读者从头读到尾就像看一个完整的故事。

不要把每个知识点拆成单独的文件。碎片化的文件破坏阅读体验。

**核心设计理念**: 读者是一个聪明但对这门课一无所知的人。每一章只假设读者读过前面的章节，绝不使用任何未在前文讲过的术语。像一个耐心的资深前辈，坐在你对面，从最简单的事情开始，一步步把你带到完整理解。

## 执行流程

### Phase 0: 准备 + 发散校准

**Step 0.1 — 读取材料:**

1. 读取 `output/{课程名}/concepts.json`，获取全部知识点和依赖图
2. 读取 `output/{课程名}/course-outline.md`，获取模块结构和考试信息
3. 读取 `output/{课程名}/mental-model.md`，理解全局认知框架；读取 `output/{课程名}/lecture-flow/L{N}.md`（scan Phase 1.6 产出）：本讲老师的开场问题、过渡、例子、原话与逐步评价
4. **按顺序读三份写作规范** (顺序即优先级, 外层压倒内层):
   1. [content-coverage.md](content-coverage.md) — **Layer 0 内容层**: 课件 100% 进正课、导读条带课件页、讲末课件对照表、外部补充三级标记、保真清单、验证脚本。**最高优先级**
   2. [presentation.md](presentation.md) — Layer A/B 表达层: 节奏编排、12 种块类型、读法指南。它是**加法**, 加在完整覆盖课件的正课之上
   3. [writing-craft.md](writing-craft.md) — Layer C 工艺层: 一个概念怎么讲透 (5 问 3 抽 + 10 步)
5. 如果 concepts.json 不存在 → 提示先执行 `scan`
6. **读取 `output/{课程名}/coverage-audit.md`**（scan Phase 2.5 产出）— 如果不存在，或存在"未覆盖"块，先回 scan 补齐再写 story。concepts.json 是 story 的唯一输入漏斗，scan 漏掉的内容 story 永远看不见，所以必须在此拦截。
7. **读取 `output/{课程名}/raw/_figures.json`**（scan Phase 0 的 extract_figures.py 产出）— 本讲每页有哪些可嵌的课件原图。不存在就先跑 `extract_figures.py courses/{课程名} output/{课程名}/raw`。写作时**原图优先于自绘**（content-coverage.md §1.4）：候选图先用 Read 看一眼 PNG 再决定嵌不嵌，别只看 text_inside

**Step 0.2 — 发散校准 (Divergence Calibration):**

在开始规划教学之前，必须确定发散度。这决定了 teach/ 的内容边界。

**读取信号:**

| 信号来源 | 例子 | 推断方向 |
|---------|------|---------|
| 用户说了什么 | "备考"/"考试"/"低空飞过" | 收紧 |
| | "答辩"/"面试"/"解释项目" | 中等 |
| | "想了解"/"从零开始"/"探索" | 放开 |
| | "时间紧" | 当前基础上再收一档 |
| | "想深入"/"彻底搞懂" | 当前基础上再放一档 |
| 输入材料类型 | lecture PDF | 偏收（课件有明确边界） |
| | 代码 repo / 项目 | 偏放（代码背后的"为什么"需要发散） |
| | 空白话题（没有 courses/ 文件） | 最放（全靠发散建认知） |
| 用户画像 | 有相关背景 | 可以跳基础，发散到进阶 |
| | 完全小白 | 先收着，每层讲透再开下一层 |

**推断三个参数:**

- **`divergence_layers`** (0-3): 发散展开几层
- **`divergence_breadth`** (1-8): 每层每个核心概念最多展开几个关联概念
- **`relevance_threshold`** (严格/中等/宽松): 关联度门槛

**推断方法**: 不是 if-else 查表，而是综合所有信号做判断。常见组合供参考:

| 场景 | layers | breadth | threshold |
|------|--------|---------|-----------|
| 考试复习（课件 PDF） | 0-1 | 1-2 | 严格 |
| 项目答辩（代码 repo） | 2 | L1:≤5, L2:≤2 | 中等 |
| 领域探索（空白话题） | 3 | L1:≤8, L2:≤5, L3:≤3 | 宽松 |

这些只是锚点，实际值根据信号综合判断。

**必须向用户确认:**

> "根据你的目的（{用途}）和材料（{类型}），我打算按 **{N} 层发散、每层最多 {M} 个**展开。OK?"

用户可以说:
- "OK" → 确认
- "再收一点" → 减 layers 或 breadth
- "再放一点" → 加 layers 或 breadth
- "不要发散" → layers=0，纯守范围
- 给出具体数字 → 直接使用

**确认后把参数记在内部状态**，后续 Phase 1-4 都使用这组参数。

**"追问链"生成方法** (确定发散展开哪些概念):

对每个核心概念 A，问:

> "如果有人在 {用户场景} 中提到了 A，对方最可能追问的下一个概念是什么？"

这个"追问"的 top-N（N = breadth）就是 L1 发散概念。对 L1 中的每个概念递归同样的追问，得到 L2。

追问链的判断依据:
1. concepts.json 的 dependency_edges（显式依赖）
2. knowledge-graph 的关系表（contrast/implements/part_of）
3. 行业常识（"提到 Docker 一定会被问 K8s"）

**只有超过 relevance_threshold 的关联才展开。**

### Phase 1: 规划故事弧线（含发散概念）

基于 concepts.json 的 `learning_order` + `dependency_edges` + **Phase 0.2 的发散结果**，规划完整教学序列。

**规划原则:**
1. **严格依赖前置** — 每个知识点（包括发散概念）的所有 dependencies 必须在它之前出现
2. **核心先行** — 同一 Arc 内，核心概念优先于发散概念
3. **发散概念紧跟核心** — L1 发散概念插在它对应的核心概念后面（"讲完 Docker 后紧跟讲 Docker 为什么被选、和 Podman 的对比"），不要把发散概念攒到最后集中讲
4. **叙事连贯** — 一个 Arc 内的知识点围绕同一主题，不跳跃。**默认沿讲者脉络的推进**：老师的悬案→反例、过渡页、贯穿多页的例子照走，例子优先用老师的（跨几页就跟几页，不中途换成自编例子）；只在讲者脉络标了"目的后置 / 缺动机 / 先用后讲 / 理由偏弱"的地方调整，调整处在规划表里注明
5. **适当合并** — 强耦合的知识点合并成同一章节进行对比讲解
6. **每个 Arc 自成一体** — 有自己的开篇引入和结尾收束
7. **先定重点，再排篇幅** — 规划的第一步不是列 §，是回答"读者读完只该记住哪 3-5 件事"（判据与配额见 content-coverage.md §2.1）。这 N 条写进讲首的 `## 本讲大纲`，并**决定每个 § 能写多长**
8. **节奏编排** — 规划时给每个 § 同时评**分量**（🎯核心 / 常规 / 背景）和**负载**（轻 / 中 / 重），两把尺的分工见 presentation.md。**不允许连续 3 个重 §**、也不允许连续 3 个以上轻 §（说明该合并）；两个重 § 相邻时交界处预留 ☕ 换气
9. **规划表七列: § / 标题 / 分量 / 负载 / KP / 课件页 / 原图** — 先把 concepts.json 里本讲的**每一个 KP** 和课件的**每一页**分配到某个 §（或标豁免），再动笔。分配不完的 KP / 页就是你还没想好怎么讲的内容，**不允许留白**。KP / 课件页两列直接变成讲末「课件对照表」的骨架，也是 verify_teach.py 对账的依据。**原图列**从 `_figures.json` 挑：该 § 要嵌哪几张课件原图（文件名），表格 / 装饰图 / 满屏文字页不选；选了原图的 § 不再自绘同一张图
10. **分量列写完先自查一遍**：标了 🎯核心 的 § 是不是就是第 7 条那 N 条？标了背景的 § 加起来是不是 ≤ 15%？不对就在规划阶段改，别等写完再砍

### Arc 0 强制要求（默认必写，不能省）

**Arc 0 是这门课的"序章"**，独立于主线 Arc，但**默认每门课都必须写**。它不教任何具体知识点，目的是给读者一张**全局地图**和**入场票**。

Arc 0 必须包含 4 个 section（缺一不可）:

#### §1 为什么这门课长这样
- 这门课在它的领域中处于什么位置（是 intro 还是 advanced？）
- 时代背景：当前学界 / 工业界在这个方向走到哪了
- 课程特色：跟同主题其它课程比，这门课的独特视角
- 读者画像（谁会上这门课、为什么）

#### §2 你应该已经会什么 — Bring-up 前置常识
**不要假定读者全懂，但也不能从零教。** 这一节列出本课**默认你会**的前置知识，让读者自检是否需要补课。

格式建议:
- **必备**：列 5-8 项硬性前置（缺了读不下去的）
- **加分**：列 3-5 项有了更轻松的（可补可不补）
- 每项一句话说"为什么需要"+ 一句话指向哪里补（教科书章节 / 经典视频）
- 末尾给一个 **30 秒自检清单**（"如果以下问题你 3 个以上答不出，先去补 X"）

#### §3 课程大图：每个章节怎么连
- 用 **栈式 / 层次化 / 流水线** 等结构（不是一长串 lecture 列表）展示**所有 Arc 的相互关系**
- 推荐用 **ASCII 图**视觉化（PDF 编译时会等宽渲染）
- **编排逻辑**：解释为什么 Arc 是这个顺序，不是教学组的随意排列
- 标出**主线 vs 支线**：哪些 Arc 是必走，哪些可按需

#### §4 暗线 — 串联整门课的反复出现的"思想"
这是 Arc 0 最有价值的部分。把整门课**反复出现的核心思想**抽出来，告诉读者:
- "你将看到 X 思想反复出现在 Arc N / Arc M / Arc K"
- "学完这门课你会发现，看似不同的技术其实在做同一件事的不同 instance"

例: 大数据课的暗线是 "scale out + move code to data + sequential I/O"；深度学习系统课的暗线可能是 "低秩近似 + 异构资源拆分 + 二阶动量"。

至少抽 3-5 条暗线，每条标出它出现在哪些 Arc。

**这一节是把课程从"知识列表"变成"心智模型"的关键。** 写不好这一节，整个 Arc 0 就只是华丽的 TOC，没有真正的入场价值。

#### Arc 0 的写作风格

- **不需要严格的 🔍 入门/现实两段式 box**（因为 Arc 0 还没引入具体技术概念）
- 但**通俗易懂、入门为先**的总体风格保留
- 类比和钩子可以更"宏观"（关于学科本身、行业历史等）
- 长度: 通常 250-400 行，比一般 Arc 短，但是**密度更高**

### Phase 2: 逐 Arc 生成

每个 Arc 生成一个 MD 文件。对于每个 Arc:

**生成前准备:**
1. 确定该 Arc 包含的所有知识点及其在 Arc 内的排列顺序
2. 读取所有相关知识点在 concepts.json 中的完整信息
3. 读取这些知识点来源的课件文本（`raw/*.txt` 中对应页码的内容），确保讲解基于课件原始内容
4. 如果知识点来源页有视觉内容（`raw/visuals/` 下有对应 PNG），用 Read 查看图片，将图中信息融入讲解
5. 回顾前面已生成的 Arc，确保跨 Arc 的术语衔接正确

**视觉层级约定（PDF 编译时按标记自动上色）**

标题层级:

| 层级 | 标记 | 用途 | PDF 中的样式 |
|------|------|------|-------------|
| `# Arc N: 标题` | h1 | Arc 大标题 | 大字号 + 蓝色双下划线 |
| `## §N 概念名` | h2 (带 §) | 一个**核心概念** | 蓝色侧栏 + 浅蓝背景，醒目 |
| `## 开篇 / 本篇收束` | h2 (无 §) | Arc 内的导引/总结段 | 同上但语义不同 |
| `### 入门：xxx` / `### 真实场景：xxx` | h3 (在 🔍 内) | 例子内的子段 | 浅色小标签风格 |

内容块 (blockquote) 的**唯一词汇表在 [presentation.md](presentation.md) Layer B 的块类型表**——🧭 导读条 / 🧩 核心角色 / 💡 打个比方 / ☕ 换气 / 🔍 真实场景 / ⚠️ 陷阱 / 🎓 师门心法 / 📌 定义 / 📏 要懂多深 / 🎯 考试提醒 / ✅ 学完这节 / 📎 小补充 / 📍 发散说明。编译器识别 blockquote 首字标记，给每种块独立配色 + 顶部小标签（"换气 · 轻松读 · 跳过不影响主线"这种），读者一眼知道这块该带什么状态读。**标记拼错就不上色**，写完用 Layer B 的统计命令核对。

**emoji 在标题里的使用约定**:
- `## §N 概念名` — § 是必须的（标记这是一个核心概念）；标题里**不放** emoji（会破坏 PDF 目录）
- `### 入门：xxx` / `### 真实场景：xxx` — 字眼标记 🔍 框内的两段
- emoji 只用在 blockquote 首字作为块类型标记

- [ ] **删块测试**：把全部 ☕ / 🎓 / 💡 / 📍 块想象成删掉，剩下的正文是否仍覆盖课件每一页的定义 / 公式 / 表格 / 算例 / 边界警告（content-coverage.md §3 的落点表）？有任何一项只活在补充块里 → 违规，先补正课
- [ ] **顺读自足测试**（content-coverage.md §2.0.1）：从 §1 顺着读到最后一节，每节结尾停下，**只用这一节 + 前面所有节给过的东西**（不回翻课件、不查外部、不拿"常识"搪塞），问"小白到得了这节的 ✅ 目标吗"。
  - 到不了 → **那一节加权多说**：补例子 / 补中间步骤 / 补"为什么是这样"。判断手感：读着像剧情马上进高潮却被夹断，或像侦探剧推理站不住脚、关键处没交代 —— 哪一步让你"嗯?"就补哪一步
  - 到得了但同一件事已经第三遍 → **精简**：删重复的定位段和二次复述（别删例子）
  - 补出来的字数优先从重复段和背景 § 挪，不要让整篇变长
- [ ] **目标覆盖总目标**：大纲「必须带走的 N 条」每一条都能指到承担它的 §；某个 § 的 ✅ 目标既不服务于任何一条、也不为后面的节做地基 → 砍掉或压成背景（content-coverage.md §2.0）
- [ ] **权重复核**（content-coverage.md §2）：按字数把 § 从长到短排一列，最长的几节是不是就是大纲里"必须带走的 N 条"？不是 → 砍长错的那几节，不要靠给重点加字来配平
- [ ] **原图取舍**（content-coverage.md §1.4）：`_figures.json` 里本讲的每张非表格、非装饰图，要么嵌了，要么能说出为什么不嵌（同图重复 / 文本已完整表达 / 图不清）。嵌了的，Read 一次编出来的 PDF 页确认图没被裁掉标签
- [ ] **保真清单**（content-coverage.md §5）：⚡ 标课件外 / 表格逐格照抄 / 禁伪精确 / 出处不伪造 / 引用不空头 / 推导展示算式 / 笔误照抄加注 / 抽 5 项回 raw grep

### 门 3 · 反模式扫描（写到这些立刻停下重写）

#### 内容层（最高优先级）
- ❌ 课件的某个公式只在 🎓 里出现，正课没有原式
- ❌ 课件的算例被换成"编个数演示"的虚构数（虚构只能**另加**，不能**替代**）
- ❌ 老师的例子只出现在 🔍 的入门虚构段（虚构段是自编的，不算覆盖）
- ❌ 老师强调的边界只在 🎓 透镜 3 里当"从业者判断"
- ❌ 对照表某页的位置填了 ☕ / 🎓 / 💡，或某页干脆没有行
- ❌ 改版后旧版有的页 / KP 新版没了

#### 元叙事污染
- ❌ heading 或引用块前缀出现 "对照式发散 / 痛点-方案-效果 / raise + reject / 插件式补充 / 结构化叙事"——技法名是 LLM 的内部代号，不是给读者的内容标签。改成内容化命名（`## §6 训练显存 — 7B 模型为什么单卡装不下`）

#### 权重层
- ❌ 一页课件的动机图 / 路标页配齐了 💡 + ☕ + 📌 + 📏 + 🎯，跟必考公式那节一样长
- ❌ 📌 定义把正文刚出现过的整张表或整条公式又抄了一遍（它是速查卡，不是备份）
- ❌ 背景 § 超过 800 字，或背景 § 比某个 🎯核心 § 还长
- ❌ 讲首没有 `## 本讲大纲`，读者读到第 12 节还不知道哪几节是重点
- ❌ 某个 § 没有 ✅ 目标块，或目标写成"理解了 X / 熟悉 Y"这种验不了的词
- ❌ 大纲的「必须带走」某条指不到任何 §（谁也没负责教它）
- ❌ 读者顺读到某节结尾达不到这节的目标，缺的那一步只在课件里有（等于"读者自己去看课件"）
- ❌ 同一个定位 / 同一句话在三节里各说一遍，却在要推导的地方一步跳过去

#### 表达层
- ❌ 三个推导 § 连着来，中间不让读者喘
- ❌ 换气块写成"前面有点累，喝口水继续"（零信息寒暄）或偷偷讲新机制
- ❌ 把正课内容包进 💡 只为凑质地；给分类 / 记号概念硬造 🧩
- ❌ 导读条分钟数与文件头总时长对不上
- ❌ 🎓 写成更多公式细节或带年份的历史八卦

#### 工艺层
- ❌ 一个 § 全是 bullet list 没有故事；一个 § 全靠表格没有叙事段
- ❌ "Spark 比 Hadoop 快"后面没开盒（快在哪 / 为什么 / 懂多深）
- ❌ 首次出现的产品没自报家门；用一个新名词解释另一个新名词；自造抽象词不解释
- ❌ 数学公式直接贴，没先讲思路；"为什么不是 B"留到后面单开一节
- ❌ 边界情况只给结论不给推理

### 不通过怎么办

**重写那一节**（不是整个 Arc / 整讲）。重写后再从门 0 过一遍。**直到四道门全过**才进下一个 Arc / 编 PDF。

**用户用途不影响这个 gate**——即使用户说"备考"，四道门照过。考试和答辩的差异只在**发散范围**，不在**内容覆盖和写作方式**。

## Phase 3: 编译 PDF（必做，不要跳过）

所有 Arc MD 生成完成后，必须自动调用 PDF 编译脚本，把 `teach/` 下的 index + Arc MDs 合并成一个手机可读的 PDF。

**前提**: 每个 MD 都已通过 Phase 2.5 门 0 的 `verify_teach.py`（PASS）。编译器只管排版，不检查内容——别用漂亮的 PDF 掩盖漏页。

**为什么必做**: 用户明确要求了这个产物。教学故事链的 MD 文件分散在 teach/ 下，PDF 是整合索引 — 手机开卷考时能快速翻找知识点来龙去脉。

**执行命令**:

```bash
<python> ${CLAUDE_SKILL_DIR}/scripts/compile_story_pdf.py output/{课程名}/teach
```

其中 `<python>` 用和 scan 命令一样的 Python 探测顺序（`which python3 || which python`，找不到则搜常见路径）。

**脚本依赖**:
- `markdown` + `weasyprint` + `pymdown-extensions` (Python 包)
- 如果缺失，提示用户运行:
  ```bash
  pip install --user --break-system-packages markdown weasyprint pymdown-extensions
  ```

**产出**: `output/{课程名}/teach/full-story.pdf`（单讲模式加 `--only {N}-slug.md`，产出该讲同名 PDF）

**PDF 自动处理（脚本会做的事）**:

1. **自动生成可点击目录页**（封面后第二页）— 显示完整 Arc → § 层级，每条都可点击跳转。MD 里不需要手写目录。

0b. **课件原图自动成图框**: `![课件 pN · 图注](../raw/figures/xxx.png)` 独占一段 → 白底细框 + "课件原图" chip + 图注，不跨页；图注以 `自绘` 开头的用灰 chip。图片路径相对 teach/ 解析。

0. **按块类型标记自动上色**: blockquote 首字是 🧭/🧩/💡/☕/🔍/⚠️/🎓/📌/📏/🎯/📎/📍 之一时，编译器给它独立配色和顶部小标签（如"换气 · 轻松读 · 跳过不影响主线"）。这是 Layer B 视觉签名的落地——写作时只管用对标记。

2. **正文里的引用自动变成 PDF 内跳转链接**:
   - `Arc N` → 跳到 Arc N 的封面页
   - `Arc N §M` → 跳到 Arc N 的 §M 章节
   - `§M`（在 Arc 内）→ 跳到当前 Arc 的 §M 章节
   - `KP-X.Y` → 跳到该知识点所在的章节（通过 index.md 的 KP 表映射）

3. **MD 文件链接自动改写为 PDF 锚点**:
   - `[xxx](2-cloud-models.md)` → 自动变成 `[xxx](#arc-2)`
   - `[xxx](index.md)` → 自动变成 `[xxx](#index)`
   - 这意味着你在 MD 中可以正常写文件链接（在 IDE 里能跳转），编译后 PDF 也能跳。

写 MD 时只要**保持引用格式统一**，脚本自动识别：
- ✅ 推荐写法: `Arc 3 讲过`、`Arc 4 §9`、`§3`、`KP-5.7`、`[Arc 2](2-cloud-models.md)`
- ❌ 避免非标准: `第 3 弧`、`前面第九节`、`KP5.7`（少连字符）

注意事项：
- 脚本不会在 `<pre>`、`<code>`、`<a>`、`<h1-6>` 内替换（避免代码和标题被误链接）
- 因此标题里的 `§1 xxx` **本身不会变成链接**（避免破坏标题），它只是跳转目标

**字体处理**:
- 脚本自动探测 CJK 字体（优先 WSL 下的 Windows 字体 /mnt/c/Windows/Fonts/msyh.ttc，其次 Linux 的 Noto CJK / 文泉驿）
- 如果找不到任何 CJK 字体，脚本会警告但仍生成 PDF（中文可能显示为方框）
- 如果遇到此情况，提示用户安装:
  - Ubuntu/Debian: `sudo apt install fonts-noto-cjk`
  - 或将 Windows 字体目录挂载给 WSL

## 特殊情况处理

### 合并讲解
当多个知识点是"对比关系"（如 Full vs Para vs HW-Assisted Virt）时:
- 合并到同一个 § 章节中对比讲解
- 用表格或并列结构突出差异
- 在 index.md 的知识点索引中，所有被合并的 KP 都指向同一个 Arc + §

### 跨 Arc 依赖
当一个 Arc 中的知识点依赖前面 Arc 的概念时:
- 如果是上一个 Arc 刚讲过的 → 开篇衔接中自然带过
- 如果是更早的 Arc → 在用到时简短提一句"我们在 Arc N 讲过的 {概念}"

### Arc 内分支合流
当一个知识点同时依赖本 Arc 内多条线索时，在该章节开头用一句话串联:
"前面我们分别讲了 A 和 B，现在它们要在 C 这里汇合。"
