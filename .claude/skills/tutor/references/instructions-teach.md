# teach — 讲解知识点

## 执行流程

1. 读取 `output/{课程名}/concepts.json`，定位目标知识点
2. 如果找不到精确匹配，模糊搜索并让用户确认
3. 检查依赖 — 如有未讲的前置知识点，提醒用户并建议先学

## 输出格式

```
📍 大图定位: {所属模块} > {知识点名称} | 依赖: {前置} | 被依赖: {后续}

## {知识点名称} ({English Term})

**直觉**: {日常类比，一两句话秒懂}

**为什么需要它**: {解决什么问题，没有它会怎样}

**精确定义**: {一句话定义，需要时附公式}

**拆解**:
{分步理解，每步建立在前一步上。只在内容确实需要多步时才分步，简单概念不要硬拆}

**例子**: {课件中的关键例子，附出处}

**易错点**: {常见误区，没有就不写}

---
📍 当前认知地图:
{已学内容的最小关系图，ASCII 或层级列表}

👉 下一步建议: {最适合接着学的 1-2 个知识点}
```

## 发散展开（讲完核心后）

讲完核心知识点后，如果发散校准已激活（SKILL.md Phase 0.2），自动执行:

1. 对刚讲的概念 A，用"追问链"方法生成 L1 发散（最多 breadth 个）
2. 列出发散概念: "⚡ 讲完 A，关联度最高的概念是: B, C, D。要展开哪个？"
3. 用户选一个 → 按 L1 深度讲解（直觉+定义+和 A 的关系+"为什么会被追问"）
4. 讲完 L1 后可以继续追问到 L2（如果 layers ≥ 2）

如果发散未激活（layers=0），跳过这步，直接给下一步建议。

## 约束

- 严格遵守主文件中的"解释风格"规范
- 讲完后**等用户确认**，不自动继续下一个
- 来源标注: 核心概念标注来源（课件页码）；发散概念标注 ⚡ 和发散理由
- 发散内容的写作深度按层递减（详见 writing-craft.md 的"发散内容写作规范"）
- 讲解正文遵守 presentation.md Layer B 的块类型约定：速查定义用 📌、类比用 💡、常错点用 ⚠️、核心机制讲完基础层后可附一个 🎓 师门心法（知其所以然，考试不考）。单点讲解不需要 🧭 导读条和 ☕ 节奏规则——那是长文用的
