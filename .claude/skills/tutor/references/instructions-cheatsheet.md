# cheatsheet — 考场速查手册

## 这是什么

生成一套**打印友好**的考前速查，放在 `output/{课程名}/cheatsheet/` 下。

**默认前提**: 用户已经读过 teach/ 故事链。cheatsheet 不再做认知建立 — 它只做一件事: **考场上 5 秒内查到答题素材**。

## 自足铁律（最高优先级）

**默认这份 PDF 是用户在考场上唯一的纸质参考资料。**

所以**任何"内容在课件里、这里不重复"的写法都是 bug**。不许出现:
- "详见课件 pXX 的图"
- "这一节和 §X 相同，不重复"
- "记住结论即可，推导见课件"

课件页码**只能作为出处标注**（方便考后回查），**不能作为内容的替代**。
每一条公式、定义、状态图、例题步骤都必须**完整落在册子里**。

自足不等于啰嗦。反过来要求同样硬: **以应试为目的，用最简流程展示核心**——
该给的一条不少，不该给的一个字不多。课件用三页推的东西，这里用五行给出
"画链 → 割线平衡 → 用 p₀ 表示 → 归一化"就够，但这五行必须真的在。

## 不许 overfit 到某一场考试

cheatsheet 是**这门课的应试范式**，不是某次 test 的临时抱佛脚。所以**不写**:
- 具体的考试日期、地点、时长
- 题型与分值构成（"8 道单选 + 2 道大题"）
- 按那次题型切的时间分配表
- "本次大题最可能考 X" 这类押题

这些信息**用来指导你怎么配篇幅**（见 Phase 0），但**不写进产物**——
下一次考试范围一变，整册就废了。产物里只保留课程名与覆盖范围。

## 设计哲学（不可妥协）

**目标分数 60-70%，不是 A+。** 从打分逆推最该覆盖什么。

- ❌ 不讲原理（teach 已做完）
- ❌ 不写故事 / 类比展开（cheatsheet 是查阅工具）
- ❌ 不写整段英文模板（用户考场上读不动也用不上）
- ❌ 不参考 [writing-craft.md](writing-craft.md) — 那是 story 用的，cheatsheet 风格相反
- ✅ 每条信息必须**扫描 5 秒内能用**
- ✅ 中文要点旁挂英文片段，让动笔时省去翻译摩擦

## 双语分工（硬规矩）

**中文做路，英文做料。** 两种语言承担两件不同的事，不许混着写:

| 层 | 语言 | 承担 | 写法 |
|---|---|---|---|
| **路由层** | **中文** | "我该翻哪一页" | 通俗、口语、短句；决策表 / 判据 / 陷阱提示 |
| **内容层** | **英文** | "抄什么上卷面" | 公式表、术语、答题句；bullet 或表格，无废话 |

理由: 用户读中文**不费脑子**，定位快；写卷面要的是英文，中间不能有翻译摩擦。
所以每节开头一行中文 `> 🧭 什么时候翻这里 / 什么时候用它`，正文主体全英文。

**判据不是「英文占比」，是「这句话会不会被抄到卷面上」。**

| 这段文字的身份 | 语言 | 例 |
|---|---|---|
| **能抄上卷面的内容** | **英文** | 术语、定义、公式、状态图、答题句、例题的公式与代入 |
| **你自己的逻辑旁白** | **中文** | 怎么读这张表、为什么这一步合法、它跟上一节怎么接、套路总结、陷阱 |

**最常犯的两个错，方向相反：**

**错法一 — 该英文的写成中文。** 概念类知识点写成纯中文表格:
"三种缓存写策略: 写直达 · 写回 · 写绕过"——违规，
因为用户要往卷面上写的是 *write-through / write-back /
write-around*。正确形态是
**英文定义列 + 中文速记列**:

```markdown
| # | Reason | Meaning | 中文速记 |
|---|---|---|---|
| 1 | **Write-through** | every write goes to cache and memory together | 同时写缓存和内存 |
```

**错法二 — 该中文的翻成英文。** 把"怎么读这张图""这一步为什么成立""它和上一节
怎么接"这类**旁白**写成英文，是矫枉过正。旁白是给用户**省脑力**的，英文反而增加
阅读摩擦。课件原话的**引用**用英文（因为可能要照抄），你对它的**解释**用中文:

```markdown
> A write-back cache updates main memory only when a modified line
> is evicted.

**读法**: 平时只改缓存，脏行被换出时才写回内存。所以连续改同一行只付一次
写内存的代价，代价是掉电或换出前内存里是旧值。
```

## 输出文件结构

```
output/{课程名}/cheatsheet/
├── 00-route.md                  # 纯中文路由页 (见下)，必须是第一个文件
├── 01-{topic}.md                # 每个知识区一个文件，约 2 页 A4
├── 02-{topic}.md
├── ...
└── {课程}-{考试}-cheatsheet.pdf  # 合并打印版 (Phase 3 产出)
```

### 00-route.md — 路由页（必做，全中文）

这是整册的入口，用户拿到题目先看它。**它不讲知识，只回答"我该翻哪一页"**。固定五块:

1. **怎么用这本册子** — 三五行，说清"先看哪、册子是自足的、不用翻别的"。
   ⛔ **不要写考试时间 / 地点 / 时长 / 题型分值 / 时间分配** —— 那是 overfit 到某一场考试，见上方铁律。
2. **大图** — 每一讲一行，回答"这讲在解决什么问题"。用户先定位到讲，再定位到节。
3. **看题面 → 去哪一节** — 本册最重要的一张表。左列写**题面会出现的原话或给定量**，
   而且要写得**长而口语**（"题目给了 X 和 Y，问你 Z" 整句写出来），右列写章节号。
   判据要写成"第一刀 / 第二刀"这种递进，不要并列一大堆。
4. **练习题原型索引** — 见下方「练习题必须逐题进册」。**有练习题就必须有这张表。**
5. **符号表 + 同义词对照 + 单位陷阱** — 若课程在不同章节用**两套字母写同一件事**（极常见），
   必须单独出一张对照表点破"这不是两个公式，是一个公式"。符号要给**汉语读音**（λ 拉姆达、ϱ 变体柔）。
   单位陷阱逐条列: "给的是间隔还是速率""给的是单台还是整机"。

## 分区原则（硬规矩）

**一个文件 = 一个 Lecture。一个 H2 section = 一个知识点 (KP)。**

```
01-L1.md   ← Lecture 1 的全部 KP
02-L2.md   ← Lecture 2 的全部 KP
...
```

**不许自创跨讲的主题分章。** 不要出现"通用量与定律""Markov 模型""陷阱合集"这种
按内容重新归类的章节——用户复习时脑子里装的是 lecture 的顺序，cheatsheet 再发明一套
自己的目录，等于逼用户**额外记一遍 cheatsheet 的结构**，考场上多一层翻译。
沿用 lecture 的分法，用户翻册子和翻课件是同一个索引。

**同理不许有"综合性"章节**——"卡住了怎么办""30 秒验算清单"这类跨章节的东西，
用户根本不知道自己什么时候算"卡住"、哪一条验算对应哪道题。**全部拆回到它所属的 KP 里**:
某条守恒式只在算完排队题后有用，它就写在那个 KP 下面，不要抽出来单列一章。

唯一允许的非 lecture 文件是 `00-route.md`（入口路由页）。

**section 编号**用 `L{讲号}-{序号}`，并在标题右侧标**课件页码**:

```markdown
## L3-08 Kendall 记号 A/S/m/K/N/SD · 课件 p29-31
```

页码是用户翻回原课件的锚点，开卷考时必须有。

**KP 不是均分篇幅的理由。** 覆盖要全，但计算类 KP 给完整例题，
概念类 KP 两三行表格说清即可（见 [content-coverage.md](content-coverage.md) 的「覆盖 ≠ 均摊」）。

## 每个知识点的标准结构

**三段固定顺序: ① 中文 route → ② 英文知识罗列 → ③ 例子。** 缺一不可（③ 视 KP 类型）。

### ① 中文 route — 每个 KP 开头三行，不许省

```markdown
> 🧭 **这是什么**：<一句话，说人话，不用术语解释术语>
> 🗺 **大图位置**：<这一讲走到哪一步了，承上启下>
> ⏱ **什么时候看这里**：<题面出现什么词 / 给了什么量，就翻到这>
```

三行各有分工，写的时候自问:
- **这是什么** — 用户扫一眼就知道"我找的是不是它"
- **大图位置** — 用户知道它前后接什么，不会孤立地看一个公式
- **什么时候看这里** — **最重要的一行**。必须写成**可判定的触发条件**
  （"题目给了 λ 和 µ 且只有一台服务器"），不能写模糊状态（"当你需要分析队列时"）。
  写完回读一遍: 用户**不看正文**能不能判断该不该翻这里？不能就是没写好。

### ② 英文知识罗列 — 结构化，不要段落

表格优先，其次 bullet。公式单独成行。**不写解释性散文**。

### ③ 例子 — 见下方「🧮 计算题」与「⚖️ 判断题」

### ⚖️ 判断题 — 写法

**两侧都有命题** → 2 列对照表:
```markdown
| ✅ True | ❌ False |
|---|---|
| "<陷阱原句>" → <一句反例/充要条件> | "<陷阱原句>" → <一句反例/充要条件> |
```
一行 = 两个独立陷阱（左 / 右各一）。一边比另一边多就留空 cell。

**只有单侧** → 标题写 `### ⚖️ 判断题（仅 ❌ False 类）` 然后用 bullet 列表。

**陷阱选择标准**:
- ✅ True 类 → "**违反直觉但其实对**"的命题（例: "Combiner 跑 0/1/多次都不能改变最终结果"）
- ❌ False 类 → "**看着对其实错**"的常见误区（例: "Reduce task 数 = 不同 key 数"）

**T/F 数量平衡（重要）**:
- True 和 False 行数应保持接近（差 ≤ 1）。例: 3T+3F、3T+2F、2T+2F 都可以；3T+1F 不行。
- 不平衡时**把一边的命题反向陈述移到另一边**:
  - 原 ✅: "Combiner 跑 0/1/多次都不能改变最终结果"
  - 反向 ❌: "Combiner 合法的前提是每次调用次数固定"
- 目的: 防止用户在考场上凭"哪边短就选哪边"的 pattern-match 答题，强制读题。

**取材优先级**: past exam Q1 原型 → Tutorial T/F → Revision 标注的 confusions → 自孵化（见下方）

### 🧮 计算题 — 写法

**每一个核心计算点与抽象，都必须挂至少一个走完全过程的 worked example。**
公式表告诉用户"有这条式子"，worked example 才告诉他"这条式子长什么样、代什么数"。
只给表不给例子 = 没做完。

**选例原则: 覆盖最大化，复杂度最小化。** 一个例子要尽量把该节的公式串成一条链
（算出 A 顺手就能算 B、C），而数字要能心算或一步按计算器。宁可一个例子跑十个公式，
不要十个例子各跑一个——后者用户记不住，也看不出公式之间的关系。

**同一组数字贯穿整章**是加分项: 用户只需记住一组数，就能自测全章。
配置变化（"换台更快的""加一倍负载""改成 m 台"）直接在同一组数上做 what-if，
对比表一放，公式之间的因果关系自己就浮出来了。

**例题必须写全三块，缺一块就等于没做完**:

**（甲）题目原文** — 照抄，不要复述、不要缩写。用户要能对照着认出"考卷上这道题长这样"。

**（乙）已知量翻译表** — 把题面的话逐个翻成符号，**每个变量配中文解释**:

```markdown
| 符号 | 题目里的原话 | 值 | 中文：这是什么 |
|---|---|---|---|
| λ | "arrival rate is five robbers per hour" | 5/hr = 1/12 per min | 到达率：每分钟来几个 |
| E[s] | "service time ... average of 6 minutes" | 6 min | 平均服务时间：服务一个要多久 |
```

这张表是**整个 cheatsheet 最值钱的东西**。考场上用户的动作是"把我这道题的数字，
填进你这张表对应的格子里"，所以：
- 「题目里的原话」必须是**英文原句片段**，因为考卷是英文的，用户靠字面匹配
- 「中文：这是什么」必须**说人话**——"每分钟来几个"而不是"到达强度参数"
- **单位换算写在值那一格里**（`5/hr = 1/12 per min`），别让用户自己换

**（丙）逐步求解表** — 每一步一行，**不许合并步骤**:

```markdown
| 步 | 求什么（中文） | 公式 | 代入 | 结果 |
|---|---|---|---|---|
| 1 | 服务率 µ：每分钟能处理几个 | µ = 1/E[s] | 1/6 | 0.1667 /min |
```

铁律:
- **中间步骤全留**。用户考场上是照着抄的，跳一步他就断了。
- **每一步都要有「求什么」的中文**，让用户知道自己算到哪了。
- 「公式」和「代入」**分两列**：公式那列是可以直接搬到卷面上的，代入那列是数字。
- 最后一行给**结论句**（"therefore the SLA is not met"），大题要写这句才拿满分。
**取材优先级**: past exam / tutorial 原题（连数字一起用，因为那就是考试的口径）
→ lecture worked example 简化 → 自孵化。

用了 tutorial 原题要**标出处**（如 `(Tutorial 2 Q2)`），用户知道这题练过。

末尾用 🔑 一行套路（固定动作序列，如"① 哪个 V 变了 → ② V_CPU 要不要跟着变 → …"）。

**数值必须逐个验算。** 写完把所有数字抽出来跑一遍脚本核对，尤其是
与官方 solution 对照时——对不上要么是你算错，要么是课件有笔误，**两种都要查清**。
课件确有笔误时，在正文标出正确值并注明"课件原页印的是 X"，让用户考场上不慌。

**取材优先级**: past exam 计算题 → lecture worked example 简化 → tutorial 题去工程化

### ✍️ 简答题 — 写法

每问独立 panel:
```markdown
**问**: <题目>

**答**:
- 中文要点 *(English fragment)*
- 中文要点 *(English fragment)*
- 中文要点 *(English fragment)*
```

**多问之间**用 `━━━` 分隔（不是 `---`，要更显眼）。

**格式铁律**:
- 中文 bullet = "想清楚答什么"
- `*(...)*` 里的英文片段 = "动笔时直接抄"
- 英文片段是**真句子**（带技术术语），不是带占位符的骨架
- 一个中文 bullet 配一个英文 fragment，一对一 — 不是一段话拆出来塞回去
- 英文用 academic 但不啰嗦的语气，常用动词: yields, requires, guarantees, ensures, must remain invariant, processes, satisfies

**取材优先级**: past exam 简答原题 → 老师 Revision PDF 点出的"why X / how X / X vs Y" → 自孵化

## 练习题必须逐题逐子问进册（硬规矩）

课程发的 tutorial / practice questions **是老师亲手写的题型样本**，考卷上极可能出同型题。
它们不是"参考资料"，是**必须全部落进册子的一等公民**。

**三条铁律**:

1. **逐题逐子问，一个不漏。** 开工前先把练习题的题号与子问号列成清单（Q1(a)…Q3(d)），
   收尾时逐条勾。**只做了 (a)(b)(c) 漏掉 (d)** 是最常见的失手。
   官方 solution 花整页讲的小问（例如某个分布的尾概率怎么推），**必须单独成块**，
   不能压缩成步骤表里的一行。
2. **放进最相关的那一节，不另设"练习题"章节。** 例题跟着它考的那个知识点走 ——
   M/M/1 全套指标的题就挂在 M/M/1 公式表下面，界分析的题就挂在 bounds 总表下面。
   同一节挂两道同型题时，第二道标"**第二道同型题**"。
3. **老师打的题型标签要原样保留。** 很多练习题的题面开头有 `[Warm-up]`、
   `[Design Question]` 这类**方括号标签**，那是老师自己给的分类，
   比任何自创分类都准。写进例题标题，并进路由页的原型索引表。

**路由页的「练习题原型索引」固定四列**:

| # | 老师打的题型标签 | 题面长这样（看到这些特征就是这一型） | 翻哪一节 |

第三列要写得**长而口语**，让用户扫一眼就认出"我这道就是它"。
例: "有人抱怨排队太久，管理层反驳「利用率才 67%，加机器是浪费」，让你判断谁对"。
表下再跟一条「最高频的坑」，把各型踩过的坑并列出来。

**每道练习题例题的开头加一行「一句话思路」**:

> 💡 **一句话思路**：（这题在考什么 + 怎么下手 + 哪一步是真正的考点）

写给一个没做过这题的人看，**通俗、不超过三句**。它回答的是"我为什么要这么算"，
后面的步骤表回答"具体怎么算"。两者缺一不可 —— 只有步骤表，用户换个数字就不会了。

**数字口径要跟官方 solution 对齐，对不上就两个都写。**
solution 里常有四舍五入过的 hint（"取 ξ = 0.87"），自己精确算会差一点。
这时**两个数都给**，并写明哪个用哪个、卷面上该怎么交代来源。

## 题目孵化规则（没有 past exam 时）

很多课程没有 past exam paper。这时从 lecture / tutorial / revision 三处孵化。

### 孵化 ⚖️ 判断题

扫描 lecture 找以下信号:
- "X 必须满足 Y" → 出 "X 满足 Z" 的反命题作 ❌ False
- "很多人误以为 X 是 Y" / "注意区分" → 直接 ❌ False
- 概念对称差: "X 跑在 mapper 端" → "X 跑在 reducer 端" 作 ❌
- 数量关系: "task 数 = 用户配置 R" → "task 数 = key 数" 作 ❌
- 因果关系: "落盘是为了容错" → "落盘是为了性能" 作 ❌

✅ True 类比较稀有 — 一般是"违反第一直觉的对的命题"，例: "Combiner 跑 0 次仍合法"。

### 孵化 🧮 计算题

- 找 lecture 里的 worked example
- 缩小数据规模: 原题 100 条 → 缩到 5 条
- 单字符化: word "the cat" → key "a / b"
- 走完所有 algorithm 步骤（一步不省）
- 输出一行总结性 idiom

### 孵化 ✍️ 简答题

按这 4 类问句模板:

| 模板 | 答 3 段 | 例 |
|---|---|---|
| "Why is X needed?" | 痛点 / 解法 / 代价 | "Why is shuffle expensive?" |
| "How does X work?" | 触发条件 / 步骤 / 输出 | "How does combiner work?" |
| "X vs Y" | 维度 / 适用 / 代价 | "Combiner vs in-mapper combiner" |
| "评估 X 看什么" | 几个轴 + 含义 | "评估 MR 程序效率看什么" |

每条中文要点配一个英文 fragment。英文 fragment 来自 lecture 原文/术语用法（保证 academic 准确性），不要硬翻中文。

## 执行流程

### Phase 0: 读材料 + 确认范围

**Step 0.1 — 读取**:
1. `output/{课程名}/concepts.json`（必须）
2. `output/{课程名}/teach/`（如果存在 — 抽 🎯 例子的钩子来源）
3. `output/{课程名}/exam-prep/` 下的 `revision-key-points.md` / `practice-problems.md`（如果存在）
4. `courses/{课程名}/` 下找 past exam paper（关键词: `past`, `exam`, `sample`, `sem`）
5. `courses/{课程名}/lecture/` 的 Revision PDF
6. **`courses/{课程名}/practical/`、`tutorial/`、`practice*` — 练习题与 solution**

**Step 0.1b — 先问考试情报**: 老师的 announce / 考纲**通常不在仓库里**。
开工前先确认这五项，缺了就直接问用户，不要猜:

**考试时间 · 开卷还是闭卷 · 时长 · 题型与分值构成 · 覆盖范围（到哪一讲、含不含 tutorial）**

这五项决定整册的形态: 闭卷有页数上限就要狠压，开卷不限页数则**路由层比内容量更重要**；
题型决定重心（多选多 → 概念与陷阱加厚；大题多 → worked example 加厚）；
时长 ÷ 分值只用来**分配篇幅**（哪些节该厚、哪些节一张表带过），⛔ **不许把时间 / 分值 / 时间分配写进产物**。

> ⚠️ **带 solution 的练习题是最高价值的材料**，优先级仅次于 past exam。
> 它同时给出**题型、数字口径、以及老师认可的解法步骤**——worked example 直接照它的步骤写，
> 用户考场上写出来的过程就和标准答案同构。

如果 concepts.json 不存在 → 提示先 `scan`。
如果 teach/ 不存在 → 警告"未读过 teach 的用户体验会差"，仍然继续。

**Step 0.2 — 题型侦察**:

按优先级判断本课考试题型:
- 优先级 A: past exam paper 直接看 — 题型分布、分值占比、问句模板
- 优先级 B: Revision PDF 老师明确说"要会" 的内容 — 当作必考
- 优先级 C: Tutorial 真题 — 当作题型样本
- 优先级 D: 都没有 → 从 lecture 自孵化（见上面规则）

**Step 0.3 — 向用户确认覆盖**:

```
根据 [past exam / Revision / Tutorial / lecture] 我看到考试题型分布:
- T/F + justify: ~X%
- 写代码 / 计算: ~Y%
- 简答: ~Z%

打算切 N 个 cheatsheet 文件:
01-{topic} (~Y 个 KP)
02-{topic} (~Y 个 KP)
...

每个文件目标 ~2 页 A4 印刷密度。先做 01 当样张？
```

用户确认后再进 Phase 1。

### Phase 1: 一次只做一个文件（样张优先）

**默认行为**: 不一次性生成所有文件。先做用户指定的（或第 1 个）作为样张，让用户看效果再继续。

写文件时严格按"标准结构"。每个 KP 内部按"section 出现条件"决策表挂 4 个 section（不是每个都 4 全）。

写完一个文件后，明确告诉用户:
> "01-{topic}.md 完成，N 个 KP / M 道题。看一眼格式 OK 后继续做 02。"

### Phase 2: 用户确认样张后批量生成剩余文件

样张通过 → 按相同模板生成剩余文件。

### Phase 3: 收尾 + compile PDF

**Step 3.1 — 回填 `00-route.md` 的目录块**: 每章一行，写清"这章管什么 / 对应哪几讲"，
并确认路由表里每一个"翻到 §X.Y"都真的存在。**路由指错比没有路由更糟。**

**Step 3.2 — 陷阱与验算就地安放，不单列章节**:
- 单选陷阱写在**它所属的 KP 下面**，用左右两列对照（✅ 看着错其实对 / ❌ 看着对其实错）
- 验算方法写在**能用它的那个 KP 下面**（"算完 M/M/m 用 E[n]=λE[r] 核一遍"）
- `00-route.md` 末尾可以放一页**考前 5 分钟公式墙**——那是路由页的一部分，不是新章节

**Step 3.3 — 编译 PDF**:

```bash
python3 .claude/skills/tutor/scripts/compile_cheatsheet_pdf.py \
    output/{课程名}/cheatsheet \
    output/{课程名}/cheatsheet/{课程}-{考试}-cheatsheet.pdf
```

脚本已实现: A4 纵向 / 8-9mm 边距 / 8.4pt / 表格带网格线 / 每章新起一页 / CJK + emoji 字体。

**排版密度是硬指标 —— 用户要自费打印。** 两条经验:

- **长表不许整块 `page-break-inside: avoid`。** 一张二十几行的公式表放不下就整块跳页，会在上一页留大半页空白，是页数虚高的最大来源。正确做法: 表格允许断开 + `thead { display: table-header-group }`（续页重复表头）+ `tr { page-break-inside: avoid }`（单行不劈开）。
- **先压行距和间距，再压字号。** line-height、p/table/blockquote 的 margin、单元格 padding 这些加起来能省三成页数，且完全不影响可读性；字号是最后才动的，不要低于 8pt 正文 / 7pt 代码。

收尾时报告页数。若用户嫌多，**只调 CSS，绝不删内容** —— 内容是考场上唯一的参考。

**Step 3.4 — 过门禁**，三项都要看:

| 门禁 | 怎么查 | 失败怎么办 |
|---|---|---|
| **字体接管** | 脚本内置 `check_font_assignment`，编译后自动跑 | 见下 |
| **每节自足** | 脚本内置 `check_sections_self_contained`，编译后自动跑 | 见下 |
| **横向溢出** | 扫 span，`x1 > 页宽 − 8pt` 即溢出 | 拆长行 / 缩表列 |
| **数值正确** | 所有 worked example 的数字跑脚本复核 | 改数，并查是不是课件笔误 |

> ⚠️ **自足门禁查两类洞**，都是实际踩过的:
> - **推诿** —— 用「详见课件 pXX」「对比在 L4-17」代替本体。
>   **册内互指和册外指向一样违规**: 用户手上只有这一份 PDF，
>   "定量对比在 L4-17" 等于这一节什么都没讲。
> - **空壳** —— 去掉 route 三行与 ⚠️/🎯 提示块之后，正文既短（< 150 字）
>   又没有表格或公式块。典型症状是只写了「原则是 X」却没列出 X 的内容。
>
> 写完一节自检一句: **把 route 三行和所有提示块盖住，剩下的内容够不够答题？**

> ⚠️ **字体门禁为什么必须有**: font stack 里若混入系统 emoji 字族名
> （`Segoe UI Emoji` / `Noto Color Emoji`），它们覆盖 keycap 底座字符 U+0030-0039，
> Pango 会把正文里的**数字**整段判给 emoji 字体，按全角宽度排版——
> `CS1234` 会排成 `CS 1 2 3 4`。这在 PDF 里肉眼很容易忽略，但整册数字全废。
> 正确做法: 只保留带 `unicode-range` 的 `CourseEmoji`，其余 emoji 交给 fontconfig 自动回退。

输出: `output/{课程名}/cheatsheet/{课程}-{考试}-cheatsheet.pdf`

## 反模式（绝对不要做）

- ❌ 抄 teach 的故事 / 类比展开 — cheatsheet 没空间讲故事
- ❌ 在 cheatsheet 里写 "为什么需要这个概念"的导入 — user 已经读过 teach
- ❌ 简答题写整段英文模板 — 上次 iteration 已 fail，分散英文片段贴 bullet
- ❌ 计算题用大数据集 — 永远 < 5 条记录，单字符 key
- ❌ **核心计算点只给公式表不给 worked example** — 表是索引，例子才是会不会做的分界
- ❌ **正文主体写中文** — 中文只做路由与陷阱提示，抄上卷面的内容必须是英文
- ❌ **worked example 的数字没验算过** — 必须跑脚本核对，与官方 solution 逐项对上
- ❌ **自创跨讲的主题章节** — 文件按 Lecture 分，section 按 KP 分，不重新归类
- ❌ **设"卡住了怎么办""验算清单"这类综合章节** — 用户不知道何时该翻；拆回所属 KP
- ❌ **例题只给步骤不给题目原文** — 用户认不出考卷上哪道题对应它
- ❌ **练习题漏子问** — Q3(d) 没做是最常见的失手；开工列清单、收尾逐条勾
- ❌ **另设"练习题"独立章节** — 例题必须挂在它考的那个 KP 下面
- ❌ **丢掉老师打的题型标签** — `[Bottleneck & Bounding Analysis]` 这种方括号标签是最准的分类
- ❌ **例题只有步骤表没有「一句话思路」** — 用户换个数字就不会了
- ❌ **界 / 公式类的题只给结果不给代入** — 每条式子都要写"先化简"再写各 N 的值
- ❌ **变量不给中文解释** — "λ = 5/hr" 不够，要写"到达率：每分钟来几个"
- ❌ **合并计算步骤** — 用户是照着抄的，跳一步就断了
- ❌ **route 的"什么时候看"写成模糊状态** — 必须是可判定的触发条件
- ❌ 写文学性句子 / 过渡语 / "总之" / "因此值得注意"
- ❌ 把 ⚖️ 判断题的 ✅/❌ 上下排 — 必须左右对照（仅有单侧除外）
- ❌ 知识点里 4 个 section 强行都凑齐 — 没考点的 section 直接不出现
- ❌ "tip"/"note"/"重要" 这种空标签 — 替换成具体内容或删掉

## 与其他命令的边界

| 命令 | 产出 | 风格 |
|---|---|---|
| `story` | teach/ 故事链 | 鲜活叙事 + 类比 + 渐进 |
| `exam-prep` | exam-prep/ 真题 + 核心认知 | 中等密度，按真题反推 |
| **`cheatsheet`** | **cheatsheet/ 速查** | **极致压缩，考场可查** |

`cheatsheet` 默认依赖 `story` 和 `exam-prep` 已经做完。如果都没做，也能从 lecture 直接生成，但效果会差（缺类比钩子 + 缺真题信号）。

## 练习题进册: 压缩题面时不能丢的两句话

> 来自一次真实失败 (2026-09-15): 速查册把 QT-4 的题面压成两行，读者**完全读不懂题目在说什么**。
> 复盘发现丢掉的正是题面里那句「应用背景」——原题写着 *"the M/M/2 system could be a dual processor
> unit and the M/M/3/3 system could be the number of terminals"*，有它这题就是学过的终端系统，
> 没它就是一道抽象数学题。

压缩一道练习题时，**下面两类句子一个字都不能删**:

1. **应用背景句** —— 题面里"这个抽象模型在现实中是什么"的那句话（"could be a dual processor unit"、
   "the terminals"、"a file server consists of a CPU and two disks"）。它是读者把符号接回现实的唯一桥。
2. **角色定义句** —— 每个符号**是什么量**的原话，尤其当符号名与惯例冲突时
   （QT-4 里 **λ 是服务率不是到达率**；OA-1 里给的是**间隔**不是速率）。惯例冲突处必须显式点破。

可以删的是: 故事包装、重复的背景数据、与解题无关的机构名。

**判据（自检一句）**: 把你压缩后的题面单独拿给一个没看过原题的人，他能不能画出系统的样子？
画不出来 ⇒ 你删掉了上面两类中的一类。

**如果一道题压不进速查册的篇幅还能读懂 —— 那它就不该进速查册**，应该进逐题拆解材料
（见 `output/{课程}/drill/`: 英文原题 → 中文复述 → 拆题 → 系统图 → 量表 → 逐问解答）。
