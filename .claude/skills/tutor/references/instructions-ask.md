# ask — 问题记录与反馈循环

## 触发条件

当用户在学习过程中提出问题时（非使用 /tutor 命令，而是自然提问），自动进入此流程。

## 流程

### 1. 记录问题
将问题追加到 `output/{课程名}/questions-log.md`:
```markdown
### Q-{序号} [{时间}]
**问题**: {用户原始问题}
**涉及知识点**: KP-X.X
**分类**: 🎯主线 / 背景补充 / ⚡发散(L1) / ⚡⚡发散(L2) / 超出范围
**状态**: pending
```

### 2. 判断分类（受发散校准影响）

先判断这个问题落在哪个区:
- **🎯 主线**: 源材料直接覆盖的概念 → 正常回答
- **背景补充**: 理解主线所必需的前置 → 简短回答
- **⚡ 发散范围内**: 追问链 N 层内能到达的关联概念 → 正常回答（标 ⚡），深度按层递减
- **超出范围**: 发散阈值之外 → 极简回应（"这超出了当前教学范围，如果想了解可以告诉我调整发散度"），拉回主线

如果发散未校准（首次自然提问，还没跑过 story/teach），先快速做一次隐式校准:
- 从用户的提问内容和上下文推断目的
- 用默认中等发散度回答
- 之后如果用户继续深入，动态调整

### 3. 回答问题
按主文件的解释风格回答（直觉→意义→定义→例子），简洁不啰嗦。发散内容按 writing-craft.md 的层级深度要求。

### 3. 请求反馈
回答后问一句: "这个解释清楚了吗？有没有需要补充的？"

### 4. 处理反馈
- 用户说清楚了/OK → 更新状态为 `resolved`
- 用户说不清楚 → 换个角度重新解释，再次请求反馈
- 用户提出补充需求 → 补充后更新

### 5. 回写教学笔记
如果反馈表明回答有价值，将核心内容补充到对应 Arc:
- 通过 concepts.json 或 teach/index.md 的 KP 索引表，找到该问题涉及的 KP 在 `output/{课程名}/teach/` 下哪个 Arc 的哪个 § 章节
- 在该 § 章节相关位置末尾追加:
```markdown
> 💡 **补充** (来自 Q-{序号}): {补充内容}
```

如果补充内容影响了教学叙事，建议重新跑一次 `compile_story_pdf.py` 让 PDF 同步更新。

同时更新 questions-log.md 状态为 `resolved, added to Arc N §M`

## questions-log.md 格式

```markdown
# 学习问题记录

## 统计
- 总问题数: N
- 已解决: M
- 高频知识点: [KP-X.X 出现次数最多的]

## 问题列表
### Q-1 [2026-04-12]
**问题**: ...
**知识点**: KP-2.5
**分类**: 🎯主线
**回答摘要**: ...
**状态**: resolved, added to L02
---
```
