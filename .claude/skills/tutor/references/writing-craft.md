# 写作工艺 — 教学叙事的范式

> 这份文件是 `instructions-story.md` 的伴侣文件。Story 命令生成 § 章节内容时必读。
>
> 它不讲工作流, 只讲"一段教学怎么写"。
>
> **不是规则清单, 是程序性流程**: 四层结构 — 内容覆盖 (content-coverage.md, 最高优先级) / 节奏编排与块类型 (presentation.md) / 10 步范式 (本文件)。每步含执行细节/哲学/正反例。

---

## 0. 范式总览

教学写作有四层。最外层是**内容**, 中间两层是**表达**, 最内层是**工艺**; 外层压倒内层:

```
Layer 0  内容覆盖 (Coverage) — 课件 100% 进正课 + 来源页 + 课件对照表 + 保真 + 脚本验证  → content-coverage.md  ← 最高优先级
Layer A  节奏编排 (Pacing)   — § 序列级: 给每节评负载, 硬核之间穿插变奏, 管读者的脑力曲线    → presentation.md
Layer B  内容块类型 (Blocks) — 段落级: 每块内容属于一种模式, 有固定视觉签名                → presentation.md
Layer C  10 步范式 (Steps)   — 概念级: 一个概念从钩子讲到知其所以然                        → 本文件
```

**表达层是加法不是替换**: Layer A/B 的一切 (☕ / 🎓 / 💡 / 节奏) 都加在"正课已完整覆盖课件"之上。把 ☕ / 🎓 / 💡 全删掉, 剩下的正文必须仍然覆盖课件每一页 — 这是 Layer 0 的判定标准。

Layer C 的 10 步:

```
准备 — 写之前 5 问 + 3 抽
  5 问决定形态 (概念形态 / 取舍类型 / 来源 / 首次产品 / 负载评级)
  3 抽防自由发挥 (老师定义 / 老师例子 / 老师边界)

── 基础层: 是什么角色 / 为什么存在 / 怎么运作 / 如何应用 ──
Step 1  Hook         钩子 — 让读者好奇, 1-2 句
Step 2  Define       定义 — 精确定义 + 数学形式 + (复合) 结构图 + (多层) 分层
Step 3  Aid          理解辅助 💡 — 类比 / 画面 / 简图 (短)
Step 4  Role         角色锚点 🧩 — 一句话压缩"它活着为了啥" + 输入输出
Step 5  DeepExample  代表性例子超详细 — 最重的一步; 重概念在它之后接 ☕ 换气
Step 6  Choice       取舍 — 为什么这么选不选别的 (改进型 / 设计选择 / 比较开盒)
Step 7  Reality      真实场景 🔍 — 两段式 + 自报家门 + 边界推理 + 选型决策树

── 进阶层: 为什么它会合理 / 它是被什么范式发明出来的 ──
Step 8  Insight      师门心法 🎓 — 课本之外、原本只有当面问导师才拿得到的理解

Step 9  Calibration  收尾 — 📌 定义框 + 📏 深度档 + 🎯 考试提醒 + 章节过渡

通用文风 (跨所有 Step) — 术语 / 废话 / 语气 / 命名禁地

Step 10 Verify       自查 — grep + 10 步复盘 + 节奏/块类型/心法核对 + 长度
```

简单原子概念可以合并跳步 (e.g. Step 3 跳过, Step 8 跳过), 复杂概念按全 10 步走。**顺序不能换**: 钩子先于定义, 定义先于辅助, 辅助先于角色, 角色先于深度例子; **基础层 (1-7) 不牢, 进阶层 (8) 不开** — 读者先知其然, 再知其所以然。

## 准备 — 写之前 5 问 + 3 抽

### 5 问 (决定后续形态)

下笔前在心里答这 5 问:

1. **概念形态** — 单一原子 / 复合 (X = A + B + C) / 多层抽象 (架构 - 实现 - 实例)?
   → 决定 Step 2 是否附结构图 / 是否显式分层
2. **取舍类型** — 改进型 (X 改进了 Y) / 设计选择 (用 A 不用 B) / 选型决策 (A/B/C 选哪个)?
   → 决定 Step 6 走哪个子情境
3. **来源** — 核心 (源材料里的) / 发散 L1/L2/L3?
   → 决定深度档跟篇幅 (见末尾"发散概念变体")
4. **首次出现** — 这段第一次提到某产品/公司吗?
   → 决定 Step 7 是否加 "自报家门 4 要素"
5. **负载评级** — 这个 § 是 轻 / 中 / 重? (判据见 Layer A)
   → 决定 🧭 导读条怎么写、要不要 ☕、放在哪一步之后; 也决定 Step 8 是否值得开 (重概念和设计选择通常值得, 术语分类不值得)

### 3 抽 (防自由发挥脱课件)

下笔前从源材料 (lecture / 课件 / 代码 / 论文) 抽 3 样, 后续每步对齐:

1. **老师怎么定义** — 老师用什么名词? 一句话定义是什么?
   → **Step 2 的字面源**。老师叫"投影矩阵"就别叫"线性变换"; 老师叫"映射"就别叫"拆分"。
2. **老师举什么例子** — 老师讲这概念时用什么 case?
   → **Step 5 / Step 7 现实段的首选例子**。课件给了的就沿用 (用口语重写, 不照搬), 不另起新例子让学生进度对不上。
3. **老师强调什么边界 / 陷阱** — 老师特意警告什么?
   → **Step 7 边界推理 / 决策树陷阱的源**。老师强调的边界一定收进去。

#### 哲学设计

LLM 自己懂这些概念。如果不强制对齐课件, 写的会是"agent 心里的 QKV"而不是"老师的 QKV"。学生对照课件读 → 进度对不上 → 怀疑自己看错; 考试老师按自己 wording 出题 → 学生用 agent 的 wording 答 → 失分。

3 抽不是限制创意, 是**锚点**。范式骨架照走, 但**词汇 / 首选例子 / 边界警告**必须跟课件同步。

## Step 1: Hook — 钩子

### 执行细节

**§ 标题下第一行先放 🧭 导读条** (格式见 Layer B), 然后才是钩子。导读条是预期管理, 钩子是好奇心制造, 两者不冲突: 读者先知道"这节要花多少力气", 再被勾进去。

导读条只写三样: 负载评级 (轻度/中度/重度) · 预计分钟 (按 Layer A 速率表算) · 该带什么状态 (如 "需要纸笔跟一遍" / "看画面就行" / "对照课件 p12 的表读")。一行, 不展开。

钩子本身: 写 1-2 句引入, 触发读者"我也想知道"。

**两条硬约束** (违反就重写):

1. **只用读者已知的语言抛问题** — 不出现待讲概念的术语 / 机制 / 公式。Hook 的语言池是 "通用中文 + 读者已学过的概念"。讲 Self-Attention 的 Hook 里**禁止**出现 "self-attention / token / embedding / 投影 / Q/K/V" 这种 Step 2 才该讲的词。
2. **不剧透 Step 2 答案** — 钩子是开门, 不是预告片。"答案是什么 / 怎么做 / 为啥这样"留给后续 step。Hook 只负责让读者**想知道**, 不告诉读者**是什么**。

形式三选一:

- **抛痛点**: 用读者熟悉的场景, 演示一个"现在就办不到"的具体问题
- **抛连接**: 接上一节, "X 解决了 A, B 还没解决"
- **抛反直觉**: 用读者已有直觉做对照, "你以为 X, 其实 Y"

1-2 句够, 不展开。

### 哲学设计

教学跟讲座不同: 讲座允许 "接下来我们看 X 的定义" 过渡; 教学不行 — 读者随时会跑, 每段开头必须给停留理由。

但钩子**不能替代定义, 也不能预告定义**。两个失败模式:
- 钩子里塞定义/机制 → 读者还没"想问问题", 答案就抛过去了, 反而无感; 而且术语未解释, 读者卡词
- 钩子全用类比独占开场 → 读者读完只记类比, 不记主概念身份; 10 个概念 10 个张三, 久了抓不住重点

正解: **钩子用读者已有的语言制造好奇, 然后立刻交棒给 Step 2 给身份证**。两者紧接, 各司其职。

### ✓ 正例 (Self-Attention)

抛痛点版:
> 一个词的意思常常取决于周围的词 — "bank" 在 "river bank" 是河岸, 在 "bank account" 是银行。要是给每个词一个固定向量表示, 这两个 "bank" 就长得一模一样, 模型分不清。怎么让一个词的表示**自动**吸收周围词的信息?

抛反直觉版:
> 你读 "I saw her duck" 时, 怎么知道 "duck" 是名词 (鸭子) 还是动词 (低头)? 靠 "her" — 但 "her" 在前面, "duck" 在后面, 模型怎么让 "duck" 回头看 "her"?

(都用读者已知的英文短语 / 中文翻译做痛点演示, 没出现 self-attention / token / embedding / 投影 这些词。读者读完想问 "对啊怎么办", 这就是钩子起效)

### ❌ 反例 — 剧透型 (最常犯)

> Self-Attention 让每个 token 看到句子里其他所有 token, 但 token 的语义不是直接拿来比, 是先**投影到三个不同的子空间**, 再比。

(把 Step 2 的定义 + Step 5 的机制 + Step 6.B 的 reject reason 全提前抛了。token / 投影 / 子空间 都是未解释术语。读者还没想问问题, 答案先来了 — 反而没好奇心)

### ❌ 反例 — 定义型

> Self-Attention 是 Transformer 的核心机制, 它通过计算 query, key, value 之间的点积...

(定义直接进, 没钩子。query / key / value 未解释)

### ❌ 反例 — 废话型

> 让我们来看一下 Self-Attention 是怎么工作的。

(机械过渡, 无好奇心制造)

### ❌ 反例 — 类比独占型

> 想象你在图书馆找书...

(类比抢走 Step 3 的活, 读者读完不知道这段讲啥概念)

## Step 2: Define — 直接抛定义

### 执行细节

钩子之后**立刻**给精确定义。**先抛, 不藏**。

包含 4 件:

1. **中文 + 英文术语** (首次出现): "**Self-Attention (自注意力)** 是 ..."
2. **一句话身份证**: 它是什么 / 输入是什么 / 输出是什么
3. **数学形式 + 维度** (有数学定义时一起给): `X ∈ R^{n × d_model}` 这种符号比文字精确
4. **(复合概念) 结构图先行** / **(多层抽象) 显式分层** (见下方两个子节)

定义这句话**能懂最好, 不懂也没关系** — Step 3-5 会逐步辅助消化。重点是身份证先发出来, 后续所有展开"挂回这一句"。

#### 复合概念 — 结构图先行

复合概念 (X = A + B + C + D) 在主体展开**之前**, 必须给一张结构图:

格式 0 — **课件原图** (有则优先, 见 content-coverage.md §1.4): 老师画过结构图的, 直接 `![课件 pN · ...](../raw/figures/...)` 嵌入, 下面用一段逐组件点名。自绘只补课件没画的

格式 1 — 树形 (自绘时推荐):
```
Self-Attention
├── Q (Query)  — "我想找什么"        X · W_Q ∈ R^{n × d_k}
├── K (Key)    — "我能匹配什么"       X · W_K ∈ R^{n × d_k}
├── V (Value)  — "我贡献什么"        X · W_V ∈ R^{n × d_v}
└── 流程: X → Q/K/V → S (相关度) → A (权重) → Z (输出)
```

格式 2 — 表格:

| 组件 | 角色 | 维度 | 在主流程位置 |

**逐项不能跳过任何组件**。某个组件不打算深讲, 仍然在结构图里列出, 标 📎 (见 Step 7.G)。

#### 多层抽象 — 显式分层

讲多层抽象的概念 (Transformer / MapReduce / Diffusion / RAG) 时, **必须显式分层**, 否则后续会"漂移" — 读者不知道某细节挂哪一层。

模板:
```
X 是 [架构 / 思路 / 范式], 不是 [具体模型 / 产品 / 实例]
- 架构层 (Architecture): X 的设计思想 — 想干什么
- 实现层 (Block / Engine): 可堆叠的具体模块
- 实例层 (Models / Products): 包含这个 block 的实际产品
```

例: "Transformer 是**架构** (让每 token 看到全局), **实现**是 Transformer Block (SA + FFN + Residual + LN), **实例**是 BERT/GPT/T5/LLaMA。"

### 哲学设计

大脑读教学时需要"现在在讲什么"的锚点。**没锚点的内容像漂浮的句子**, 读两段就忘第一段说啥; 有锚点 (= 一句精确定义), 后面所有展开都"挂回"它, 记忆压力小一半。

为什么不让"理解辅助"先行? — 类比/画面是**消化定义的工具**, 不是**身份证**。读完类比读者只记住"图书馆找书", 不记住"自注意力是什么"。10 个概念 10 个图书馆, 久了抓不住重点。

为什么数学形式同步给? — 维度跟形状是定义的一部分。`X ∈ R^{n × d_model}` 这种符号比文字精确; 读者一眼看清数据流向, 后面拆解时所有维度演算对得上。

为什么复合概念必给结构图? — 漏件就是结构性教学失误。学生学完, 如果你列了 4 件他只学了 3 件, **他自己也不知道漏了**; 下次看到第 4 件他不知道挂哪。

### ✓ 正例

> **Self-Attention (自注意力)** 是 Transformer 中让每个 token 看到上下文的机制。输入 token 序列 `X ∈ R^{n × d_model}`, 输出同样形状但**每个 token 已融合其他 token 信息**的新序列。
>
> 内部把 X 通过三个投影矩阵 W_Q, W_K, W_V 拆成三种角色:
> ```
> Self-Attention
> ├── Q (Query)  — "我想找什么"        X · W_Q ∈ R^{n × d_k}
> ├── K (Key)    — "我能匹配什么"       X · W_K ∈ R^{n × d_k}
> └── V (Value)  — "我贡献什么"        X · W_V ∈ R^{n × d_v}
> ```
> 流程是: X → Q/K/V → S (相关度) → A (权重) → Z (上下文化输出)。

(身份证 + 输入输出 + 维度 + 结构图 + 流程方向, 读者读完知道这段在讲什么)

### ❌ 反例

> Self-Attention 听起来很神秘, 但其实是个简单的想法。想象你在读一句话...

(藏定义, 读者两段后还没拿到身份证)

> Self-Attention 用 Q, K, V 三个矩阵。Q 是查询, K 是键, V 是值。

(支离破碎, 三个术语没整体描述, 读者不知道组合起来在做什么)

> Self-Attention(X) = softmax(Q·K^T / √d_k) · V

(直接抛公式当定义。还不知道概念是什么, 看公式只是符号)

## Step 3: Aid — 理解辅助

### 执行细节

定义抛完后, 用一段**辅助消化**, 让"刚刚那句话"在读者脑里有画面。

形式自由, 选最贴的:

- **类比**: "把它想成 ..." (生活场景)
- **画面**: "想象矩阵流过来 ..." (数据流图示)
- **简图**: 课件这页有图就嵌**课件原图** (`_figures.json` 查该页), 没有才自绘 ASCII / 表格
- **一句通俗翻译**: "说人话, 就是 ..."

#### 关键约束

- 这一步**辅助**, 不是主线 — **不超过定义段长度**
- **≥3 行的类比装进 `> 💡 **打个比方**:` 块** (1-2 句的短类比可以留在正文里)。装块的目的是让读者一眼看出"这是辅助, 定义没懂时回来读它", 累了也能只读这些
- 类比要**准确, 不能误导核心** — 错的类比比没类比还坏
- 不引入新术语 / 云厂商产品 (避免"用新名词解释新名词")
- 简单原子概念 (e.g. `requires_grad`) **跳过这步**, 直接 Step 4

#### 类比的灵感方向 — 仅参考, 不限定

不限于以下方向, 任何读者已知的领域都行:

> 餐饮 / 居住 / 出行 / 人物 / 工具 / 团队协作 / 学习场景 / 游戏 / 自然现象 / 古代故事 ...

**判断标准**: 类比里的关系跟概念的关系是否**同构**? 是 → 用; 错位 → 换。同构性比"贴近生活"重要。

### 哲学设计

类比让读者的"已有知识"参与解码 — 没类比读者只能靠陌生符号建模, 慢且易错。

但类比**不能替代定义**。Step 2 已经给了身份证, Step 3 是给身份证配一张照片, 不是给身份证换一张。一句"对应到 X 世界" 把类比 link back 到定义里的术语, 这是关键收尾。

辅助轻就好, **不展开成故事** (那是 Step 5 deep example 干的事)。这步 1-3 句, 给个画面就退出。

### ✓ 正例 (Self-Attention)

> 拿"图书馆找书"打比方:
> - 你心里有一个**问题 (Query)**: 想找关于"机器学习"的书
> - 每本书脊上有**标签 (Key)** 描述自己讲什么
> - 你拿 Query 跟所有 Key 比, 匹配度高的书取**内容 (Value)** 来读
>
> 对应到 Self-Attention: 每个 token 既是 query (问别人), 也是 key (被别人问), 也是 value (被取用)。三种角色由 W_Q / W_K / W_V 投影出来。

(类比短, 紧扣 Q/K/V 三角色, 一句 link back)

### ❌ 反例

> 想象一下你开煎饼摊...

(类比跟概念不同构 — 煎饼摊跟 Self-Attention 没共同结构, 强行误导)

> Self-Attention 就像 transformer block 在做 contextual encoding ...

(用术语解释术语, 读者还不懂 transformer block 跟 contextual encoding)

> 想象注意力分配的过程, 你的大脑在阅读时也是这样工作的, 关注重要的, 忽略不重要的... 大脑里有 attention head 帮你过滤信息... 跟 Self-Attention 类似... (展开了一大段)

(类比膨胀成主线, 占了 Step 5 的空间)

## Step 4: Role — 角色锚点

### 执行细节

写一句话压缩"这个概念活着为了啥"。**所有数学/技术细节后面都挂回这一句**。

格式 (🧩 是角色锚点的专属标记; 🎯 留给考试提醒, 不要混用)。输入/输出**写成列表项**, 否则 markdown 会把三行合并成一段:
```markdown
> 🧩 **核心角色**: X 是一个 [...] 的 [生成器 / 调度器 / 求解器 / 优化器 / 路由器 / 缓存器 / ...]
> - 输入: ...
> - 输出: ...
```

**开不开 🧩 的判据**: 这个概念有没有明确的"吃什么吐什么"? 有 → 开; 是纯定义 / 分类 / 记号 / 术语 → **不开**, 只用 Step 9 的 📌。硬给一个分类概念造"XX 是一个 XX 器"就是为了凑块而撒谎。

一句话压缩需要包含:
- **它是什么样的"东西"** — 生成器? 调度器? 求解器? 缓存器?
- **输入是什么** — 一个数据? 一个 distribution? 一个 query?
- **输出是什么** — 转换后的数据? 一个决策? 一个标量?
- **(可选) 它在大图里挂哪** — 跟前置/后续概念怎么衔接

**位置**: Arc 顶部 metadata 之后 / 核心 § 开头都行, 但**必须在 Step 5 deep example 之前**。

### 哲学设计

学生忘了所有公式细节后, 记住核心角色这一句**能重建心智模型**。这是教学最贵的资产 — 高密度低脑力压缩。

所以这一步是 **Step 5 (deep example) 的索引**: 例子里每个动作都对应回 "它在干 [输入 → 输出]" 的某一步, 读者看完例子能用一句话总结概念在干啥。

### ✓ 正例

> 🧩 **核心角色**: Self-Attention 是**上下文表示生成器**。
> - 输入: 没上下文的 token 序列 `X ∈ R^{n × d_model}`
> - 输出: 看过彼此后的 token 序列 `Z ∈ R^{n × d_model}`

> 🧩 **核心角色**: MapReduce 是**数据并行调度器**。
> - 输入: 一个大数据集 + 一个并行函数
> - 输出: 数据集被切分计算后的聚合

反例 (不该开 🧩): "Kendall 记号是一个**排队系统描述器**" — 记号没有输入输出, 这是硬造。只写 📌 定义框。

### ❌ 反例

> Self-Attention 是 Transformer 中很重要的一个机制。

(没压缩, 没输入输出, 没实质信息)

> Self-Attention 是基于注意力机制的方法, 通过计算 query 跟 key 的相似度...

(在重复定义, 不是压缩"为啥活着")

## Step 5: DeepExample — 代表性例子超详细

### 执行细节

挑 **1 个 (复杂时 2-3 个) 不复杂但能 cover 所有特征的 case**, 走完整流程, 把 Step 2-4 所有点 reasonate 一遍。

这是范式中**最重要的一步**。前面 Step 2-4 是抽象, Step 5 是具体 — 没这一步, 学生只懂概念名字不懂概念是怎么活的。

#### 例子选择标准

- **不复杂**: 数据小, 维度小, 一眼能看完 (e.g. 4-token 句子, 不要 256-token)
- **覆盖面**: 一个例子里要能演示 Step 2 定义的所有组件 / Step 4 角色的所有特性
- **跟课件对齐**: 优先沿用准备阶段 3 抽里"老师举的例子" (3 抽要求)

#### 流程拆解 — 数学概念严格按这个顺序

1. **先讲思路**: 用 1-2 段口语化叙述讲清"这一步想干什么"
2. **再给公式**: 公式作为思路的"形式化记法"出现
3. **拆解符号**: 每个符号 / 每一项分别在做什么 (从局部到整体重组理解)
4. **数值代入** (可选): 给一个具体数字 case, 一步一步算
5. **推导是 optional**: 用来"演示思路", 不是主线; 完整推导参见外部 reference

每一步都**显式 reasonate** Step 2-4 的某个点:
- "这就是为什么 Q/K/V 要解耦 (Step 4 角色) — 看, 这里 Q 单独算自己的相关度..."
- "维度演算: (n, d_k) · (d_k, n) → (n, n) — 跟 Step 2 定义的形状对得上..."

#### 不只是"算一遍" — 是"演示活着"

每个动作做完, 加一句**意义 / 巧思**:
- "为什么要 / √d_k? — 因为 Step 2 定义的 d_k 越大, 点积值越大, softmax 容易爆 (one-hot), 除掉是稳定性修正"
- "为什么这里加 mask? — 因为 decoder 不能看 future token, 跟 Step 4 的角色 '只看历史' 一致"

#### 重概念: 例子之后接 ☕ 换气

Step 5 是全范式脑力消耗最大的一步。**重**概念的 deep example 走完后**紧接一个 ☕** (规格见 Layer A) — 读者刚啃完最难的推导/算例, 这时候一个画面钉子最容易钉牢。推导链特别长 (>25 行) 时, 可以在链中间换一次质地 (数值代入 / 💡), 链末再 ☕。轻 / 中 概念不加。

### 哲学设计

抽象概念在脑子里像没填涂的轮廓 — 知道形状, 不知道内容。Deep example 是 ground 抽象到具体的关键步骤: 一个**简单**但**完整**的 case 走完, 学生能把 Step 2 (定义) / Step 4 (角色) 的所有点跟具体数据对应起来。

为什么"不复杂"? — 复杂例子让学生分心去解码数据, 抓不住流程。**这步教流程, 不教数据**。

为什么必须显式 reasonate? — 不显式连回, 学生看完例子只记得数字流过, 不记得跟概念有啥关系。"看, 这里就是 Step 4 说的 X" 这种连回是把例子转成认知锚的关键。

### ✓ 正例 (Self-Attention deep example)

> 拿一个 4-token 句子 "I love deep learning" 走完整流程。设 `d_model=4, d_k=2, d_v=2`。
>
> **Step 1 投影**: X (4×4) 经过 W_Q, W_K, W_V 投影成 Q (4×2), K (4×2), V (4×2)。
>   - 维度演算: (4, 4) · (4, 2) → (4, 2) ✓
>   - 这就是 Step 2 定义的"三种角色解耦" — 同一个 token "love", 它作为 query 时关心什么 (Q[love]) 跟它作为 key 时怎么被找 (K[love]) 是两个不同向量。
>
> **Step 2 算相关度**: S = Q · K^T (4×4)。S[love, deep] = "love 视角看 deep 多相关"。
>   - 思路: 每对 token 都要算关系强度, query 跟 key 点积大就强
>   - 数值: 假设 S[love, deep] = 5.2
>
> **Step 3 缩放**: S / √d_k。除 √2 ≈ 1.41。S[love, deep] = 5.2 / 1.41 ≈ 3.7。
>   - 巧思: 没除时如果 d_k=128, 点积量级 √128 ≈ 11, exp(11) 天文数字, softmax 输出几乎 one-hot, 梯度几乎 0 → 训不动。除 √d 让数值稳。
>
> **Step 4 softmax**: A = softmax(S, dim=-1) (4×4)。每行和为 1。
>   - A[love, *] = "love 把注意力分配给 4 个 token 各多少比例"
>
> **Step 5 加权汇总**: Z = A · V (4×2)。
>   - Z[love] = A[love, I]·V[I] + A[love, love]·V[love] + ...
>   - 这就是 Step 4 角色说的"上下文化" — Z[love] 不再是单独 love 的语义, 是吸收了句子里其他 token 信息后的新表示。
>
> 整流程一句话回收: `Z = softmax(Q·K^T / √d_k) · V`, 每一步都对应回 Step 2 定义的一个组件、Step 4 角色的"上下文化"目标。

### ❌ 反例

> Self-Attention 公式是 `Z = softmax(QK^T / √d_k) · V`。其中 Q, K, V 由输入投影得到, 矩阵相乘后用 softmax 归一化。

(纯公式描述, 没具体例子, 没流程拆解, 没 reasonate 回前面)

> 用 100 维 embedding, 32 层 attention head, 处理一个 1024-token 的 batch...

(例子太复杂, 学生忙着解码维度, 没法跟概念对应)

> Q · K^T 算相关度, 然后 softmax, 然后乘 V 得到输出。

(只是把公式翻译成中文, 没有"为什么", 没 reasonate 任何前面的点)

## Step 6: Choice — 取舍

### 执行细节

任何概念都有 "为什么这样不那样"。**当下回答, 不留到后面单独章节**。

按准备阶段 5 问的"取舍类型", 走对应子情境:

#### 6.A 改进型 (X 改进了 Y)

适用范围: 架构演进 (Spark vs Hadoop / Transformer vs RNN), 工程优化 (KV Cache / FlashAttention), 算法改进 (AdamW vs Adam / DPO vs RLHF), 训练改进 (Pre-LN vs Post-LN)。

三段式:
```markdown
**痛点**: 旧方案 Y 是什么糟糕状态 (最好带数字 — "n=4096 时这矩阵 67MB")
**方案**: 新方案 X 改了什么 (带公式或伪代码)
**效果**: 省了什么 + 代价是什么
```

> 不适合改进型: 抽象架构概念本身的核心机制讲解 — 用 Step 5 deep example 而不是这个三段式。

#### 6.B 设计选择型 (用 A 不用 B)

四步:
1. **拿出 candidate**: "可能会想, 为什么不直接用 [B]?"
2. **对比 A 跟 B**: 列各自特点
3. **B 的失败模式**: 用反例 / 实验观察 / 理论缺陷指出 B 哪里不行
4. **回到 A**: 重申为什么是 A

经典例: "为什么 LayerNorm 不是 BatchNorm" / "为什么 √d 不是 d 也不是不除" / "为什么 q/k/v 不是同一个投影" / "为什么 Adam 不直接用 plain SGD"。

#### 6.C 比较开盒 (任何 "更 X" 必答)

凡用了"更高级 / 更智能 / 更好 / 更快 / 更强 / 更省事"这类比较, **必须同时回答三问**:

1. **具体在哪?** — 沿什么维度比较? 列 2-3 个具体差异点
2. **怎么做到的?** — 背后什么机制? 给概念性草图, 不必深入实现
3. **要懂多深?** — 考试记什么? 工作怎么用?

**这三问任何一个不答, 不要用比较级** — 改成描述 A 和 B 各自是什么样, 让读者自己比。

### 哲学设计

学生记住 A 的同时记住 B 为什么不行, 价值翻倍 — 既懂正解, 又懂场景边界。

为什么"当下回答, 不留到后面单独章节"? — 读者引入新概念时心里第一个问题就是"为什么不是 X"。这问题不当下答, 后面所有内容都浮着 — "前面看懂了后面再理解意义不大, 前面没看懂可能就放弃了"。

为什么"更 X" 必答三问? — 比较性语言会在读者脑里留三个黑洞 (具体在哪 / 怎么做到 / 懂多深)。三个一并回答, 读者满足; 跳过任何一个, 黑洞带着读者读后续, 越读越糊。

### ✓ 正例 (6.B Self-Attention 为什么 3 投影)

> 可能会想: 为什么搞 3 个矩阵? 直接 `x_i · x_j` 算相关度不行吗?
>
> 答: 那样"任何词跟自己最相关"是被结构性写死的 — `x · x` = `||x||²` 总是最大, 梯度推不动这个偏好。
>
> 引入 3 个独立投影, 让模型**自己学**: 我作为 query 时关心什么 / 作为 key 时怎么被找 / 作为 value 时贡献什么。三种角色解耦, 灵活度大增 — 同一个 token 在 Q 空间跟 K 空间可以学成完全不同的方向。

(四步齐: 拿出 candidate → 对比 → B 失败模式 (结构性写死 + 解释) → 回到 A)

### ✓ 正例 (6.C 比较开盒)

> Elastic 比 Dynamic 高级在三个地方:
> 1. **反应时机** — 嵌在运行时的 Listener 让它能**提前**扩容, 不等阈值
> 2. **扩容粒度** — 能加 CPU/内存而不只是加机器
> 3. **决策复杂度** — 背后是工作流引擎而不是一条 if-then
>
> **怎么做到**: 决策逻辑嵌入运行时 (Listener + Engine + Workflow), 不是外挂监控。
>
> **要懂多深**: 考试记 "外部规则 vs 内嵌引擎"; 工作懂三维度; 实现细节不必深究。

### ❌ 反例

> Elastic 是更高级的自动化。

(三问全没答, 留三个黑洞)

> 自造词没拆: "x · x 总是最大是被结构性写死的" — 没解释什么叫"结构性写死", 直接抛术语

(自造词必须当场拆解, 这是通用文风的"术语管控"延伸到 Step 6)

## Step 7: Reality — 真实场景

### 执行细节

抽象讲完, 给 **🔍 框** 锚定到真实场景: 这玩意工业上真在用吗? 怎么用?

#### 触发条件

- **必加**: 有子分类 / 平级对比 / 易混淆邻居的概念
- **应加**: 重要核心概念 (即使不对比, 也加个真实场景)
- **可省**: 简单原子概念 (e.g. `requires_grad`)
- **位置**: 在 Step 8 定义框之前

#### 7.A 课件例子优先

如果原课件给了好教学例子 (MapReduce 的词频统计 / TCO 三案例对比 / 某个 case study), **优先沿用** (来自准备阶段 3 抽), 因为:
- 读者对照课件学习时**进度对得上**
- 节省脑力 (课件看一次, story 再看一次, 记忆加强)
- 老师出题大概率用课件例子

但课件例子是**素材, 不是成品**:
1. 归类到两段结构某一槽 (理论性对比 → 入门虚构; 完整真实案例 → 现实连贯叙事)
2. 按下面 7.B / 7.C 规则丰富
3. **永远不照搬课件原文表达**, 用口语化叙事重写

课件没给例子或例子不适合做入门时, 自编。

#### 7.B 入门虚构段 (55%)

让读者用最少脑力感受概念核心差异。**不是真事儿, 为概念服务**。

**5 条要求**:

1. **场景最小化** — 一两句设定 ("假设你开煎饼摊, 早高峰排队太长"), 不铺陈
2. **每分类对应一个具体动作** — 不是抽象描述, 而是"加李四" vs "升装备"这种能想象的画面
3. **显式 link back 到概念** — 场景讲完后必须有一行映射:
   ```
   > **对应到服务器世界**: 张三李四 = 服务器; 加李四 = 水平扩展; 升装备 = 垂直扩展
   ```
4. **两种做法的"感受" 1-2 句点明** — 差异、取舍, 不分子弹列表
5. **不引入云厂商产品 / 英文术语** (除概念名映射) — 这一段是纯生活场景
6. **≤ 12 行** — 入门段是低负载的, 但低负载拖长就是"低强度废话连篇"; 场景一两句、动作各一句、link back 一行, 够了

#### 7.C 现实连贯叙事段 (45%)

让读者知道"这真的在发生"。

**最关键原则**: 挑**一个**合适的场景, 不是列一堆不相干的案例。

❌ 坏做法 — 把 3 个真实例子拼起来:
- 淘宝双十一是水平扩展
- OpenAI 升级 GPU 是垂直扩展
- 你家数据库分库分表是被迫转水平

✓ 好做法 — 一个连贯故事串起所有要点:
- **场景设定** (1-2 句): 时间、地点、主人公 — "{日期} {地点}, {谁在做什么}"
- **3-5 个编号动作**: 每个演示一个核心概念/边界/应用。动作标题括号里**显式写对应概念** ("**动作 1 (水平扩展)**")
- **Link back 必须写**: 动作结束后用一个 "Link back" 小节, 把每动作 → 概念要点显式连回

**场景选择**:
- 读者能想象到 (公司运维办公室 / 工程师做决策 / 创业公司演进)
- 时间线有推进感 (T → T+1 → T+2)
- 一个场景能覆盖多面 (对比 + 边界 + 应用 + 取舍)

#### 7.D 首次产品自报家门 4 要素

产品/公司**整个故事链中第一次**出现时, 必须覆盖:

1. **出身**: 哪家公司做的, 什么时候/什么背景
2. **定位**: 普通人用它做什么
3. **使用感**: 用一次是什么体验 (动作 + 画面)
4. **独特性**: 跟同类比独特在哪

之后再提就简短带过。

**与保真清单冲突时的降级规则**: 源材料只报了产品名、没给出身信息 (常见: 课件里 Grafana/SPECint 只出现名字) 时, 四要素降级为**定性定位 + ⚡** — 说清"这是干什么的、在生态里什么位置"即可, **禁止**从先验补具体年份 / 公司史 / 用户量这类易伪精确项。保真优先于完整。

✓ 正例:
> **Cloudflare Workers** — Cloudflare 是全球最大 CDN 之一 (你访问的很多网站背后有它加速), 在全球 300 多个城市有服务器。Workers 让代码直接跑在**离用户最近的那台**服务器上: 北京用户请求, 北京就地处理, 不绕硅谷。延迟几毫秒, 适合登录校验、地域重定向这种轻量逻辑。

❌ 反例:
> Cloudflare Workers — Cloudflare 的边缘节点 FaaS

(读者不懂 Cloudflare 跟"边缘节点", 堆新名词)

#### 7.E 边界推理流程

边界情况 / 模糊归类时, **不直接给结论, 给推理流程**。

❌ 反例: "Google Colab 是 PaaS 不是 SaaS。"

✓ 正例:
> **Google Colab 是 PaaS 还是 SaaS?** 按套路推:
> - 问一: 我要写代码吗? 要 → 不是 SaaS
> - 问二: 我要管 OS 吗? 不要 → 不是 IaaS
> - 结论: Colab 是 **PaaS**
>
> 这个推理模板对每个服务都管用, 比记 "Colab = PaaS" 值钱多了。

#### 7.F 选型决策树

考试题型是"给场景选 A/B/C/D" (部署模型选型 / 服务模型选型 / 定价模型选型 / 计算模型选型) 时, **必须附分步决策树, 不只列特征表**。

```markdown
> **考试选型决策树**:
> 第一问: {最高优先级判断}? 是 → {结论 A}; 否 → 继续
> 第二问: {次优先判断}? 是 → {结论 B}; 否 → {默认结论 C}
```

加典型陷阱提醒 (用 ⚠️ 块, 让读者考前能一眼扫到所有陷阱):
> ⚠️ **陷阱**: {最常选错的选项} — {为什么看起来对但其实不对}

⚠️ 块不只用于选型: 课件本身的笔误 (照抄原文 + 算式说明)、老师特意警告的边界 (3 抽的第 3 样)、学生常犯的符号错误, 都用它。

为什么决策树? — 特征表让人"每个都觉得对", 决策树让人"按顺序排除到唯一答案"。考场决策树比表格快 10 倍。

#### 7.G 课件细节怎么处理 — 📎 小补充

材料里扣出来的细节 (具体产品名 / 偏门变体 / 学术 detail), 两种坏处理:
- ❌ **丢弃**: 读者外面遇到一脸懵
- ❌ **塞主线**: 主线密度爆炸, 读者迷失

正确做法: **小补充块**, 在主线相关位置插:

```markdown
> 📎 **<细节名>**: <一句话或一段讲它的作用 / 意义>
> (深入: <去哪里查>)
```

特点:
- 长度 1-3 行
- 内容: 只 name + 作用意义, 不展开
- 视觉: 📎 + blockquote 跟主线明显区分
- 留尾巴: "深入查 X"

例:
> 📎 **NTK-RoPE / Position Interpolation**: RoPE 的两个长度外推增强 trick。Yi-200K, LLaMA-Long 用过。考试不考, 知道存在即可。

> 📎 **AdamW 的 weight decay 修正**: Adam 把 L2 reg 折进梯度时不正确, AdamW 把 weight decay 从 grad 中分离直接应用到 weight。Loshchilov 2017。

#### 篇幅原则

不吝啬 (好例子是教学核心), 不啰嗦 (同一个意思不说两遍)。重要对比类概念 40-80 行, 小概念 15-30 行。

### 哲学设计

学生真正记住的不是抽象分类表, 是**老师讲的故事**。好例子把概念锚在生活化场景跟真实事件上, 大脑才能生根。

入门虚构段为什么禁云厂商/英文? — 入门段给"对这世界一无所知的人"看。一旦塞 AWS / Cloudflare / FaaS, 读者要先解码这些, 才能用它解码主概念 — 反向负担。

为什么不要拼盘? — 3 个不相干案例罗列, 每个都浅, 读完读者一个都没记住。一个连贯故事 (双11 阿里运维) 一气呵成, 时间线推进, 一个场景覆盖多面, 读完留印象。

### ❌ 现实段反模式

- 用大型真实事件 (ChaosDB 事故 / Netflix 迁移) 当**入门虚构例子** — 真实案例太重, 只能放现实段佐证, 不能当第一个教学例子
- 列 3-5 个不相干真实案例代替**一个连贯叙事** — 拼盘 ≠ 故事
- 入门虚构段出现云厂商产品或英文术语 — 污染了纯生活场景的"易懂"

## Step 8: Insight — 师门心法 🎓 (知其所以然)

### 执行细节

基础层 (Step 1-7) 讲完, 读者已经知道这个概念**是什么角色、为什么存在、怎么运作、如何应用**。Step 8 往上走一个维度: 从"这个机制是合理的"上升到**"为什么它会合理"**, 以及**"这个合理的机制是靠什么范式、什么思路被发明出来的"**。

这是课本上没有、原本只有当面问导师才拿得到的那层理解。写成 🎓 块, 放在 Step 7 之后、Step 9 收尾之前。

#### 触发条件

- **应写**: 核心机制 / 定律 / 推导 / 设计选择类概念 (中度以上), 每个概念**最多一个** 🎓
- **跳过**: 术语、分类、记号类概念 (轻度); L2/L3 发散概念
- 预算: 全文 🎓 ≤ 15% 行数

#### 三个透镜 (选一个, 最多两个)

1. **为什么它会合理 — 找到让机制"不得不这样"的那条约束或不变量**
   课本给的是机制, 这里给的是机制背后的**守恒律 / 边界条件 / 结构性约束**。读者看到"原来不是有人拍脑袋选了这个, 是在这个约束下只能这样"。
2. **同构指认 — 这是哪一类思维动作, 本课别处哪里再现**
   把机制还原成一种**思维动作** (切片到事件不重叠再取极限 / 把不确定性换成均值 / 用守恒代替分布 ...), 然后**指出这一招在本课别处的再现**。这一步把 12 个机制收成 3 个思路, 是 Arc 0 暗线在概念级的落地。
   注意这是**课内同构**, 不是思想史: 落点必须是"L4 的生灭过程用的是同一招", 不能是"这个想法起源于某年某人"。允许一句不带年份人名的传统归属 (如"这属于运筹学的传统做法"), 到此为止。
3. **从业者的判断 — 资深的人拿这个概念实际怎么用, 课本不会说的那个"但是"**
   老师讲 ρ < 1 稳定; 从业者知道 ρ 到 0.7 就该动手。这一层讲的是**判断阈值、使用姿势、什么时候这个模型该扔掉**。

#### 格式

```markdown
> 🎓 **师门心法 — {一句话标题, 写"所以然"不写"然"}**
>
> {第 1 段: 课本停在哪 — 一句话复述基础层的结论}
> {第 2 段: 上一层看是什么 — 约束 / 范式 / 判断, 用推理不用断言}
> {第 3 段 (可选): 这一招还在哪出现 — 指向本课其它讲/节}
```

150-400 字。语气是前辈私下聊天, 不是论文。不用手写"进阶 · 考试不考"副标题 — PDF 编译器给 🎓 块的顶部标签已经写了。

#### 保真约束 (🎓 天然是课件外, 所以约束比正课更严)

- 🎓 块本身就是"课件外"标记, 块内不必逐句 ⚡
- **只允许三种材料**: 可核验的数学/逻辑推理 (恒等式、结构论证)、本课内部的交叉引用 ("同一招在 L4 生灭过程再出现")、以"从业者通常 / 圈子里的共识"口吻给出的判断
- **禁止**: 具体年份、人名引语、外部论文的具体数字、"某公司当年怎样" — 这些一旦编错就是伪史。要讲范式来源, 讲**思路**, 不讲**史实**
- 🎓 里的结论**默认不进考试**

#### 与 Step 6 的界线 (实操判据, 按顺序问)

1. 课件**给了结论也给了原因** → 正课 Step 6, 不是 🎓
2. 课件**给了结论但没给原因**, 原因要你用推理重构 → **这是 🎓**
3. 课件**连结论都没给** → 不写。🎓 必须挂在课件的某个结论上, 否则就是超纲自由发挥

第 3 条是保真底线: 🎓 是"把课件的结论往上抬一层", 不是"讲课件没讲的新东西"。

### 哲学设计

基础层让学生会用; 进阶层让学生**会造** — 遇到课本没覆盖的新问题时, 知道这类机制是被什么思路发明出来的, 就能自己推出下一步。这是"和内行人无障碍交流"跟"背会了公式"之间的差距。

为什么必须放在基础层之后? — 所以然依赖于然。读者没牢牢握住"是什么、怎么运作", 上一层的推理没有落脚点, 只会被当成又一段更难的正课, 反而加重负载。所以 Step 8 是**奖励**, 不是**门槛**: 读法指南里 🪫 状态可以整段跳过, 🔋 状态读它把课学厚。

为什么单独成块而不融进 Step 6? — Step 6 回答的是"为什么选 A 不选 B", 还在机制层; Step 8 回答的是"为什么这类选择会存在、是被什么思路生成的", 在范式层。混在一起读者分不清哪句是必须掌握的取舍、哪句是可选的顿悟。

### ✓ 正例 (Little's Law, 透镜 1 + 2)

> 🎓 **师门心法 — Little's Law 不是模型, 是记账恒等式**
>
> 课本停在: E[n] = λE[r], 且"与分布、调度、队列数无关"。
> 往上一层: 它为什么能无关? 因为它根本不描述系统怎么运转, 只描述一件守恒的事 — 每个顾客在系统里待的每一秒, 都同时被"顾客数"和"停留时间"各数了一次。累计到达/离去曲线之间那块面积 J 就是这个"顾客·秒"总量; 除以 T 是平均人数, 除以 N 是平均停留, 两者相除自然等于 λ。它是一条会计规则, 不是一个物理假设 — 会计规则对什么分布都成立。
> 同一招在哪再出现: L5 运筹分析整套定律 (Utilization Law、Forced Flow Law) 都是这个思路 — **只用可观测量的守恒关系, 拒绝对分布下任何假设**。这就是为什么老师把 Markov 模型和运筹分析并排教: 一个是有假设的显微镜, 一个是无假设的卷尺。

### ❌ 反例

> 🎓 **师门心法 — Little's Law 的严格证明**
> 设 N(t) 为 ... (接着写了 20 行测度论)

(这是"深入研究", 不是"所以然"。🎓 不是往下钻更多细节, 是往上看一层。深入内容归 📏 的"深入研究: 查 X")

> 🎓 **师门心法**
> Little 在 1961 年发表这个定律时, 贝尔实验室的 ... 据他后来回忆说 ...

(伪史风险: 年份、机构、引语全是可能编错的具体史实。要讲范式讲思路, 不讲八卦)

> 🎓 **师门心法 — 为什么 E[n] = λE[r]**
> 因为到达率乘以停留时间就是系统里的人数。

(把基础层的定义换个标题重复一遍, 没有上一层)

## Step 9: Calibration — 收尾

### 执行细节

段末三件套 (📌 定义框 + 📏 深度档 + 🎯 考试提醒) + 一句过渡。

#### 9.A 精确定义框 📌 (强制)

每个知识点讲完后, 必须有一个定义框, 方便复习快速查阅:

```markdown
> 📌 **定义**: {一句话精确定义}
```

跟 Step 2 的开篇定义不同: Step 2 是叙事性的精确定义 (含输入输出 + 维度), Step 9 是 markdown blockquote 形式的**速查定义框**, 一句话, 不展开。📌 让它在 PDF 里上蓝色速查样式, 考前扫读时一眼可辨。

#### 9.B 深度三档 📏 (偏门概念必给)

学生最焦虑"这要懂到啥程度"。给三档:

```markdown
> 📏 **要懂多深?**
> - 考试够用: {一句话记 X 就行}
> - 工作够用: {懂 Y 三个维度}
> - 深入研究: {不必, 是黑盒 / 想深入查 Z}
```

什么时候必给:
- 讲到内部机制或架构图 (读者会想"这要背吗?")
- 介绍偏僻或学术概念 (读者会想"考试会考吗?")
- 展开更高级/更底层话题 (读者会想"这值得花时间吗?")
- 一个新名词频繁出现 (读者会想"这得多熟悉?")

常用句式:
- "考试够用: 记住 X 就行"
- "工作够用: 理解 Y 即可"
- "深入研究 (不必): 这属黑盒, 多数人用不上"
- "这个细节不用深究"
- "你不用记这个架构图的组件名, 理解意思就好"
- "想深入可以查 {具体资源}"

#### 9.C 考试提醒 🎯 (按需)

仅对 concepts.json 中带 `exam-freq` 标签的知识点添加:

```markdown
> 🎯 **考试提醒**: {这点考什么, 常见陷阱是什么}
```

#### 9.D 章节间过渡 (一句, 不机械)

同一 Arc 内的章节之间, 用一句自然过渡衔接:

- **抛新问题**: "X 的问题解决了, 但还有一个问题..."
- **顺势引申**: "既然知道了 X, 你自然会问: Y 呢?"
- **制造连接**: "X 依赖一个我们还没讲的东西 — Y"

❌ 不要用 "接下来我们讲 Y" 这种机械过渡。

过渡句之后就是下一节的 🧭 导读条 — 过渡负责"为什么要读下一节", 导读条负责"下一节要花多少力气"。两个重 § 相邻时, ☕ 放在过渡句之前 (见 Layer A 序列规则)。

### 哲学设计

深度档让读者**心里踏实** — 知道学到哪一档了, 不焦虑"是不是漏了什么"。这是好老师的标志: 时刻告诉学生"该投多少精力"。

定义框跟 Step 2 重复定义吗? — 不重复, 职责不同。Step 2 是叙事开头的"身份证发出", 帮读者建立锚点; Step 9 是段末的"速查框", 帮复习时快速翻回。两者都需要。

## 通用文风 (跨所有 Step)

以下规则不依附特定 step, 写每段都遵守。

### 术语管控 (最重要)

- 每个术语**第一次出现必须解释**
- 已经在前面 § / Arc 讲过的术语, 用 "前面讲过的 {术语}" 唤醒记忆, 不重复解释
- **没在前文出现过、也不在当前章节讲解范围内的术语, 禁止使用** — 用白话替代
- Arc 内部章节之间术语可直接复用 (读者刚读过)
- 跨 Arc 引用且间隔较远时, 简短提一句出处

### 不说废话

没有"让我们来看看"、"接下来我们将讨论"、"总结一下"、"非常"、"实际上"、"大家都知道"这类过渡/装饰废话。直接讲。

### 语气

像耐心的资深前辈在聊天, 不是教科书。用 "你" 称呼读者, 不要过度口语化。保持专业感。

### 命名禁地 — 技法名不当 heading

**这是最容易犯的错**。下面这些是**LLM 推理用的内部代号**, **不是给读者看的内容标签**:

- ❌ 对照式发散
- ❌ 痛点-方案-效果
- ❌ raise + reject
- ❌ 插件式补充
- ❌ 结构化叙事

产出 markdown 里**禁止**出现这些字串当 heading 或 blockquote 前缀。

写 heading 用**内容化命名** — 描述这段在讲什么内容, 不是讲什么技法:

```markdown
❌ ### §4.1 为什么 X — 对照式发散
✓ ### §4.1 三个矩阵不是一个 — 解耦的代价跟收益

❌ ## §6 训练显存 — 痛点-方案-效果
✓ ## §6 训练显存 — 7B 模型为什么单卡装不下

❌ > **对照式发散** — 主动 raise + reject (引用块当前缀)
✓ 直接进对照内容, 不打技法标签

❌ ## §7 ⚡ Agent 框架对比 — 痛点-方案-效果
✓ ## §7 ⚡ 三个 Agent 框架对比 — 痛点 / 方案 / 取舍各是啥
```

#### 哲学设计

写作技法的名字是 LLM 找写法时的查询 key, 不是读者认知所需。读者打开是要学 QKV, 不是学 "什么叫对照式发散"。把技法名当 heading = 让读者每段都做一次"这是啥技法"的认知开销, 然后才进入内容 — 元叙事污染。

### 长度控制

- 简单概念: 150-300 字
- 中等概念: 300-500 字
- 复杂概念 (e.g. MapReduce 执行流): 500-800 字
- 合并对比的章节 (e.g. 3 种虚拟化): 最多 1000 字
- 整 Arc 文件: 控制在合理范围, 宁可多分一个 Arc 也不要单文件过长

> 📎 **补充**: Arc 知识点确实多时 (e.g. Transformer Block 4 组件), **讲完讲透为主, 自然延展**, 不强行压字数上限。但不要为凑长度灌水 — 每段都要承担信息量。长度不是节奏: 一个 800 字的重 § 只要质地有变化 (Layer A) 就不闷, 一个 300 字全是定义堆砌的 § 照样闷。

## 发散概念变体

发散概念 (L1/L2/L3) 也走 10 步范式, 但深度按层递减。

### 标记

发散内容在标题上标 ⚡ 跟来源:

```markdown
## §N+1 ⚡ Redis 缓存策略 (发散自: §N Video SaaS 的性能优化)

> 📍 这个概念不在源材料范围内, 是从 §N 发散出来的。
> 发散理由: 答辩时被问"为什么用 Redis 而不是 Memcached"的概率很高。
```

### 每层的写作深度

| 层 | 标记 | 教学深度 | 篇幅 (相对核心) |
|----|------|---------|------|
| **核心** | 无标记 | 全 10 步走完 | 100% |
| **L1 发散** | ⚡ | 10 步走完但简洁; 必有"为什么会被追问"; Step 7 必有 🔍; Step 8 🎓 可选 | 60-80% |
| **L2 发散** | ⚡⚡ | Step 1, 2, 6 (1 个 alternative), 9 (含深度档) 必走; Step 5 简短; Step 7 可选; 无 🎓 | 30-50% |
| **L3 发散** | ⚡⚡⚡ | 一句话定义 + 一句"想深入看 X" | 2-3 行 |

### "为什么会被追问"

L1 跟 L2 发散概念必须说明为什么它被纳入:

```markdown
> **为什么会被追问**: 在 {用户场景} 中, 提到 {核心概念} 时,
> 对方大概率会问"为什么不用 {替代方案}?"或"这背后的原理是什么?"。
> 这个发散概念就是回答那个追问的。
```

### 发散概念的位置

紧跟对应的核心概念之后, **不攒到 Arc 末尾或单独开"发散"Arc**。

理由: 发散概念是核心概念的"追问延伸", 读完核心立刻看发散, 认知连贯; 隔太远读者已经忘了核心上下文。

### 发散必备件

- **精确定义框** (Step 9.A): 必有
- **🔍 现实例子** (Step 7): L1 需要 (简短版), L2 可选, L3 不要
- **🎯 考试提醒** (Step 9.C): 只有考试也可能考的发散概念才加
- **深度提示** (Step 9.B): L2/L3 **必有** ("了解到什么程度"对发散更重要)
