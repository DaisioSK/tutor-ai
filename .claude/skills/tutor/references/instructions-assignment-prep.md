# assignment ⟨N⟩ prep — 借一个高手的脑子读这道题

## 这是什么

为**还没动手**的作业写一份**可以跟着想**的东西：一个熟手拿到这份作业，从读题、看穿它在考什么、在脑子里搭出大图，到一步步落到每个单元——**他依次想了什么、为什么这么想、在哪卡过、怎么绕过去**。

读者的处境要认准：**原题他能读，但读完心里没有解读，满脑子问号。** 这份材料的大部分意义，就是让一个高手的理解**在他阅读的过程中出现在他脑子里**——他看到题面的一句话、骨架的一行代码、测试的一条断言时，旁边就站着那个高手说"我看到这句想到的是……"。

学生读完的收获顺序是：**先有认知框架 → 再有解法 → 最后才是代码**。

> 这份规范的来历，用户原话：
> - 2026-09-09 "从头读题、分析，从大的框架设计大图，到小的函数实现，通俗解释，脑中形成认知，抓住核心要点，一点点解题，像一个高手专家去思考——**能跟上的心路历程，而不是一堆排列出来的报告**。AI 时代**知识和实现本身是 cheap 的，重要的是思路和认知框架**。"
> - 2026-09-09 "把参考答案也一起写了……讲解你给的答案，哪个部分对应你的哪个思考，**让我一个个 paste 上去，带着意义的思考 paste 上去，不是整块 paste 上去**。"
> - 2026-09-12 "在思路之前，必须有对题目的通俗和完整的理解。把 user 当成小白，可能看了原题也没看懂……把你的心智模型和核心架构用最通俗的方式摆出来，和课程内容重合没有关系，引用就好。"
> - 2026-09-12 "PDF 不应该依赖除了课件之外的任何外部文件，比如介绍 data structure 的时候必须展示出来，而不是说你自己看原来的 dataset。让一个小白自然按顺序读懂。"
> - 2026-09-12 "看原文我也能读，但是我心中没有解读，满脑子问号。我需要的就是**换一个高手的脑子，让他的理解在我阅读的过程中出现在我的脑中**。"

### 不是什么（上一版就是死在这里）

| 不要 | 因为 |
|---|---|
| 每节按 ①契约 ②原理 ③底座 ④推导 ⑤伪码 ⑥陷阱 ⑦参考 填槽 | 编号槽保证要素齐全，也保证读起来是表单。**要素齐 ≠ 能跟上** |
| 开篇一张 8 列总表 | 那是审计产物。读者第一页要的是"这题在说什么"，不是一张对照矩阵 |
| 只写结论（"契约说了什么"） | 结论是 cheap 的。**贵的是"熟手为什么会想到它"** |
| 实现细节写得比思路长 | 实现是 AI 十秒能给的东西；思路不是。**给答案不等于让答案占篇幅** |
| 一个函数一节、九个函数九节 | 那是文件目录的顺序，不是认知的顺序 |
| "去看一眼 `test_x.py` 里的例子" | 把解读的活推回给读者；他打开文件看到的还是没有解读的原文 |

## 四条硬规矩

### 1. 篇幅按"贵重程度"分配

| 内容 | 定位 | 篇幅 |
|---|---|---|
| **认知**：这题在说什么 / 在考什么 / 大图 / 为什么这么做 / 卡点与想通的过程 | 贵 | **≥ 60%** |
| **解法**：算法骨架、消息怎么传、算子换成什么 | 中 | ~25% |
| **实现**：底座字段、索引、分块参考代码、陷阱 | 廉价，但要给全 | **≤ 30%** |

`verify_prep.py` 按这个比例卡。写超了不是"更详细"，是**把贵的挤掉了**。"廉价"不等于"不给"——见第 4 条。

### 2. 自足：读者手边只有这份 PDF 也能顺序读懂

PDF **只依赖课件**。作业目录里的任何东西——题面原图、数据表、数据结构的定义与实例、骨架里已经写好的代码、测试里的例子、期望值——**讲到哪一样，就把那一样的原文摆出来，紧跟一段解读**。不写"去看一眼 X"、"自己打印一下就知道"、"参见 Y 文件"。

基本写法单位是**「原文 → 我读到的」**：先抄原文（代码块 / 表格 / 裁图），再用第一人称写读到它时脑子里出现的东西。读者读完这一对，才算把高手的解读接收了一次。

课件内容**不重抄**，但要**引用**（课件页 + Arc §）；用到的认知就地用一两句日常语言说明白，因为读者可能没读过那一节。和课件重合不是问题，绕开重合才是问题。

### 3. 小白视角：不假设读者懂任何术语

每个术语第一次出现，就地用日常语言解释，配一个来自题面的具体例子（"一行 `1, 0, 0.6` 读作：如果 X_0 取 1，那么 X_4 取 0 的可能性是 60%"）。**任何形式化之前，先用日常语言说明白一次**；说不明白说明自己也没懂，回去想。

章序 = 认知递进顺序。一个小白从第一页顺着读到最后一页，中间不需要跳出去查任何东西（课件除外，而且课件是"想深入再去"，不是"不查就读不下去"）。

### 4. 参考实现：给，而且要分块给

**给完整的参考实现**，但方式受三条约束：

1. **先邀请再给答案**。每个单元先出 `▶ 先自己写` 交接点（含验法），参考实现放在它**之后**。读者可以选择跳过自己写，但顺序不能反。
2. **按思考的拍子切块，不按语法切块**。每一块对应"怎么想通"里的某一拍，**一块不超过约 12 行**。一个函数整段甩出来等于没分——那正是要避免的"整块 paste"。
3. **每块三件事必写**：对应哪一步想通的（回指前文的某个念头）；这几行承担什么语义（不是复述代码）；贴完之后能跑什么、看到什么（或"还不能跑，缺下一块"）。

格式：

```markdown
> ▶ **先自己写**: {单元}。验: {命令}。期望: {现象}。

#### 参考实现 · `{单元名}` 分 N 块

**第 1 块 —— {对应哪一拍}**

    {≤12 行代码}

{这几行承担什么语义} · {贴完之后的状态}
```

小标题必须写成 `#### 参考实现 · \`{单元名}\` 分 N 块`——门禁靠单元名抓块。

**作者责任**：参考实现**必须真的跑过评分依据**再写进材料，验的是"讲义里印的那一份"——把材料里的代码块按顺序抓出来、拼回骨架、跑测试，不是跑作者本地那份（两者在誊抄时很容易分叉，分叉的代价由读者承担）。

拼出来的那份**要交付**：`prep/reference/{骨架文件名}_reference.py`，每个空槽上方标「第几章 · 第几块」，旁边放 `TEST-LOG.txt`（日期 / commit / 依赖版本 / 测试原始输出）。读者自己写完要有一份整体能跑的东西逐函数对照，而不是在八章里翻代码块自己拼。文件头复述荣誉守则并写明"对照用，不是提交件"。

**学术诚信**：材料的读题章必须复述作业的荣誉守则原文，并说明这份材料的定位——分块理解后自己敲上去、可查阅的参考，不是可整体提交的成品。这是给读者的使用说明，不是免责声明。

## 三个词（全文只用这三个）

| 词 | 意思 | 例 |
|---|---|---|
| **单元** | 可独立完成、可独立验证的最小任务块 | stub 函数 / notebook cell 组 / 一道小题 |
| **评分依据** | 材料里能判断"对了没"的东西 | 测试 assert / rubric / 参考数值 / 格式硬指标 |
| **底座** | 作业已经给你、必须在其上工作的东西 | 数据结构与索引约定 / 骨架 / 工具函数 / 数据 |

## 输出形态

```
output/{课程名}/assignment{N}/prep/
├── 1-读题.md          先把题目说成人话 → 我拿到它先做什么 → 只在评分依据里的要求 → 交付与规则
├── 2-大图.md          一个念头 + 一张图; 底座在这个念头里是什么形状 (实例展示, 不是字段清单)
├── 3..K-*.md          按认知台阶推进 (不是按函数清单)
├── {K+1}-回头看.md     交付前的自验与对账; 你脑子里现在多了什么
├── 附录-对照表.md      单元 → 课件页 / Arc § / 评分依据 / 陷阱 (审计用, 放最后; 末节指向 reference/)
├── figures/           从题面裁下来的原图 (图注标"指导书 p?")
├── reference/         {骨架}_reference.py (各章分块拼回骨架的整份, 已跑过评分依据) + TEST-LOG.txt
└── full-story.pdf
```

`figures/` 和 `reference/` 是子目录，编译器和门禁只扫 `prep/*.md`；图靠正文里的 `![...](figures/x.png)` 进 PDF，reference 不进 PDF。

**没有 index.md**。目录由编译器自动生成；正文第一页必须是"读题"，不是总表。审计信息（谁对谁、哪页、哪条测试）全部沉到附录——它要存在（可追溯是铁律），但不占开头。

## Phase 0：认材料

**目录**：先找 `courses/{课程名}/assignments/Assignment{N}/`，再找 `courses/{课程名}/assignment{N}/`（大小写不敏感）。都没有 → 报错并列出可用作业。

**读取顺序**（全部读完再动笔）：

1. 题面 / 指导书 —— 交付物、评分、截止、迟交、荣誉守则**原文抄下**；有图就裁到 `prep/figures/`
2. **评分依据** —— 测试逐条 assert（含消息字符串）；rubric 逐条；样例输出与参考数值
3. 底座 —— 骨架、数据结构说明、工具函数、数据文件（形状与规模）。**顺手跑一遍**：实例化一个对象打印出来、加载数据看第一张表、把骨架建出的图列出来——这些输出正文要用
4. 关联课件 —— 题面标的 References；对应的 `output/{课程}/teach/` Arc（没跑 story 的课程退化成只写课件页并 WARN）

**判定变体**（决定收口形式与哪一段变重）：

| 变体 | 判据 | 单元 | 收口 | 变重的地方 |
|---|---|---|---|---|
| A 填空式代码 | 有自动测试 | stub 函数 | 自验清单 + 数值对账 | 读题（测试里藏要求）、底座 |
| B 从零搭 notebook | 无测试，有 rubric | 逻辑 cell 组 | rubric 自评 + 输出对照 | 大图、骨架 |
| C 报告 / 推导 | 不交代码 | 小题 / 报告一节 | 报告骨架 | 大图、每小题的"想通" |
| D 有答辩 | 含 presentation / viva | 模块 | 自验 + 接回顾模式答辩 | 判断与取舍 |

发散校准默认 layers 0-1 / breadth ≤ 2 / 严格，不问用户。

## Phase 1：先想清楚，再排章（动笔前必做）

按顺序回答四个问题，答不出来就别写：

1. **这题在考什么？** 一句话。不是"实现 BP"，而是"考你懂不懂**为什么可以把求和推进去**"。
2. **一个念头是什么？** 整份作业能不能压成一句话的认知？（例："联合分布是因子的乘积；推断就是把不关心的变量消掉；消的顺序决定了快慢"）
3. **认知台阶怎么排？** 从这个念头到全部单元，中间要迈几步？**每一步是一个新念头，不是一个新函数**。一步可能带 1-3 个单元，也可能一个单元占两步。
4. **每一步的卡点是什么？** 一个熟手在这一步真正要想明白的那件事（不是"要调用哪个函数"）。

产出一张**规划表（内部用，不进产物）**：

```
| 台阶 | 这一步的新念头 | 卡点 | 带哪些单元 | 课件页 / Arc § | 评分依据 |
```

台阶顺序 = 认知递进顺序。它常常**不等于**依赖顺序，也不等于文件里函数的顺序。每个单元必须落在某个台阶上，不许留白。

## Phase 2：怎么写

### 每一章各自的形状

**读题章**，四段，顺序不能反：

1. **先把题目说成人话**（第一个正文小节，必须在"我拿到它先做什么"之前）。假设读者看过原题但没看懂，每件配题面里的具体例子：
   - 题目给了什么 —— 图 / 数据 / 骨架里的对象各是什么，怎么读一行、一格。嵌题面原图；图里字太小的表**抄成 markdown 表**
   - 它能回答什么问题 —— 每一类问题各在问什么、答案长什么样，用题面给的期望值举例；不同类问题容易混的地方点出来
   - 要写的到底是个什么东西 —— 不按函数清单，按**层**画一张最简架构图（底座 → 零件 → 解法），说明上层由下层搭成
   - 心智模型一句话版 —— 作者读完题在脑子里定型的那句话，后面所有章都是它的展开
   - 题面逐节对照表 —— 原文每节在说什么 → 人话（≤ 3 列）
2. **我拿到它先做什么** —— 熟手的动作顺序和理由；扫到的单元签名**抄出来**并贴上自己的标签
3. **只在评分依据里的要求** —— 每条引测试原话，说它会怎么改变写法
4. **交付与规则** —— 截止、占分、打包、荣誉守则原文、这份材料的用法

**大图章**：一个具体问题开场 → 一个念头 → 弯路与洞见 → 单元排成的图 → **底座**。底座那一节按第 2 条硬规矩写：一个具体对象的**完整实例**（构造代码 + 摊开的行表）、工具函数的**调用示例与返回值**、数据在底座上的**实际形态**（比如骨架建出来的图，逐节点逐边列出）。字段清单不算展示。

**台阶章**（3..K）：一章 = 一个认知台阶，按思考发生的顺序走，典型三拍，**不写编号、不写小标题模板**：

- **卡在哪** —— 这一步真正难的是什么。用一个具体问题开场，不用定义开场
- **怎么想通** —— 直觉 → 为什么不行 → 退一步看本质 → 得到做法。全篇最贵的部分，写透
- **落到手上** —— 在这个底座上是什么动作（骨架已给的代码**抄出来解读**）；你去写；怎么验；然后分块参考实现。**这一拍要短**

三拍之间用正常的行文过渡（"于是问题变成……"），**不用编号标记**。

**回头看章**：绿了不等于对了 → 数值对账（期望值抄在正文里）→ 报告怎么写 → 打包 → 你顺带复习了什么 → 你脑子里现在有什么。

**附录**：单元 → 课件页 / Arc § / 评分依据 / 陷阱 的窄表；只在评分依据里的要求汇总；交付清单；末节指向 `reference/`。

### 全局写法

- **第一人称在场**。"我先看测试，因为题面会骗人，测试不会"——写熟手当时的动作和理由，不是写结论清单。
- **「原文 → 我读到的」成对出现**。每引一段作业原文（题面句子、骨架代码、测试断言、数据表），紧跟一句"我读到这里想到的是……"。这是让高手的解读进入读者脑子的最小单位。
- **允许写弯路**。"第一反应是把所有因子乘起来——216 行还行，可这是小图；大图会炸。所以退一步问：我真的需要那张全表吗？" 弯路是认知的一部分，删掉它读者就只能背结论。
- **每章一个念头**。章首一句"这一章只装一个念头：……"，章末复述它 + 一句"你现在能做但之前做不了的事"。

### 块类型（presentation.md 的子集，够用就好）

| 块 | 用途 |
|---|---|
| `> 🧭 **本章**` | 章首一行：负载 · 分钟 · 一个念头 · 课件页/Arc |
| `> 💡` | 通俗解释、打比方（认知，鼓励多用） |
| `> ⚠️` | 会让你写错的地方，每条标来源（评分依据 / 题面 / 骨架 / 课件 p?） |
| `> 🎯` | 评分依据里藏着、题面没写的硬要求 |
| `> ▶ **先自己写**` | 交接点：去写什么 + 用什么命令验 + 期望看到什么 |
| `> 🎓` | 从业者的判断（每章最多一个） |

**不用** 🔍 两段式、📌 定义卡、📏 三档、📎——它们让文档变回卡片集。定义就写在行文里。

### 代码与表格（上一版排版崩掉的直接原因）

- **表格最多 4 列**。A5 页宽只装得下 4 列；5 列以上拆成两张或改写成列表。审计用的宽表放附录，并拆成窄表。
- 单元格里不放超过 24 字符的连续标识符；放不下就写在正文里。带竖线的公式写 `\mid`，不写 `|`。
- 代码块每行 ≤ 70 个等宽单位（CJK 算 1.66）；抄骨架原文时按这个宽度折行。
- 伪代码 ≤ 15 行，只写思路骨架；参考实现按第 4 条硬规矩分块给，**不另补**"另一个底座上的通用参考"——重复且占篇幅。

## Phase 3：门禁

```bash
<python> ${CLAUDE_SKILL_DIR}/scripts/verify_teach.py {course_out} {prep_md} --layout-only
<python> ${CLAUDE_SKILL_DIR}/scripts/verify_prep.py {assignment_dir} {prep_dir}
```

| 检查 | 判据 | FAIL 的含义 |
|---|---|---|
| 单元全覆盖 | 每个待完成单元在附录对照表和某一章正文里都出现 | 有单元没人教 |
| 认知配比 | 代码块 + 表格 ≤ 30% | 写成了实现手册 |
| 一个念头 | 每章章首有"这一章只装一个念头" | 章没有认知锚点 |
| 交接点 | 每个单元都有 `▶` 且含具体验法 | 没告诉学生怎么验 |
| 契约对齐 | 评分依据里每条可机读要求在正文被引用 | 隐藏要求漏了 |
| 参考实现齐 | 每个单元都有参考实现，切成 ≤14 行、带"第 N 块"标记与前后讲解的块 | 少了答案，或整段甩出 |
| 对账表 | 材料里的参考数值出现在附录或收口章 | 做完没得对 |
| 表格宽度 | 任何表 ≤ 4 列 | PDF 里会被压成碎条 |
| 无填空槽 | 正文不出现 `① 契约` 这类编号小标题 | 又写回报告了 |
| 读题先拆题 | 读题章第一个正文小节是拆题，且标了课件/Arc 出处；有图或架构图（否则 WARN） | 读者看了原题也没看懂，材料却直接开讲思路 |
| 自足 | 正文不出现"去看一眼 / 参见 / 自己看 + 作业文件名"这类把读者推回文件的句子 | PDF 依赖了课件以外的外部文件 |

任一 FAIL 不得编 PDF。变体 C 无代码时，「参考实现齐」改为"每小题给解题骨架 + 关键步骤的写法"。
`reference/` 是否交付、TEST-LOG 是否存在，门禁不查——作者在 Phase 4 前自己核对。

## Phase 4：编 PDF

```bash
<python> ${CLAUDE_SKILL_DIR}/scripts/compile_story_pdf.py output/{课程名}/assignment{N}/prep --prep
```

`--prep` 换掉讲义封面文案（无"故事链"、无 KP 提示）。产出 `prep/full-story.pdf`。
**编完必须打开 PDF 抽查**：有没有整页只剩一个标题、有没有表格被压成一字一行、裁进来的题面图在 A5 上字是否还能看（看不清的表要抄成 markdown 表）。源码门禁看不见这三件事。

## 交互模式（`--walk`）

批量产物是底稿。交互时按章逐个放行：讲到 `▶` 停 → 学生贴回自己的产物 → 按评分依据冷血审（`check` 的四维度）→ 过了再往下。一次一个单元，不自动继续。

## 与回顾模式的关系

[instructions-assignment.md](instructions-assignment.md) 是**回顾模式**（作业已做完，顺着代码讲决策 + 答辩），本文件是**预备模式**。两者互补，不互相覆盖；`assignment{N}/prep/` 与 `assignment{N}/teach/` 分开存放。
