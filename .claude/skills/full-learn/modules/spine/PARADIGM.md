# spine — 范式

## 一句话

依赖只给出"不能先讲什么"，脊柱要在所有合法顺序里挑出那一条：每一步都在回答上一步留下的疑问，而且此刻一看就懂。

## 理论

**1. 偏序与全序。** 科技树的 requires 边是偏序（partial order）：它排除非法顺序，但合法的拓扑序（topological order）有很多。旧做法把"依赖序"直接当讲述序，得到的是合法却无动机的书——每节都像"接下来介绍 X"。脊柱的工作是在依赖约束之内，按"读者心里先问什么"选出全序（total order）。

**1a. 默认全序 = 讲者脉络。** 在所有合法顺序里，老师的讲序是唯一被一个真人在真课堂上试过的那条：它的过渡页（"Limitation""Fallacy""But:"）、悬案与反例、贯穿多页的例子，正是一条现成的疑问链，而且读者的课件、考卷都用它的语言。所以从 T1b 出发，不从零排。老师的讲序水平参差，T1b 已逐步评价；脊柱只在四类地方偏离，并在 spine.md 的「偏离讲者脉络」表里逐条写明：
- **目的后置**（先定义后说用处、先规定做法后给理由）→ 把目的/理由提前；
- **动机缺失**（一步没有过渡理由）→ 补入口问题，标为补充；
- **前置倒挂**（先用后讲，例如先用某概念、几讲后才定义）→ 调序，或改成在后文回指；
- **理由不对或偏弱**（老师给的过渡理由其实已被前文解决）→ 换成真正的理由，注明老师原说法。
其余照走。与讲者脉络完全重合不是问题；偏离而没有理由才是问题。

**2. 疑问链（question chain）。** 一本顺的书，下一节的入口问题就是上一节结尾读者自己冒出来的问题。读者引入新概念时第一个念头几乎总是"为什么不用原来那个"——这个对比当下不答，后面的内容全浮着。所以入口问题不是作者想讲什么，而是读者此刻缺什么；每一步的卡点是熟手真正要想明白的那件事，不是"调用哪个函数"。每步是一个新念头（idea），不是一个新函数或新页。

**3. 可懂性的不对称代价。** 前面懂了，后面再懂的边际价值有限；前面没懂，读者会直接放弃。因此"此刻能懂"压倒一切：每一步的全部前置必须已经解锁。辅导场景里由导师动态维护的"已讲 / 未讲 / 下一步讲什么"，在书里被静态化为脊柱本身——书的阅读顺序就是一条依赖合法的学习路径，不需要另给 A/B 路线，也不需要运行时提醒"先去学某某"。

**4. 能力为章。** 读者买的是能力（ability），不是页码。一章 = 解锁一项能力的一串节点，可以跨 Lecture、跨文件；章的"解锁"写成"懂了什么"（能推出为什么求和可以推进去），而不是"做了什么"（实现了某算法）。章入口问题连起来，就是全课的 3-5 个核心大问题（为什么 → 是什么 → 怎么做 → 怎么管 → 代价多少这一类），它们自上而下展开：先大框架、大图，再组件，最后实例与细节。

**5. 脊柱是最便宜的修改点。** 脊柱只有几页，路径、完整性、分量在这里改几乎零成本；写完再砍代价是整章。所以"每个节点都有落点""重的节点占得到位置""发散多宽"都在这里定死，并在 ⏸1 一次性交用户审。

## 方法

**0. 读入。** 输入是 T2 `tree.json`（节点 + requires 边 + weight + apex + generators）。它不存在就停下，先跑 tree；不在缺上游产物时凭材料自己排。动笔前先能答出四个问题，答不出就回 tree 补：终极理解是哪一个念头（apex）；每章让读者懂了什么；台阶怎么排、每一步的新念头是什么；每一步的卡点是什么。

**1. `case` — 选运行案例。** 先看 T1b 里老师的开场问题与贯穿多讲的例子（如"从局部观测得到全局认识"配一张照片）：能撑起全书就直接用，书和课堂说同一种话。撑不起再从 apex 出发找一个具体场景，它在第一章就能被朴素地提出，并且每解锁一项能力，读者对它能多说一点。判断：逐章写一句"这一章之后，关于案例我们能多说什么"，写不出的章超过三分之一就换案例。案例写进 spine.md 的「运行案例」段。

**2. `order` — 选拓扑序。** 维护两个集合：已解锁节点、悬而未决的问题。
- 先把 T1b 的步按讲序铺成初始序列，再用 requires 检查：违反依赖的地方就是"前置倒挂"，按理论 1a 处理。下面的贪心选择用于老师没覆盖的节点（external 前置、追问型发散）和需要偏离的地方。
- 候选 = requires 已全部解锁的节点。在候选里选最直接回答"最近留下的那个问题"的节点；没有候选回答它，说明这里要么是章的接缝（新能力以新问题开场），要么树上缺一条"为什么"——回 tree 补，而不是硬接。
- 从生成元与大框架起步：先回答"这个领域为什么存在、整体长什么样"，再下到组件与实例。
- 发散分两种。**前置型**（external：材料默认你会、但没讲的东西）推荐扎堆成**前置包**：只依赖其他前置、不依赖材料节点的前置，提到第一个需要它们的卷或章开头，成一个包（可以独立成「补给站」章，按主题分两三半，如概率规则 / 微积分）；依赖材料节点的前置提不上去，就在第一个使用者所在章的开头扎小堆。包内按前置自己的依赖排序，成对的（tree 里标 `pair`）同节。前置包与它的使用者同卷且在前；混在材料节里的前置拆出来进包。为什么扎堆而不是逐个插在首用处之前：逐个插会把成对的概念拆到两章（导数在第 4 章、积分在第 5 章），每个前置节还要被迫接上前后的排队问题，前置就开始引用后文；扎成包，前置自成一条短而直的路，读者一口气吃完、回主线。**追问型**（延伸：为什么选它、和替代方案比如何，例如讲完 Docker 紧跟"为什么不是 Podman"）紧跟它的核心节点之后，不攒到章末、不单开"发散"章——隔远了读者已丢了上下文。前置节的四格：入口问题只用日常语言或纯数学语言（不提运行案例、不用材料符号）；凭什么现在能懂只列别的前置；留下的新问题写「—（回到主线）」，不必接到下一节。
- 节与节点不必一一对应：强耦合或互为对比的节点（A vs B、同一机制的两面）合进一节对比讲；一个很重的节点可以占两节。每个节点都必须落在某一节——落不下的节点就是还没想好怎么讲的内容，它在写作时一定会变成空洞。
- 判断做对：把「入口问题」列从头读到尾，应当像一串自然连续的追问；每一处与讲者脉络不同的顺序，都能在「偏离讲者脉络」表里找到理由。入口问题优先用老师过渡页的原话改写。

**3. `chapter` — 切章。** 沿疑问链找"读者手上多了一项完整能力"的位置下刀；章标题点出能力，标题行的 `— 解锁:` 后写这项能力（懂了什么），下一行 `章入口问题:` 写读者此刻的真实困惑（T3 的章头格式）。一章内的节点围绕这一项能力，不围绕课件主题。章过长就拆：默认一章不超过约 8 节、约 60 分钟阅读，宁多一章也不要一章过厚。章数较多、章入口问题明显聚成几个大问题时，在章之上分卷，一卷 = 解锁同一大能力的一组章，卷的问题就是那 3-5 个核心大问题。切完章就定骨架（chapter 理论 5 的规则，写作前定死，节是往里填的）：每章 3–6 个大概念、各 2–4 个子题（标出由哪一节填）、概念间的关系词，以及连词成句的一段话，写在 spine.md 该章表格之前；卷内几章合成 3–5 块、卷与卷的关系同样各一段话。同时定**目标树**（top-down）：终极目标拆成几片子目标（拼图），每卷补哪一片、每块补哪一角、缺了它终极目标哪里断——这是"为什么要学这些、为什么进了课件"的唯一来源，卷串讲与总纲都从它取。每章同时搭一架**好奇心阶梯**：0 技术名词（"M/M/m 怎么推"）→ 1 本领域的反常（"利用率才 60%，为什么还有人等好几秒"）→ 2 跨领域的同一现象（"银行为什么宁愿一条蛇形长队"）→ 3 普遍规律之问（"共享池为什么几乎总是赢"），外加一级读者自己的世界（取自 reader.md 的读者背景）。求知欲只在预期被打破、且问题大到值得在乎时接管学习；0 级只有考试在乎。取本章机制还答得了的最高一级作本章的大问题——爬不上去的章（工具、命令类）停在 1 级，不硬拔成"世界规律"（读者被标题党骗一次就不再信）；2、3 级的跨领域说法属材料外，按外部补充标记，且必须由本章机制真能推出。骨架里挂不上的节点是信号：要么它属于别的章，要么它只配背景档。骨架同发散参数一样在 ⏸1 交审——这是全书最便宜的改结构的时刻。

**4. `cells` — 填四格。** 每节一行，四格各管一件事：
- **入口问题**：读者能具体感到的问题，带条件（"只有一台服务器、到达率和服务率已知，平均要等多久？"），不写"当你需要分析 X 时"这种模糊状态。新节点的入口常是"为什么旧方案不够"。
- **凭什么现在能懂**：只列排在前面的节点 id，至少覆盖本节节点的直接 requires；它让"前置已解锁"在表里可见、可被脚本核对。
- **解锁了什么**：一行可检验的动作——会算 / 能判断 / 能推出 / 能说出为什么——优先选推理类动词，体现"懂了什么"；不用"理解 / 熟悉 / 掌握"这类验不了的词，约 40 字内。它是 section 节末回扣的目标，也是分配篇幅的依据。
- **留下的新问题**：刚学到的东西哪里不够、让读者想追问什么；它应当就是下一节的入口问题（或下一章的章入口）。
- 主表在四格之前还有 § 与节点 id 两列；同章另附一张按 § 对齐的机读表：分量（tree weight）、负载（轻/中/重）、sources、预选原图（从 `_figures.json` 挑，取舍规则归 devices）。

这张表写进 `spine.md`（T3）：它是产物，compose 写任何一章前，该章包含哪些节点、按什么顺序都由它给定；但它是规划，不进书的正文。

分量在这里校正：分量最高的节点应占独立节、处在章的中心；分量低的节点合并或依附。分量问题在规划阶段改，不等写完再砍。

**5. ⏸1 审阅。** 产出 spine.md 后停下，一次性给用户看：科技树图、节点数 / 章数 / 卷数、脊柱章节表、发散参数（写在 spine.md 头部，发散节点在表中可见）。所有确认合并在这一次——不单独问发散参数，不问"从哪开始"。必报一个数：全书预估阅读时长，对照 reader.md 里读者可用的时间（如考试日期）；超出时可调的是粒度（合并轻节、拆超图节）与发散刻度，不是范围。用户可以说"再收一点 / 再放一点 / OK"：收放发散回 tree 增删 external 节点后重排；路径意见回写到本范式再重出。得到 OK 前不进 compose。⏸2 样章审阅同理，反馈回写对应模块范式后再批量写。用户事先授权自主运行（"有决策按你的推荐来"）时，两个 ⏸ 照常发生、只是由作者代为拍板：⏸2 由冷读者 agent 顺读样章代行，它报的卡住/无聊/断裂先回写范式再批量写；每个代拍的决定连同备选与理由记入工作区 `work/decisions.md`，用户回来时一张表看完。

## 判断准则

1. **合法性 > 流畅性。** 叙事想让 B 先于 A 而依赖不允许时，不违反依赖：要么依赖边本身错了（回 tree 改），要么换一个能由已解锁知识回答的入口问题。
2. **此刻能懂 > 章主题完整。** 某节点放在本章会依赖尚未解锁的东西，就挪到后面的章，不在本章留一个读不懂的节。
3. **能力 > 来源。** 一章跨三个 Lecture 是常态；按 Lecture 或文件切章需要额外理由。
4. **两条合法路径难分高下时**，选过渡问题更具体、更早让运行案例出场的那条。
5. **落点 ≠ 独立节。** 每个节点都要有落点，但低分量节点可以被合并进相关节；覆盖是对节点集合的承诺，不是平均分配篇幅。
6. **不 overfit。** 入口问题用读者此刻的语言写，不预支后面才出现的术语；方法对任何领域都成立，具体课程只是例子。

## 反例

- **照抄课件不加判断**：章 = Lecture、节 = 幻灯片组、"一个函数一节"，连老师跳步、先用后讲的地方也照搬——讲者脉络是默认，不是免检。
- **推翻讲者脉络另起炉灶**：只按依赖重排、另选例子，丢掉老师的悬案—反例—过渡（如 L2 的"代数证一条 → 能否只看图 → 反例 → 三种结构 → 回收悬案"），留下的是正确却无味的结论链。
- **合法但无动机**：每节以"接下来介绍 X"开场——只做了拓扑排序，没有疑问链。
- **模糊入口**："当你需要分析队列时"——读者感觉不到这个问题，入口等于没有。
- **"做了什么"式解锁**："实现 BP""熟悉 M/M/1"——验不了，也不是认知。
- **发散攒尾**：external 前置集中放附录或全书末的"补充知识"章——读到需要它时已经卡住。前置包放在使用者所在卷/章的开头，不算攒尾。
- **前置逐个插**：每个前置插在首个使用者紧前，成对概念被拆开，前置节被迫用后文的场景与符号开场。
- **留白**：有节点没分到节，写作时才发现不知道放哪——完整性本该在脊柱定死。
- **散装确认**：先问发散参数、再问 Arc 计划、再问从哪开始——三次打断，且回到了交互式辅导。
