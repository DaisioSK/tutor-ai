# compose/book — 范式

## 一句话

书是一个整体：书首让读者用二十分钟握住整本书要解锁的那个模型和通往它的路，正文沿脊柱一路点亮，书尾把点亮的东西收回同一个模型；中间靠一个运行案例和一套守信的交叉引用，把各章缝成一本书。

## 理论

**1. 一本书，不是一堆章 (one book, not a pile of chapters)。** 按讲成册时，读者拿到的是并列的碎片，章与章的联系要自己脑补。这里的组织单位是整个范围：一本书（大到一个 PDF 无法顺手翻读时分卷，每卷仍有自己的书首书尾）；章按科技树与脊柱排，不按 Lecture；每章一个文件，章内的节按"上一步留下的疑问"环环相扣，而不是按知识点罗列，更不拆成知识点碎文件。全书层要管的，是任何单独一章都管不了的事：读者入场时手里该有什么、全书朝哪里走、贯穿的东西怎样不断线、离场时脑子里多了什么。

**2. 大图优先，而大图是理解不是目录 (big picture first)。** 先建全局视图，再逐层深入。书首就是"二十分钟版的整本书"：终极理解一句话（后面每一章都是它的展开）、少数生成元（反复出现的根思想——看似不同的技术是同一思想的不同实例）、一副全书骨架（几卷、每卷几块、块与块之间什么关系——由各章骨架逐层拼上来，见 chapter 理论 5）。节点级的科技树是作者的工作底稿，几百个节点铺开正是"细节很多没有层次"，进书只作附图，不当大图。这一块写不好，书首就退化成华丽的目录：有地图，没有入场价值。所以书首的标准不是"列全了"，而是读完能说出：这个范围回答哪几类问题、答案长什么样、哪几个思想会一再回来、哪里最容易混。

**3. 第一页给读者，审计沉附录 (reader-facing vs audit-facing)。** 可追溯是铁律，但追溯信息是审计者要的，不是第一次翻开的人要的。开篇一张多列对照矩阵，就是把审计产物摆在了读者面前。于是全书有一条分界：书首与正文只放推进理解或帮助定位的东西；对照表、反查表、节点索引、覆盖说明都沉到书尾附录——存在、可查、拆成窄表，但不占开头。

**4. 读法是预期管理，只说一次 (the reading contract)。** 读者带着不同电量来：满电、疲惫通勤、复习/考前。块类型只有配上"哪种读法读哪些块"才完成预期管理；但这份契约属于整本书，在书首说清一次，不在每章文件头重复。便宜的那条路要一眼可见并标出耗时——"全书若干小时"会劝退时间紧的读者，"快速路径若干分钟"能把人留下。心法类内容是奖励不是门槛：低电量整段跳过，高电量读它把课学厚。

**5. 一条线穿全书 (the running case)。** 一个具体的运行案例在书首登场、只抛困惑；之后每章用本章解锁的能力重看它，它每次多暴露一层（新问题、新数字、新解释）；书尾给出完整解答。数字尽量沿用同一组，读者记住一组数，就能沿全书自测。这条线是全书层的资产，章层只负责在本章用好它。

**6. 指针是承诺 (navigation as a promise)。** 书被顺读，也被翻查。每个"见 §X.Y"都是对读者的承诺：指错比不指更糟。回指可以作提醒，但不能替代本节推理需要的内容——"定量对比见前文"等于这一节什么都没讲。前指只能指向脊柱计划里确定会讲的地方。"首次出现"也是全书概念：产品、公司第一次出场要自报家门，之后简短带过，这需要全书层按顺读顺序维护一张首次出现表。

## 方法

### 1. front — 书首 `00-front.md`

动笔前读 tree.json 的 apex / generators / external 节点与 spine.md 的章表。要素是"定位 / 前置 / 大图 / 生成元"加终极理解与读法，形式可变，要素不缺。

- **封面信息。** 书名、范围声明、一句读法提示，交 render 排进封面；不用"故事链"之类的副标题。
- **第一页：这在说什么。** 定位语（这是什么范围；像读一本书一样从零学完它）；它在领域中的位置（入门还是进阶）、与同主题其它课程或书相比的独特视角、谁会读它以及为什么。时代背景（学界、工业界在这个方向走到哪了）是材料外内容，用外部补充块标记，不编造年份和数字。这里的类比与钩子可以宏观（学科本身、行业历史）；不需要入门/现实两段式例子框——还没有具体概念可举。
- **终极理解。** apex.statement 放进终极理解专属块（不贴"考前必看"一类标签），配一段人话：学完能回答哪几类问题、答案长什么样、最易混的点。对直接支撑它的节点和每个生成元，只给直觉 + 一句定义 + 与其它概念的关系，不推导（推导是正文的事）。可附一段"熟手面对这堆材料会先抓什么"：动作顺序与理由。
- **前置 (prerequisites)。** 从 kind=external 的节点生成，不凭空列。分"必备"（缺了读不下去，常见 5–8 项）与"加分"（有了更轻松，常见 3–5 项）；树上没那么多就少列，不凑数。每项一句"为什么需要"（取自依赖它的节点）+ 一句"哪里补"；去处不在材料内时按外部补充标记，不编造书名章节。末尾一份 30 秒自检清单：答不出 3 个以上，先补什么。
- **大图 = 全书骨架 (book skeleton)。** 与章骨架同一条规则，逐层往上拼：全书 → 3–6 卷（大概念）→ 每卷 3–5 块（几章合成一块，块名是读者的词）→ 章。书首给一段连词成句的话把各卷连起来（这段话就是终极理解的展开），配一张骨架图（mermaid `%% skeleton`：每卷一个 subgraph，子题是块，标签 `块名 · 第a–b章`，卷与卷之间的边写关系词 + 短语）。各卷导览里每卷同样一段话 + 一张卷骨架图（块为 subgraph，章为子题 `章短名 · 第N章`）。卷、块的划分取自 spine 与各章骨架，不另起炉灶；每章骨架段的第一句写明"本章是第几卷哪一块"，读者在任何一章都知道自己在全书哪一格。节点级科技树（tree.md）是作者的工作底稿，不进书：几百个节点画在一页上只是"细节铺开"的极端形式，读者什么也看不清；它承担的"一切内容各在哪"由总纲卷的层级目录接手（方法 6）。图下用文字讲编排逻辑：每卷每块解锁什么、为什么先解锁它；标出主线与可跳过的章或外延节点。
- **生成元即暗线 (recurring threads)。** 列出 generators，在书里叫"反复出现的几个根思想"这类读者的话，每个标出它在哪几章展开："X 会在第 N、M、K 章反复出现"。
- **运行案例登场。** 一段话抛出案例的困惑，不给答案。
- **目录、读法与规模。** 目录每章一行：解锁的能力 / 回答的问题 / 覆盖的材料，读者先定位到章再到节；全书写完后回填。读法只讲怎么读、不讲知识：从第一章顺读到最后；本书自足，不用翻别的。三条路径——满电精读（全读，心法块也读）、快速路径（每节开头的问题 + 结论句 + 📌 定义 + 💡 打个比方与 ☕ 换气，先建直觉，硬核回头补）、复习路径（结论、公式、⚠️ 陷阱，最后过书尾索引；reader.md 声明考试时可称考前路径，并说明 🎯 考点块怎么用——只是问法提示，不标频次）。每条路径给耗时（按块字数估）。附全书规模：章数、节数、节点数、各路径阅读时间。发散参数等全书配置也只在这里声明一次。

书首短而密，比普通章短；材料只有一讲时可压缩成一小节，但定位、前置、生成元保留。

### 2. thread — 运行案例的出场计划

读 spine.md 的运行案例，给每章定一行：本章用新解锁的能力看见案例的哪一层、留下什么悬念、沿用哪组数字。出场表交 chapter 层使用，书尾负责完整解答。做对了的标志：任取前后两章，案例在后一章的出场依赖前一章解锁的能力，而不是重复同一层。

### 3. xref — 跨章引用与首次出现

- **格式统一。** 节 `§N.M`，章 `第 N 章`，节点 `N-xx`（指向其所在节）；不出现"第 3 弧""前面第九节""KP5.7"这类写法。产物在 `output/<课程>/full-learn/book/`：`00-front.md`、`NN-<slug>.md`（两位编号，slug 为英文短名）、`99-back.md`。锚点约定：章 `#ch-N`，书首、书尾各有锚点；render 据此把上述引用转成 PDF 内链接。
- **回指。** 用到更早章的概念时简短一句"我们在 §N.M 讲过的{概念}"，间隔远时必带位置；回指只作提醒，本节推理需要的东西就地写出。
- **前指。** 只指向 spine 计划里确定会讲的节。
- **术语连续。** 写每章前回顾已写的章，核对术语、记号、案例数字的衔接。
- **首次出现表。** 按全书顺读顺序记录产品、公司、系统的首次出场。首次出场自报家门：出身、定位、使用感、独特性——例如介绍一个边缘计算平台，讲它从哪来、节点遍布全球、请求在离用户最近处就地处理是什么感觉、适合什么场景；而不是堆名词式的"某某的边缘节点 FaaS"。之后再提简短带过。
- **终检。** 全书写完，逐个核对指针目标真实存在。

### 4. back — 书尾 `99-back.md`

正文部分（读者用）：
- **回到终极理解。** 重述 apex，此时每个词都已被某章解锁；写清读者脑中现在多了什么；给出运行案例的完整解答。
- **公式墙。** 一面扫一遍就能复习的公式墙（全书骨架的填满版归总纲卷，书尾不重复）。
- **核心认知清单。** 每条一句精炼解释，指回章节；有题集时覆盖题集全部考点。
- **易混概念对照。** 窄表：易混概念与核心区别（正文已开盒讲过，这里只收束）。
- **自测答案。** 章内若有自测题，答案在此，每题附常见错法与为何错。

附录（审计信息沉底，全部窄表）：
- **材料 → 本书反查表。** 由 tree 的 sources 自动生成，读者拿着某讲某页能直接定位到节；一讲可指向多个节（`§X–§Y`），客座讲座也列。开头一句说明它回答"每页都讲到了吗"，豁免页给理由。它弥补"本书顺序 ≠ 材料顺序"造成的索引断裂。
- **节点索引。** 节点 id / 名称（中文 · English）/ 所在节 / 出处（材料某讲某页），一行走通"节点 → 节 → 出处"；合并讲的节点指向同一节。
- **英文关键词索引。** 默认附，不限开卷：按树的板块分表，每行 关键词 | 位置 | 一句提示。
- **考试附录（仅当 reader.md 声明考试信息）。** 考察维度 → 章节映射（维度、题号作出处），每个维度一句话答案并指回节。往年题本身已作为材料进树、进正文例子，这里只做映射；不写占比、频次、"高频/必考"——那是 core 禁止的重要度标签。

### 5. volume — 卷串讲 `NNv-<slug>.md`

每卷最后一章之后一份卷串讲，专门把这一卷的全部内容串起来——章骨架把一章收拢，卷串讲把一卷收拢；没有它，读者手里是几章各自整齐、彼此不通的骨架。它不讲新知识，只讲关系，全部指回 §。总结要两个方向都走：自下而上概括细节（bottom-up），更要自上而下说清**为什么学这些**（top-down）——读者学泊松分布不是为了泊松分布，而是为了描述输入；脱离这一层，总结只是更短的目录。top-down 的依据是全书唯一的**目标树**：终极目标拆成几片拼图（子目标），每卷补一片，每块补那一片里的一角；目标树在 spine 阶段与全书骨架一起定下（spine 方法 3），卷串讲与总纲只引用、不另拆。
- **在终极目标里的位置。** 先讲 top-down：终极目标是什么、拆成哪几片、本卷补的是哪一片；缺了这一片终极目标哪里断；本卷每一块各补这片的哪一角、为什么要进课件——这一段决定读者用什么眼光读后面的细节。
- **本卷的问题与答案。** 卷入口问题，用一两句话给出本卷的答案；问题按好奇心阶梯取本卷答得了的最高一级（"为什么平均容量够还排长队"，而不是"排队论讲什么"）。
- **卷骨架（填满版）。** 同书首各卷导览的那段话与那张图，这次每块填上具体结论。
- **按块串讲。** 每块一小节，先一句 top-down（这一块为子目标补什么、不学它哪里断），再 bottom-up：块内各章的大概念如何接力——上一章的哪个概念是下一章哪个概念的前提、被推广、被反驳；块与块之间的接口。把本卷那条主推理链（或公式链）从头到尾走一遍，每一步标出在哪一节。
- **概念位置表。** 章 | 大概念（取自各章骨架）| 它用到前面的什么 | 它交给后面什么。
- **跨章易混。** 本卷里分属不同章、最容易混的成对概念，一句话分清并指回两处 §。
- **运行案例在本卷。** 一段：这一卷让读者对案例多看见了哪几层。
- **收。** 本卷让读者能做的事——说成"拼图的哪一片现在补上了"，以及这一片缺什么、由下一卷补（引出下一卷的问题）。
篇幅约 2500–4000 字；不重述推导，不放原图。

### 6. map — 总纲卷 `98-map.md`

全书最后一份正文（书尾附录之前），一卷专门给所有卷归纳整理位置，取代节点级科技树。它先 top-down 再 bottom-up：
- **终极目标与拼图。** 目标树：终极目标一句话 → 几片子目标 → 每卷补哪一片、每块补哪一角、缺了哪里断；配一张 `%% skeleton` 图（子目标为框、卷与块为子题）。后面各部分都挂在这张目标树上。
- **全书骨架（填满版）。** 书首那段话与那张图，每卷每块填上读者现在能说出的结论——书首给外框，这里是拼好的拼图。
- **层级总目录。** 卷（标出它补的子目标）→ 块（标出它补的一角）→ 章 → 大概念 → 子题（§）逐层缩进，取自 book-skeleton 与各章骨架（脚本生成，不手抄），读者从任何一个子题都能读出它在全书哪一格。
- **跨卷主线。** 每条根思想沿哪些卷、哪些章、哪些概念走过，写成一条路径。
- **按问题找位置。** 读者会遇到的问题类型（"给一张测量表求响应时间""SLA 写成百分位怎么反算""CPU 忙但吞吐没涨"……）→ 卷 / 块 / 章 / §。只做定位，不标频次。
- **卷与卷的接口。** 每对相邻卷：前一卷补上的那片交出了什么、后一片拿它做什么、两片合起来离终极目标还差什么。

**总结的呈现：一棵拆散的树，一层一张图。** 全书的总结是一棵树：根是总纲（这门课在学什么），往下是卷串讲、块小结，叶是各章心智卡；世界模型 vN 每章刷新一次根。树拆散了撒在阅读路上——叶在每章末，块小结在块末章（chapter 方法 4），卷串讲在卷末，总纲单成一卷——读者每一两章就收一次。每个结向上说挂在哪、向下说收了谁，读者在任何一个结上都能顺着走到根。卷串讲与总纲是"拼图"，只用文字会退化成一维的长段落。每一层用一张 DAG 图（`%% skeleton` 画法：框是本层的节点，框内只写这个节点的一两行说明——补什么、交出什么——不列它的下一层；框间箭头写关系与交接物），文字退到图后做解说：
- 总纲：一张全书图，节点是 5 卷（各自补哪片拼图、缺了哪里断、交出什么）；每卷再一张卷内图放在层级总目录对应处。
- 卷串讲：开头一张"位置图"——同一张全书图，本卷高亮（`class X here`），其余变淡（`class Y dim`），读者一眼看见自己在拼图哪一片；卷骨架处一张卷内图，节点是块；每个块小节开头一张块内图，节点是章（框内写该章的大概念）。
- 块小结：一张小树图，节点是块内各章，框内一行"留下：…"（该章心智卡的一句话）——与卷串讲的块内图同层，但框内写的是结论，不是大概念。
- 同一张图里不跨层：卷与块不混在一张图里，块与章不混在一张图里。下一层的内容只出现在下一层的图里。

### 7. 样章与批量

build 中 book 先写书首，再配合 chapter 写样章。交付样章时报告规模（本章节数、节点数、篇幅）并请用户审格式与节奏；通过后按同一模板批量写其余章，最后写书尾、回填目录、跑 xref 终检。

## 判断准则

- **读者价值 > 完整性展示。** 一样东西主要用来证明"都覆盖了"→ 附录；帮助理解或定位 → 可进书首。
- **自足 > 简洁指引。** 回指省掉的若是推理必需的内容，宁可就地重写一句。
- **从树生成 > 手写。** 前置、大图、目录、反查表、节点索引都从 tree / spine 生成；手写会漂移。
- **一次 > 每处。** 全书性的说明（读法、参数、图例）只在书首出现一次。
- **有则写，无则不留空。** 考试类附录与 🎯 块只在 reader.md 声明考试信息时出现。
- **不越界。** 速查册、讲义这类压缩成品是 compose 的兄弟模块（复用 devices），不塞进这本书的书尾。

## 反例

- 书首只列章名与讲次 → 没有终极理解与生成元，入场价值为零（理论 2）。
- 开篇一张 8 列课件对照总表 → 审计产物占了第一页（理论 3）。
- 每个章文件头都重复三种读法 → 契约散成噪音（理论 4）。
- "定量对比在 L4-17""详见前文" → 指针替代了内容（理论 6）。
- 每讲一本、每个知识点一个文件 → 碎片化，读者自己缝（理论 1）。
- 运行案例每章换一个 → 线断了，数字无法沿全书自测（理论 5）。
- 前置写"补课见某书第 3 章"而材料里没有 → 编造出处，违反保真。
