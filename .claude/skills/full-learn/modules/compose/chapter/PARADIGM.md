# compose/chapter — 范式

## 一句话

一章是读者脑中的一级台阶：从一个读者自己感到的困惑出发，走过一串轻重交替、首尾相扣的节，带着一项新能力和下一个问题离开。

## 理论

**1. 章是一项能力，不是一份材料。** 章的单位来自脊柱：一章 = 解锁一项能力的一串节点，可以跨 Lecture（讲）。所以章的一切安排——讲什么、多长、先后——都由"这项能力"反推，而不是由课件页数顺推。能力要能拆成读者合上书后应当记住的 3-5 件事（carry-away），每件都必须有某一节负责教会；反过来，每一节要么服务其中一件，要么为后面的节打地基，否则就是装饰。这是一个双向闭合：节的"解锁"之和 = 章的能力，章的能力之和 = 全书的终极理解（apex）。一章在脑中是一个认知台阶，按思考发生的顺序走，并且自成一体：有自己的开章与收章，单独拿出来也能读。

**2. 两把互不相关的尺：分量与负载。** 分量（weight，多重要）决定篇幅；负载（load，多难读）决定节奏与时长。动机图是"背景·轻"，核心推导是"核心·重"，核心速查表是"核心·轻"——两把尺各管各的。分量不凭感觉标：它来自科技树的客观分量（下游传递闭包里的节点数），再按该节点在本章能力里扮演的角色分成核心 / 常规 / 背景三档。篇幅按分量分配，不按知识点个数均摊——覆盖 ≠ 均摊。权重不对的后果是双向的：不重要处废话连篇，重要处解释不够。写超了不是"更详细"，而是把贵的那部分挤掉了；所以加权是再分配，不是通胀。经验上最大的字数泄漏点是背景节。

**3. 读者的脑力是一条会耗尽的曲线。** 连续高深的递进会把曲线打穿，读者从"没看懂"变成"不想看了"；低强度的废话连篇同样致命，读者先觉得被浪费时间，专注度先崩。好老师的本能是推完证明讲个画面、讲完画面回黑板——规则化就是"拆开大的理解负载，硬核之间穿插变奏"。这是**序列级**的事：单节写得再好，排在三个推导之后也会读不进去；章越长越需要编排（章的长度上限由 spine 切章控制，章内只管排）。还要分清：长度不是节奏——800 字的重节质地有变化就不闷，300 字全是定义堆砌照样闷；读者刚啃完最难的一步时，一个画面钉子最容易钉牢。

**4. 问题链替代了实时确认。** 书没有交互，作者看不到读者是否消化。唯一的保证是：每一节结束时留下一个读者自己会问的问题，下一节恰好从它开始。过渡句负责"为什么要读下一节"，章首导读条负责"要花多少力气"。机械过渡（"接下来我们讲 Y"）切断了这条链，读者就只是在被投喂。

**5. 骨架先行，细节是往骨架里填。** 人不是扫描细节的机器：细节全有、但铺开没有层次，读者建不起认知模型，反而迷路在细节里。老手脑中的一章不是一串节，而是一副骨架——少数几个独立的大概念（3–6 个），每个下面两三个子题，大概念之间是说得出名字的关系（包含、递进、并列、因果、对比、前提、应用）。骨架像拼图的外框和分区：边界知道了、每块大致画什么知道了，剩下的只是把每一处的细节填进去。所以骨架必须先于节存在：先定骨架，节是填骨架叶子的单位；挂不上骨架的内容要么删，要么压成背景。骨架的表述是一个"连词成句"的动作——把这几个大概念用一段话连起来，这段话就是这一章的论点；同一副骨架再画成一张图。开章给读者骨架（外框），收章把骨架那段话用本章得到的具体结论重说一遍（填好的拼图）。画"节的先后路线"不算骨架——那只是把目录换成了图。章的骨架向上拼成卷的骨架、全书的骨架（book 方法 1），读者在任何一页都能说出"我在全书哪一块的哪一格"。

**6. 读者要出手，不只是收。** 读者打游戏时能高频处理更复杂的信息还不累，读书 40 分钟就困——差别不在信息量，而在循环：游戏几秒一个"行动 → 结果 → 调整"，书若只让人读，就一个循环都没有；作者先替读者撞完未知再讲给他听，等于把"征服未知"的快感偷走了。所以每章要不断制造"我现在的世界模型解释不了"的局面，让读者先押注、再拿到恰到好处的反馈、亲手升级模型：开章一个挑战（选项都是常见直觉，立刻揭晓对错与错因，再引出正文）；关键转折前一句"先猜"；答对且理由对可以跳关。读完要留下的东西极少——一张与全书目标挂钩的心智卡、一句更新过的世界模型——读者感到的应该是同一幅拼图又完整了一格，而不是又多了一章细节。总结本身是一棵拆散了撒在路上的树：叶是每章的心智卡，每读完一个块（2–5 章同一个问题）有一张块小结把这几片叶收成一个结，卷末的卷串讲收块，总纲收卷；世界模型 vN 每章把根刷新一次。读者因此每一两章就有一次 wrap-up，而不是读满一卷才第一次看见全貌。进度要看得见（拼图点亮），目标要近在眼前（本章解锁的那道考题）。

## 方法

### 1 `open` — 开章

**先定骨架再写。** 动笔前不是列节，而是回答：讲清这一章，老手会在白板上写下哪 3–6 个大概念？候选来自本章节点里树分量最高的那些（以及生成元），取舍由本章要解锁的能力决定；它们就是读者合上书该记住的部件（carry-away）。然后：
1. 大概念彼此独立（不互相包含；包含关系应当是父子，不是兄弟），用名词短语命名，读者的词，不用节标题；
2. 每个大概念下通常 2–3 个子题（最多 4 个；某个概念确实只由一节承担时允许 1 个，节数少于 6 的小章允许只有 2 个大概念——宁可骨架不对称，也不为凑数把节挂到不属于它的概念下或一节挂两处），每个子题是一片叶子，标明哪一节填它（`§N.M`）；本章每一节恰好挂在一片叶子上（一片叶子可以由几节合填）；挂不上的节是信号——删、压成背景、或说明它属于哪个大概念；
3. 大概念之间连边，每条边写关系词（包含 / 递进 / 并列 / 因果 / 对比 / 前提 / 应用）加一句短语说清"怎么个关系"；
4. 连词成句：用一段话（约 80–160 字）把所有大概念按这些关系连起来，每个大概念在段中首次出现加粗——这段话读起来就是本章的论点，只立结构，不提前泄露数值结论。
骨架定了，篇幅才定得下来：核心档就是骨架里承重的那几片叶子。

**开章的骨架**（顺序即读者的阅读顺序）：
- 文件首行一句话：这一章要回答的核心问题——开章先立问题，再给任何东西。
- 章首导读条（🧭，每章必有，块的形式归 devices）：本章只装的那一个念头 / 解锁的能力（它是全章的锚点，后面每节都回指它）（与脊柱章标题行"解锁"一致）+ 阅读时长。时长由字数算出，不拍脑袋；若节下另有分钟标注，章首时长等于其和。导读条落在首个 `## §` 之前；出处不进导读条，走节注释与脚注。
- 先回忆（非首章）：一行"合上书，先说出世界模型 vN−1"（答案在上一章末）——最便宜的提取练习。
- 本章 boss：一行写本章解锁的往年题 / 练习题（取自书尾"往年题 → 节"映射），收章"现在去打"；没有直接对应题的章写它是哪道题的前置。
- 开章挑战（⚔️ 押一注，块的形式归 devices）：题从本章好奇心阶梯（spine）的最高可答级出——问"为什么会这样"，永远不问"X 是什么"；一个与本章入口问题同向的具体情境题，3–4 个选项，错误选项必须是常见直觉（读者现有世界模型的自然答案，目标是聪明人约一半会选错），不是凑数项；揭晓紧跟（render 让它另起一页）：哪个对、每个错的错在哪、对的为什么对，最后一句引出正文。挑战旁给"答对且理由也对 → 跳到本章心智卡"的链接。挑战不改正文，只是正文前的一道门。
- 开章场景：从一个具体问题起。先把问题说成人话、让读者对问题本身有通俗而完整的理解，然后才谈"熟手拿到它先做什么"；再引出本章那一个念头。目标是把脊柱里的章入口问题变成读者**自己的**困惑，而不是作者的议程。首章从零开始；非首章先用 2-3 句接住上一章收尾抛出的问题，若本章依赖的节点是上一章刚讲过的，就在这几句里自然带过，不另设回顾。
- 本章骨架：引导语 `**本章骨架**` 后紧跟连词成句的那段话；随后一张骨架图（mermaid，首行 `%% skeleton`：每个大概念一个 subgraph，标签是概念名；子题是其中的节点，标签 `子题短名 · §N.M`，承重的叶子标 `:::core`；大概念之间的边写成 `A -->|关系词：短语| B`，并列与对比用 `-.->`）。骨架即"带走清单"，不再另列平铺的 N 条（🎯 在全书只留给考点块）。再一句写明哪些内容只略写、不展开（没有就写"无"）。骨架放在开章场景之后、首个 `## §` 之前：读者先有了自己的困惑，骨架才是"答案长什么形状"的外框，而不是一份议程。节点 id 与"分量"一词不进正文（core 禁止清单）。开章与收章是不编号的 h2，名字可以自然一些。

**判断做对了**：骨架每片叶子都指得到节——指不到就是缺一节，不是"让读者自己悟"；每一节都挂得上一片叶子；遮住骨架图，只读那段话能把图画回来；冷读者读完全章，合上书能凭记忆画出骨架（大概念 + 关系），再往叶子里说出各自的要点。

### 2 `pace` — 节奏编排

先做一张写作期的编排表，每节两列：分量档、负载档。这张表是作者的工作底稿，负载评级不印进正文（T3）。节级 🧭 导读条开不开由这里定、全书统一：默认不开，书的节奏靠编排与过渡句承担；开时只印分量、时长与读法（格式归 devices），负载由"读法"一栏用读者的话转述。评级必须诚实——含推导链的节判成轻，时长和换气位置就全错了，等于对读者撒谎。

**分量三档**（由树分量 + 本章角色定）：
- 核心：承担 N 条的节点及其直接推导，通常也是本章高分量节点。合计占本章篇幅 ≥55%，单节可以很长。
- 常规：支撑核心的机制、术语、分类；约 30%，正课 + 按需校准块。
- 背景：动机、路标、时间线、一次性对照、"知道有这回事"的清单；合计 ≤15%，单节 ≤800 字，且不长于核心节篇幅中位数。
- 节内同样分贵贱：推理/认知 > 做法 > 操作细节。
- 填完先自查：标核心的节是不是就是那 N 条？不是就说明权重错了——砍长错的节，而不是给重点加字配平；单节字数超出其分量与负载对应的区间（区间见 section），先拆节或精简，是灌水就删；需要补的字数优先从重复段和背景节挪，整章不变长。某节既不服务 N 条也不打地基，就压成背景（材料仍在，只是变短；全范围覆盖由 audit 审）。

**负载三档**（可从树分量和推理链长度预估）：
- 轻：术语、分类、定义为主，无推导，一个类比就懂。极轻的节点可以只写"是什么 + 在大图哪里"，本身就是一次换气。
- 中：一个机制 + 一个例子，有一两个公式但不推导。
- 重：推导链、公式表、多步数值算例、多概念合并对比。

**编排规则**（都是"别打穿曲线、也别让它空转"的推论）：
- 不连续 3 个重节；两个重节相邻，交界处放一个换气块（☕，块类型由 devices 定义），位置在过渡句之前。
- 不连续 3 个以上轻节——那是在读名词表，该合并；连续两个轻节时至少一个要有画面，靠正文里一句带画面的话或一个 📎，不硬配 💡、不为凑数配类比，轻节也不塞换气块。
- 每个重节内部至少一个 ☕，放在最重的一步（或深度例子走完）之后。
- 硬核连续约 25 行就换一次质地；推导链超过 25 行时在链中段换质地（数值代入 / 💡），链末再 ☕。抽象之后紧跟具体数字，重推导之后接轻段。
- 排不开时：先在脊柱拓扑允许的范围内调序；调不开就把某个 🔍 独立成轻节插进去，或合并；仍不行，回 spine 改切章。节奏从不以打破依赖顺序为代价。

**判断做对了**：编排表上找不到三连重、三连轻；每个重节和每个重-重交界都有 ☕。

### 3 `bridge` — 节间过渡

每节以一句过渡收尾，这句话直接取自脊柱四格里本节"留下的新问题"，它就是下一节的入口问题。常见三种形态：抛出新问题；顺势引申（"既然知道 X，你自然会问 Y"）；制造连接（"X 还依赖一个没讲的 Y"）。下一节直接从这个问题开讲，不做"前情回顾"。不用"接下来我们讲 Y"。

内容的归属也服从问题链：提示、易错点、例题都放回它所属的那个知识点、那一节，不另设"卡住了怎么办""验算清单""练习题"这类综合章节——读者不知道何时该翻它们，它们也切断了问题链。节标题按内容命名（讲的是什么），不按技法命名（用了什么写法）：不是"为什么 X—对照式发散"，而是"三个矩阵不是一个—解耦的代价跟收益"；不是"训练显存—痛点-方案-效果"，而是"训练显存—7B 模型为什么单卡装不下"。正文也不出现"① 契约 ② 原理"式编号小标题——那是在填槽，不是在推理。

**判断做对了**：把每节最后一句与下一节第一段对读，前者的问题正是后者在回答的。

### 4 `close` — 收章

- 心智卡（🧠，收章第一块，形式归 devices）：结构化叙事，不写成段落——① 一个放在全书大图对应位置上的问题；② 两三条"❌ X —— 不对，因为 …"（常见错答与它们错在哪）；③ "✅ 正解：… 。因为 …"（核心因果与机制作为理由）；④ "一句话：…"——回答阶梯最高级那个问题，开章抛出的悬念在这里落地。它是本章被读薄之后剩下的东西，读者靠它在几秒内回想起机制，不是正文的压缩摘要。
- 块小结（🌳，只在两章及以上的块的块末章，紧跟心智卡，形式归 devices）：总结树的中间一层。卡片是这个结本身——"这块在问"（本块存在的理由，从卷的那片拼图往下问）、"合起来的答案"（几章拼起来回答了什么，讲机制，不把各章再列一遍）、"往上挂"（补的是本卷那片拼图的哪一角、缺了哪步会断）、"往下接"（交给下一块什么）、"一句话"；卡下一张小树图（`%% skeleton`，框 = 块内各章，框内一行"留下：…"即该章心智卡一句话的压缩版，箭头是章间接力）。一章的块不写，那章的心智卡就是块小结。
- 世界模型 vN：一段话写出到本章为止整门课的模型，本章新增的部分加粗；与 render 画的拼图进度图（已读的格点亮）放在一起。vN 一章一章累积，按章序由同一个作者写。
- 回到开章那个问题，现在用本章得到的能力回答它。
- 复述本章那一个念头，并写一句"你现在能做、之前做不了的事"（"你现在能做到"清单对应本章解锁的能力）。
- 回到骨架：把开章那段连词成句的话重说一遍——同样的大概念、同样的关系，这次每处填上本章得到的具体结论（式子、数、条件）。读者对照开章那段，看见外框里的拼图已经填满。
- 阶段地图：到此为止科技树上已点亮的局部图，让读者看到这一章把树推进到了哪里。
- 计算型章（解锁的能力是"会算"）收章附一张可以照抄的公式卡：本章每条要用的公式一行、符号就地释义、按计算顺序排；材料公式有勘误的写正确式，并标"与课件 L4 p42 不同，见 §21.4"。公式卡是正文推导的索引，不替代推导——没读过推导的人照抄会抄错适用条件，所以每行带一句适用条件。
- 章末思考题 3-5 道，按基础（定义 / 直觉）→ 应用（关系与原理）→ 综合递进，综合题跨本章与前面章的节点；只能用本章及之前已出现的节点，聚焦本章节点及其依赖；答案不紧跟题目，放书尾。
- 本章 boss："现在去打"——指向开章那道题与书尾答案的位置。
- 最后抛出下一章的入口问题作为钩子，一句话引出好奇心；上一章/下一章链接交给 render。

每章一个文件 `book/NN-<slug>.md`；每节标题下一行机读注释 `<!-- nodes: … | sources: … -->` 承担"覆盖了哪些节点、来自哪些页"，文件头不再列覆盖范围与来源；与课件的逐页对照表属于 audit。

**判断做对了**：只读开章和收章，读者能说出这一章从什么问题出发、到哪里结束、下一步要问什么。

## 判断准则

- **依赖顺序 > 节奏。** 节奏只在拓扑允许的范围内调；调不动就插轻节、合并，或回脊柱改切章。
- **客观分量 > 感觉。** 分档以树分量为起点；若某个低分量节点在本章能力里明显居中心，先怀疑树的依赖边，再决定是否升档，不靠手感。
- **一个念头与 N 条不冲突。** 念头 = 能力本身；N 条 = 构成这项能力的 3-5 个部件。
- **字数紧张时**，先砍背景与重复，绝不压缩核心推理链；字数富余时，也不给背景加戏。
- **质地 > 长度。** 判断闷不闷看质地有没有变化，而不是数字数。
- **覆盖是审计，不是均摊。** 材料要全，但低分量的内容以背景的篇幅出现即可。

## 反例

- 设"卡住了怎么办""30 秒验算清单""练习题"综合章：违反问题链，读者不知何时该翻，提示也脱离了它的知识点。
- 一页动机图配齐类比 + 换气 + 定义 + 深度，和核心公式那节一样长；背景节超 800 字或比核心节还长：违反分量决定篇幅。
- 没有章首骨架，读者读到第 12 节还不知道哪几节是重点：违反骨架先行。
- 开章图画的是"§1 → §2 → §3"的节路线、或平铺五条"带走"：那是目录换了个样子，看不出概念之间谁包含谁、谁推出谁，读者仍在细节里迷路。
- 先写节、写完再从节里归纳骨架：骨架成了事后贴的标签，节的边界不受它约束，铺得再开也收不拢。
- 带走清单的某条指不到任何节，谁也没负责教：能力闭合断了。
- 三个推导节连着来，中间不让读者喘：打穿脑力曲线。
- "接下来我们讲 Y"：过渡没有问题，链断了。
- 用"对照式发散""痛点-方案-效果"这种技法名当标题：读者从标题里得不到内容。
- 发现重点讲薄了就给它加字，背景一字不砍：加权变成通胀，整章变长。
