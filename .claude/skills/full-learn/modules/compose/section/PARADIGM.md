# compose/section — 范式

## 一句话

一节把一个节点写成一条读者能跟着走的推理链：先让读者真的想问，再让 TA 看着一幅画面差点自己想到，最后结论从画面里长出来——读完的人能从那幅画面重新推出结论，而不是记得课件长什么样。

## 理论

**1. 一节只装一个念头，单位是念头不是课件页。** 旧版失败的形态是"通俗在措辞、不通俗在推理"：跟着幻灯片的顺序走，描述颜色和方框，推导整块转录，类比挂在旁边。读者读完知道那页长什么样，却不能从一幅图重新推出公式。原因是组织单位错了——课件页是讲者的提纲，不是读者的思路。一节对应科技树上一个节点（或一小组紧耦合节点），它要交付的是一个能一句话说出的念头；说不成一句，说明塞了两节的量。

**2. 借一个高手的脑子（原文 → 我读到的）。** 读者的瓶颈不是读不到原文，而是读到了脑中没有东西出现。所以写法单位是成对的：材料里那句话 / 那个式子，紧跟着第一人称写"我读到这里时脑子里在想什么"。高手的价值不在结论（结论很便宜，材料里就有），而在"熟手为什么会想到它"：看到问题时的第一反应、那个反应在哪里坏掉、退一步看见了什么真正的需求。弯路要写——删掉弯路，读者就只剩结论可背。

**3. 问题先于答案。** 人只会吸收自己已经在问的问题的答案。每节从读者此刻能感到的具体困惑开始（通常是上一节留下的问题），用读者已有的语言说出来；答案到达时，它填的是一个已经存在的空，而不是一条漂浮的句子。这条取代了旧规则"钩子之后立刻给定义"：先抛问题这一点保留，定义改为在推理落地处给出。

**4. 结论从画面里长出来。** 新符号出场之前先有画面，任何形式化之前先用日常语言说一遍。理想的链是：朴素做法 → 它在哪里坏（最好带数字）→ 退一步看真正需求 → 在画面上看出关键关系 → 写成式子 → 命名。到这一步，精确定义是读者已经看见的东西的名字，因而"自然可懂"；全节之后的每个细节都挂回这一个锚句。锚是认知负担的减压阀：知道"现在在讲什么"，记忆压力减半；忘了全部公式，凭锚句和画面也能重建。

**5. 五个维度要交付，但按推理链排队。** 直觉（画面）、存在意义（没有它会卡在哪）、大图位置（从哪来、通往哪）、精确定义、关键例子——每节都得给齐，但没有固定出场顺序。同理，旧的"十步模板""五问模板"（是什么 / 怎么想到 / 为什么好 / 为什么不别的 / 挂回整体）全部降为可调用的推理动作：怎么想到是正向叙事，为什么不别的是横向比较，它们是链的成分，不是表单的槽——核心节里怎么想到、为什么好、为什么不别的三个动作都得走到，只是化在行文里。槽保证要素齐全，也保证读起来像表单；要素齐不等于能跟上。要素之间只有一条硬序：基础层（它是什么角色、为什么存在、怎么运作、怎么用）先站稳，进阶层（它为什么会合理、是被什么思路发明出来的）才开——先知其然，再知其所以然。

**6. 篇幅是差距，不是均摊。** 一节该多长 = 节点分量 × 读者起点到它的差距。要推公式、过手算、破直觉的就多写，只是"认个脸"的就一段话。决定这把尺的，是节末那一行可检验的目标：它是作者给自己的加权尺，不是给读者的第二份小结。

## 方法

> 前置节（节点全是 external prerequisite）走变体 `variants/prereq.md`：那里只列被覆盖的条目，其余照本范式。

### 1 prepare — 动笔前想清楚

读四样：tree 里这个节点（one_liner、why、requires、下游）、spine 给本节的四格、raw 里的来源页——有图的页用 Read 看图，图里的信息要进入讲解——以及 T1b 讲者脉络里对应的那几步。从材料里抽三样对齐后文：老师的定义、老师的例子、老师强调的边界与陷阱（边界与陷阱一定进书）。讲者脉络决定推进方式：老师在这里用的悬案、反例、"NO!" 式的反转照走；老师的例子是推理的首选载体（一个例子跨几页就跟着它走几页，不中途换成自编例子）；老师的直觉原话保留英文作锚。T1b 标了"跳步 / 缺动机"的步，正文补上，补的部分只往回引用。如果范围里有真题，用它反推：做对这题需要懂的那两三句认知，本节是否讲到；没讲到就整合进正文，考卷出处走脚注。读者的提问与反馈同样整合进推理链本身，不在节末追加补丁块。

再在心里答三问，决定形态：**概念形态**（单一原子 / 复合 X=A+B+C / 多层抽象——多层的必须显式分层，否则细节漂移，读者不知道挂哪层）；**取舍类型**（改进型 / 设计选择型 / 选型决策，决定"为什么不别的"怎么写）；**来源**（材料内核心 / tree 里标 external 的隐含前置 / 材料外补充，决定深度，后者走 devices 的外部补充块，深度逐层递减）。

节首一行路线（🗺️）：在节标题与节注释之后，用箭头写出这一节每一段要干什么（如"撞墙（银行排队）→ 推导速率 → 拿平台的数验算 → 结论"），读者读每段之前就知道它的用途——组织，不是压缩。

最后先写目标再写正文：把"解锁了什么"压成一行可检验动作。写不成一行（要用顿号并两件以上的事），就是拆节信号，回传 spine。按目标判断分量档：核心 / 常规 / 背景（档位与预算归 chapter）。先定分量，篇幅和阅读时长才从它换算出来；顺序反了，就会出现"背景节写了两千字，于是标 8 分钟"这种自洽的错。背景判定：删掉这节，读者会不会答不出本章要带走的那几件事？不会，它就是背景。

### 2 reason — 写推理链

核心节里，每个关键揭晓（反直觉的结论、一个式子的出处、一个数的意外）之前先放一句 🤔 先猜，答案就是紧接的下一段；读者先押注再读，揭晓才是"撞墙"而不是"被告知"。

**入口。** 标题 `## §N.M 中文 (English)`，下一行机读注释 `<!-- nodes: … | sources: … -->`。入口问题取自 spine 四格，是读者此刻真实的疑问。第一句是画面或具体问题，不是"X 是……"：抛痛点（熟悉场景里一个现在办不到的事）、抛连接（上一节解决了 A，B 还没解决）、或抛反直觉（你以为 X，其实 Y）。一两句够，只用通用中文和排在前面的节点的语言——待讲概念的术语、机制、公式都不出现；只开门不剧透；不让类比独占开场；不写"让我们来看一下"。钩子制造好奇后立刻交棒给推理链的第一步，中间夹一两句交代位置：本节点从哪个前置来、通往什么；若它汇合本章几条线索，就一句话串起来（"前面分别有了 A 和 B，它们在这里汇合"）。用到的前置就地用一两句日常话复述，因为读者可能跳着读。用到的是 external 前置时，复述就是它那句念头加节号回指（"ρⁿ ≤ ε 是乘法世界里的问题，按 §4.5 的换坐标搬到加法世界去解"）；第一次用到时必写——前置节不提后文，两头靠这一句接上。

**想通。** 这是全节最贵的部分，要写透：先把问题说成人话，再走"直觉 → 为什么不行 → 退一步看本质 → 得到做法"。痛点先画场景再给复杂度符号（"这个矩阵在 n=4096 时多大"胜过一个 O 记号）。公式先讲思路再给式子，绝不把式子当定义抛出；推导每一步说它在想什么，而不是把课件推导转录一遍或把公式翻译成中文。说不明白，说明作者自己没懂，回去想。

**为什么是它、为什么不是别的。** 就在这里当下回答，不留到后面另开一节。"为什么是它"要抓这个具体选择的非显然好处，显然的好处不值得写。改进型（架构演进、工程优化、算法或训练改进，以及"为什么需要 X"这类动机节点）走"痛点（带数字）→ 方案 → 效果与代价"；设计选择型拿出候选，对比 A/B，用反例、实验观察或理论缺陷指出 B 怎么坏，再回到 A——记住 A 同时记住 B 为什么不行，就同时拿到了正解和它的边界。替代方案要具体到后果，不只说"不好"；通俗化压篇幅时反例最后才删，因为它就是边界本身；任何"X 比 Y 更……"都要开盒：快在哪、为什么、要懂多深。抽象架构自身的核心机制不套改进型三段，它靠深度例子活起来。边界与模糊归类不给结论，给逐问排除的推理流程——模板对每个对象都管用，比结论值钱。

**落锚。** 推理到达处给出精确定义：一句话身份证——它是什么样的东西、输入什么、输出什么，需要时附公式；用人话、技术中性（只说它做什么，意图留给角色锚点），不拿术语解释术语；再压一句角色锚点（"它活着是为了……"），挂到 tree 的前置与后继上。锚点必须在深度例子之前出现，因为例子要按它索引。有方向的推理可以先于定义，绕圈的铺垫不行。

**行文。** 三拍（卡在哪 → 怎么想通 → 落到手上）之间用正常行文过渡（"于是问题变成……"），不写编号、不写小标题模板、不用①②③小标题；全是 bullet 或全靠表格的节没有故事。只有确实需要多步的才分步，每步建立在前一步上，简单概念不硬拆。顺序是认知 → 做法 → 细节，操作性细节（代数、算术）不得挤占"为什么这么想"的篇幅；通俗在前、专业有深度，两者并存（约六比四作参考）。复杂节的非显然要点逐项拆开，每项配一个具体片段或数字加一两句解释——那是专业含量的载体。材料某页只是一张对照表或清单时，正文一句话说清它要说明什么，表照抄，不逐行复述。陷阱写在它所属的节点下，验算方法写在能用它的节点下，有用处就近挂。同模式节点回指已读的节，一句话复述共同点保自足，只展开差异。

**节奏。** 节奏的尺子归 chapter，section 在节内执行：硬核连续约 25 行就换质地（数值代入、入门段是软换，换气是最强复位，器件定义见 devices）。负载重的节在最重的一步之后放一次换气，刚啃完最难的给画面最牢；轻节不塞，轻节的画面长在正文里。器件按需调用，不凑齐：没内容的块直接不出现。

### 3 land — 落到具体

深度例子是没有它学生只懂名字的那一步。用一个简单而完整的 case，把定义、角色里的每一点在具体数据上再走一遍；每个动作显式回连（"看，这里就是锚句里的那个输出"），做完补一句意义或巧思（为什么这里要除、为什么那里要挡）；末尾一句话把整条流程收回到锚句的各部分。不回连，读者只记得数字流过。材料自带的算例在正文走完全部算式，虚构数字只能另加，不能替代。机制类节点按"何时触发 → 步骤 → 产出"落地，方法类给换个数字也会做的思路与步骤——思路答"为什么这么算"，步骤答"怎么算"，缺一样读者换个数就不会。这一拍要短，它服务前面的想通。

**进阶层（心法）只在基础层站稳之后。** 所以然依赖于然，提前会被当成更难的正课。值得开的是中度以上的核心机制、定律、推导、设计选择，术语分类不值得。判据：材料给了结论也给了原因 → 那是正文的取舍；材料只给结论、原因需要推理重构 → 那才是心法。心法是课本没有、原本只有当面问导师才拿得到的理解，三种落点：约束（找到让它不得不如此的约束、不变量或守恒，读者看到"不是拍脑袋，在这个约束下只能这样"）、同构（指出全书哪一节用的是同一招，给节号）、从业者判断（阈值、使用姿势、什么时候扔掉这个模型）。上一层用推理不用断言，讲道理不讲掌故（不放年份、引语、材料外数字）；具体落地在前，心法与结论框在后。材料外的发散节点用短链：直觉 + 定义 + 和本节点的关系 + 为什么会被问到。

### 4 seal — 封节

依次：一句精确结论（复习时翻到它就能重建本节；section 只管这句话本身，它在书里以 📌 定义块呈现，形式由 devices 定）；方法类节再加一行动作序列，把刚走完的推导收成路线——路线是压缩，推导本身上面必须真的展开过；需要时附一个深度档（要懂多深）；一两句与大图的连接（谁会用到它）；spine 给的留下的新问题，作为下一节入口；最后一块是目标行（即 ✅ 这节拿到了，内容取自 spine 的"解锁了什么"格，长度上限随 spine 定，约 40 字内）：可检验动词（会算 / 能判断 / 能写出 / 能推出 / 能说出为什么），带公式的节写"给{输入}能算{输出}"而不复述公式，背景节也写、更轻（"能认出这张图在说什么"）。MD 里目标行任何情况都保留。

**复盘与校准回路。** 写完不凭整体感觉判断，而是把本范式的动作倒着走一遍，因为整体读着顺最会掩盖缺了一拍：入口问题脱离正文是否仍是一个具体问题，第一句是钩子不是定义；想通处有没有显式推导链（写的是"怎么想到"，不只是"为什么对"），数学是否先思路后公式；为什么是它是否当下答了——改进型有痛点、方案、效果，设计型有对照；落锚的定义是否精确、带维度，复合概念展开前有没有结构图，多层的是否显式分层；角色锚点写了没有；深度例子是否完整、显式回连；类比、真实场景、心法这些器件该有则有、合 devices 的标准；封节有没有结论、留下的新问题与目标行。给了表就要有一个走过它的例子——只给表等于没写完。每节留一行复盘记录，✗ 的那一拍改完再交。

然后拿目标对照正文（自读或冷读者）：到不了 → 哪一步让人"嗯?"就补哪一步，缺的通常是例子、中间步骤或"为什么是这样"，也绝不让读者去课件里找那一步；到得了但同一件事已是第三遍 → 删重复的定位段和二次复述，不删例子。

## 判断准则

- **结构听外层，节内听推理链**：内容与顺序由 tree/spine 定，节在章里的位置与篇幅预算由 chapter 定，块的形式由 devices 定——section 不在节内改顺序或补别节的内容。但一节之内规则打架时按 core 的裁决序：保真 > 推理链 > 节奏 > 器件，某条节奏或器件要求会让推理链断，就让它让路。本范式只讲"一节怎么写、写完怎么复盘"，不讲工作流：何时写、写完跑什么归 compose 的协作顺序，复盘记录由 audit 收进报告。
- **推理链 > 要素齐全**：五维或某个器件和顺读通畅冲突时，改出场位置而不是删要素；要素真没有内容，就不出现。
- **简单概念合并跳步，复杂概念全走**：类比、心法都可跳；但入口问题、精确定义、目标行不可跳。
- **篇幅区间作参考，不作门禁**：按负载，轻约 150-300 字，中约 300-500，重约 500-800，合并对比节约 1000 封顶；背景档的单节上限归 chapter，各档的质地下限（核心、常规、背景各自几种块）归 devices，section 照档执行。超出时先问是不是差距真大，不是就砍。
- **示意**：讲 M/M/1 稳态分布，入口是"这台服务器里恰好有 7 个作业的概率多大"；朴素做法是对每个状态列流入流出的方程组去解，能解但看不见规律；退一步画出状态链，在 j 与 j+1 之间切一刀，稳态下穿过这刀的左右流量相等，于是一眼看见每往右一格概率乘同一个 ρ；归一化要求等比级数收敛，ρ<1 这个条件就从画面里长出来了。结论是画面的推论，不是课件红框里的两行。

## 反例

- **描述幻灯片**：讲颜色、方框、红框和课件页序——违反理论 1，组织单位成了课件页。
- **填表式小节**：①契约 ②原理 … ⑦参考 编号槽——违反理论 5，要素齐全但无法跟上。
- **剧透 / 定义型 / 类比独占 / 废话型开场**："X 是……核心机制，通过计算……"、"想象你在图书馆……"、"让我们来看一下"——违反理论 3。
- **藏定义的绕圈**："听起来神秘其实简单"两段后仍无身份证；或"Q 是查询 K 是键 V 是值"式碎片定义——违反理论 4，没有锚。
- **转录推导**：把公式翻成中文、只有式子没有为什么、纯公式无例子无回连——违反理论 2 与 4。
- **不开盒的比较**："Spark 比 Hadoop 快"就此打住；"为什么不是 B"留到后面单开一节；边界情况只给结论——违反理论 2。
- **重复与跳步并存**：同一定位在三节各说一遍，却在要推导的地方一步跳过；或缺的那步只在课件里——违反理论 6。
- **目标缺失或不可验**：没有目标行，或写"理解了 / 熟悉"——没有加权尺。
- **全是 bullet / 全靠表格**：没有叙事段，没有故事。
- **空泛角色句**："X 是很重要的机制"，或只是把定义换个说法——没压缩出"为什么活着"。
