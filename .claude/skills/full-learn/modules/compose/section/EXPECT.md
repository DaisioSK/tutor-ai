# compose/section — 验收

本表只列人要做的条目（self / cold-read / 脚本未实现）；纯脚本检查在同目录 `GATES.md`，写作时不必读。

逐节判定。脚本检查名以 audit PARADIGM「脚本注册表」为准；`script(todo)` 未实现前由 audit 按同名动作人工执行。

| id | 验收标准（可判定的一句话） | 检验方式 | 不过时回到 |
|---|---|---|---|
| E-SEC-02 | 一节只覆盖一个节点或一小组紧耦合节点：作者能写出本节"那一个念头"的一句话；目标行要用顿号并列两件以上的事时，已回传 spine 拆节 | self: 每节在 prepare 笔记里写出一句话念头；数目标行里的顿号并列项，>1 即开拆节单 | §理论 1 · §方法 1 |
| E-SEC-03 | 动笔前读过对应 tree 节点、全部 sources 页原文，含视觉内容的页用 Read 看过图，且图中信息进入了正文 | self: 在 prepare 笔记列出 节点 id / 已读页 / 已看图页，逐一对照 sources 不缺页 | §方法 1 |
| E-SEC-04 | 材料中老师强调的边界、陷阱、"注意区分"全部进书，且挂在所属节点下；验算方法挂在能用它的节点下 | self: grep 来源页的"注意 / note / 不要 / pitfall / check"类句，逐条在本节找到落点 | §方法 1 · §方法 2 行文 |

| E-SEC-10 | 任何形式化之前先有一遍日常语言说明；"是什么"一句话说人话、技术中性不夹意图、不用术语解释术语；用到的前置就地一两句复述 | cold-read（冷读者标出"术语解释术语"与"没铺垫就上式子"处） | §理论 4 · §方法 2 |

| E-SEC-15 | 核心节含"怎么想到（朴素做法 → 卡住 → 退一步 → 解法，显式推导链而非只说为什么对）/ 为什么好（非显然好处）/ 为什么不别的（具体方案 + 具体后果，即有对照）"三者，以行文而非槽位呈现；"为什么好"写的是非显然好处；通俗化时不删反例 | cold-read（冷读者复述"作者怎么想到的"，复述不出即 FAIL）+ self 勾选三者 | §理论 2 · §方法 2 |
