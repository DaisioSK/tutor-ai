# tree — 范式

## 一句话

材料是一种理解结构被"讲课顺序"压扁后的序列化；tree 把它还原成依赖图，再压缩到少数生成元和一个顶点，让后面一切顺序与分量都能从结构里推出来，而不是从幻灯片里抄出来。

## 理论

**1. 理解有自己的拓扑，与呈现顺序无关。** 课件的页序是老师在课时、作业节点、历史习惯这些约束下选的一种线性化，不是认知结构本身。真正的结构是一张有向无环图（DAG）：边 X → Y 的含义只有一个——不懂 X，读 Y 时会在某一句卡住。这条边可以跨讲、可以逆着页序。因为结构是客观存在的，学习路径就不需要靠学习者边学边告诉我们"卡在哪"：只要 AI 先把完整的依赖认知建出来，路径就能从图里推出。"讲义第几章"只是出处坐标，用来对账，不是组织单位。但依赖图只回答"不能先讲什么"，不回答"怎么讲顺"：老师的讲序、过渡和例子记录在讲者脉络（T1b）里，由 spine 当默认全序使用，tree 不必把它编码成边。

**2. 一个领域 = 少数生成元 + 大量推论。** 好的理解是压缩：看似不同的十几个机制，往往是同一个思路的不同实例（instance）。找生成元（generator）有两把透镜：
- **不得不这样（forcing constraint）**：对每个机制问"是什么约束 / 不变量 / 守恒律 / 边界条件让它只能长这样"。找到那个约束，机制就从"要记的事实"变成"推得出的结论"。
- **同构指认（isomorphism）**：把机制还原成一种思维动作，再去别处找它的再现——如"切片到事件不重叠再取极限""把不确定性换成均值""用守恒代替分布"。共享同一动作的节点，就共享同一个生成元。

生成元之上还有一个顶：**终极理解（apex）**——把整个范围压成一句话的那个模型。它的口径不是"能复述"，而是"能和内行无障碍交流、遇到新问题能问对问题"。先装好骨架（生成元 + 顶），细节就是推论，不用背——这一步把"知识点列表"变成连贯的心智模型（认知网络），是整棵树最值钱的部分。

**3. tree 是全书唯一的入口漏斗。** 下游只读 tree.json；这里漏掉的内容，spine 排不到、compose 写不到、谁都看不见。所以完整性必须在入口拦截：读全、逐页过、每页都有去处。但完整性是一本**账**（审计），不是**结构**：页→节点的映射用来证明没漏，组织仍然按依赖。

**4. 边界相对于读者。** 材料默认你会、却从没讲过的东西，是读者最常卡死的地方。它们作为 `external` 节点显式入树。哪些算 external，不取决于材料，而取决于"材料讲了什么"与"读者起点（reader.md）"之间的缝：缝有多宽就补多宽，不多也不少。同样的相对性也决定向外延伸——从核心概念出发的追问链能生成发散节点，但深度和宽度都受读者参数约束。

**5. 分量是结构量，不是感觉。** 一个节点重要，是因为很多东西压在它上面：它影响对整体结构的理解，或是别的节点的关键依赖。所以分量 = 下游传递闭包的大小，由脚本算。考试证据、材料强调、跨讲重复都是**外部信号**：它们能提示"这里可能漏了边"，却不能改写依赖，也不进正文。

## 方法

### 0. 前置
上游产物 `raw/` 不在 → 停下，提示先跑 ingest；`reader.md` 若存在，先读，它决定 external 的边界与发散参数。

### 1. harvest — 逐页收节点
**做什么**：先把全部材料读完（逐个读 `raw/*.txt`，逐页 / 逐 cell，不跳），再开始连边——只读一半就连边，后半的概念会被硬塞进前半的结构。每页抽出：核心概念与定义、定律 / 公式、方法；作业 / 项目类材料还要抽技术选型与设计决策（它的 `why` 写清"为什么选它不选别的"）。每个节点填 `id / name / en / kind / one_liner / why / sources`；`sources` 是文件短名 + 页码范围，是覆盖对账的唯一依据。

**几条推论**：
- 材料花整页以上讲的一段推导或一道题的解答，自成节点，不压成别的节点里的一行——篇幅本身就是材料作者对"这里需要展开"的声明。
- 材料作者自带的分类与标签（如题型方括号标签、作者自己的分组名）原样保留在节点的 `labels` 里，作为归类与命名依据；它们比任何自创分类都准。
- 代码类材料用四层视角 What → Why → How → Deep 来抽节点，层级记成节点属性 `layer`；What 层顺带产出 apex 候选句"这是一个用 X 技术做 Y 事情的 Z"。层只是收割视角，不是书的组织单位。
- **external 前置**：遇到材料默认会的东西，依次问三问——材料里别处讲过吗？讲过就不是 external。按 reader.md 读者已经会吗？会就不是。只讲了概念没讲实现细节？那只补实现那一截，不从零重讲概念。只收被范围内节点**直接** requires 的前置，不顺着扩成整门课的相关内容。这类节点记 `kind=external, role=prerequisite`，`gap` 字段写明补的是哪一截——gap 越窄，读者被打断得越短。前置节点还要三样东西：
  - **`sources` 为空。** 材料没讲过它，就没有出处页；"用到它的页"归用它的那个材料节点。挂在前置上，脚注与页码账会把后文带进前置节，前置就被迫往后引用。
  - **"给谁用"留在后端，不写进正文。** 反查 `requires` 就是它的使用者（used_by），使用者的 `sources` 就是用到它的页，脚本可算，不另存字段免得两份数据漂移。写作者读它来定"够用线"——后文到底要用这个前置的哪几条性质，就讲到哪；脚本读它生成"不许出现的后文符号"清单、检查后文有没有回指。
  - **`mental_model`：一句结构念头。** 不是定义，是能推出这个前置全部规则的那个画面，如"指数/对数是在加法世界（距离）与乘法世界（倍数）之间换坐标""导数剥掉一层累积，积分加上一层累积"。写不出这一句，说明还没找到它的结构，别急着写节。
  - **成对的前置标 `relations: {type: pair}`。** 互为逆运算或同一结构的两面（exp↔log、导数↔积分）必须同节讲；同时检查它们之间漏没漏 requires 边（讲积分要用导数，这条边常被漏掉）。
- **发散节点（extension）**：对核心概念 A 走追问链——"在真实场景里提到 A，对方最可能追问的下一个概念是什么"。依据依次是：树上已有的 requires 边、辅助关系（对比 / 实现 / 组成）、行业常识（提到 Docker 必被问 K8s）。取 top-N（N = breadth）为一层，递归到 reader.md 规定的层数，越外层讲得越浅；只有关联度过阈值（relevance threshold）的才收。发散节点 `kind=external, role=extension, depth=层号`，正文用外部补充块，删掉不影响对材料的完整覆盖。
- 每页都要有去处：落进某个节点的 `sources`，或进 `coverage.exempt` 并写理由——ingest 已在 manifest 登记的豁免页原样带入，harvest 新发现的不承载知识页沿用同一张理由枚举（封面、目录、分节、路标、总结……），账才对得上。

**做对了吗**：任意抽一页，能在 tree.json 找到它的节点或豁免理由；跨 3 讲以上反复出现的概念只有一个节点（多个 `sources`），不是三个同名节点。

### 2. link — 建理解依赖边
**做什么**：对每个节点 Y，列出"不懂就读不懂 Y"的节点放进 `requires`。判别句：不懂 X，读 Y 会卡在哪一句？说不出那一句，就不是依赖边。对比、组成、实现支撑这类关系是真的，但不是理解依赖，放进 `relations`（`contrast / part_of / implements`），不污染 `requires`。

**为什么**：spine 的拓扑序只认 `requires`；混入"课件下一页"或"相关"会让拓扑序退化成页序，正是旧版失败形态。

**做对了吗**：图无环；存在跨讲边；随机抽边都能说出卡住的那一句；没有一条边的唯一理由是"课件先讲了它"。

### 3. distill — 找生成元与终极理解
**做什么**：对权重靠前、彼此相隔较远的节点逐个上两把透镜（不得不这样 / 同构指认），把共享同一约束或同一思维动作的节点归到一个生成元下，用 `derives_from` 指回去。生成元取 3–5 个，每个说清它的约束、列出由它推出的节点（理想上跨多讲）。然后问：整份材料能不能压成一句话的认知？写成 `apex.statement`，`unfolds` 列直接支撑它的节点。

**例**：概率图模型——"联合分布是因子乘积；推断是把不关心的变量消掉；消的顺序决定快慢"。性能分析——运筹分析各定律是同一招（只用可观测量守恒，拒绝分布假设）；Markov 模型是有假设的显微镜，运筹分析是无假设的卷尺。大数据——scale out + move code to data + sequential I/O；深度学习系统可能是低秩近似 + 异构资源拆分 + 二阶动量。

**做对了吗**：只拿 apex + 生成元，能推出若干非生成元节点的 one_liner；拿一个材料没给的新情境，能用 apex 问出对的问题。做不到，说明生成元找浅了。生成元交给下游时附带一条约束：全书必须覆盖每一个生成元节点。

### 4. weigh — 由闭包算分量
**做什么**：脚本对每个节点算下游传递闭包节点数写进 `weight`，作者不手标"核心 / 常规 / 背景"。外部信号记进 `signals`：材料强调（公式汇总页、数值算例、"Key!"、加粗、老师标星）、跨讲重复、考试证据（往年题直接考过、考试高频）。考试信号只在 reader.md 的「考试信息」不为"无"时启用（T0 是唯一开关，材料里有考题本身不算）。

**信号怎么用**：信号强而 weight 低 → 回 link 复查是否漏边；复查后仍低，以闭包为准，信号仅作同分时的篇幅旁证。信号不改 `requires`、不改顺序、不写进书。

### 5. draw — 出 tree.md
从 tree.json 生成（不手画）：顶部 apex 一句话 → 生成元表（各自的约束与推出的节点）→ 分层 mermaid 科技树 → 节点表（id / name / kind / one_liner / weight / sources），节点表兼任"这个范围有什么"的目录。图按**角色**分组（原理 / 模型 / 方法 / 基础设施…），不按讲分组；层由依赖深度决定（概念分层）。线型：实线 `-->` = 理解依赖，粗线 `==>` = 推论 / 实现支撑（derives_from、implements），虚线 `-.-` = 对比并列，点线箭头 `-.->` = 组成使用。mermaid 源码即科技树图的唯一来源，render 据此出图入书首。

### 6. 交付与回写
本范式在 T2 必需字段之外用到的可选字段：节点上的 `labels / layer / relations / gap / role / depth / signals`，顶层的 `coverage.exempt`。下游不依赖它们也能工作，有则参考。
交付前：每页已映射或豁免、图无环、分量已由脚本算出。任一不满足，不交给 spine。写作中若发现漏建的节点，回写 tree.json，重算 weight，重跑 spine 的拓扑检查——tree 是活的单一事实源，不在章节里就地加概念。

## 判断准则

- **依赖 vs 页序**：拿不准时用卡句测试；页序永远不是理由。
- **独立节点 vs 并入**：材料给了独立篇幅或下游有节点单独依赖它 → 独立；否则并入，作为 one_liner 里的一个分句。
- **external 收不收**：目标是不缺不滥。缝在读者与材料之间才收；只补缺的那一截。宁可在 gap 写窄，也不复述整讲；但若一个公式用到的符号或工具既不在树里、也不在读者起点里，那就是漏标，必须收。
- **生成元太多 / 太少**：超过 5 个说明还没找到更深的共同约束；少于 3 个往往是把 apex 当成了生成元。
- **结构 vs 信号冲突**：闭包优先；信号只触发复查。
- **作者标签 vs 自创分类**：作者的标签优先；自创分组只用于图上的角色分组。
- **范围**：tree 不按考题反推只收必要部分；给定材料全部入账。

## 反例

- 节点按"L3 / L4 / L5"排、边沿页序连 —— 违反理论 1，组织退化回课件。
- 十几个机制各自孤立、没有 derives_from —— 违反理论 2，读者只能死记。
- 读到一半就开始连边，或跳过"看着像例子"的页，下游永远看不见缺口 —— 违反理论 3。
- 公式第一行就用到读者没学过的工具却未标 external，读者卡在第一行 —— 违反理论 4（漏缝）。
- external 节点把整讲复述一遍 —— 违反理论 4（补过头）。
- 导读条凭感觉标"🎯核心"、或按考题频次重排顺序 —— 违反理论 5。
- 官方解答花一整页的小问被压成一行 —— 违反 harvest 的篇幅推论。
- 丢掉老师的题型标签换成自创分类 —— 丢掉了材料作者的结构信息。
