# 故事卡片 · 规格（唯一依据）

一个世界讲完整门课；一节一张卡：故事 / 技术要点 / 和故事的联系 / 计算样例。读者要的感觉是："像读故事一样顺，又把真正的知识和它的前提、陷阱都拿到了。"

## A. 整体结构
1. **开头**：一段引子，说这门课只回答哪几个问题，用世界里的话说；再加一行图例。**结尾**：一段话把各幕串起来。
1a. **前瞻章节**（`parts/1-preview.md`，排在目录之后、第一幕之前）：全课脉络，按故事的幕和集走一遍，每集标出课件页；读者深入学之前，先知道每一集碰到了什么、怎么解决、为什么行得通、留下了什么——细节留给正文，因果不能断。按 `templates/preview.md` 的五步流程做（拆集 → 补缺口 → 写 → 查全 + 冷读者画大图 + 整体顺读 → 修）。两个目的：全（每个要点能在后面的集和 §小节对号入座）、关联大图（每个点是干嘛的、在哪、和谁什么关系）；不负责讲懂：机制的为什么（为什么成立、怎么推）留给正文，衔接的为什么（为什么需要它、为什么走到这一步）一处不能省，三个观念：跟着课件走（内容、例子、集的边界）；集内按理解的路线排，因果和衔接是同一件事；讲事，不讲词；复杂机制当黑箱讲、括号指 §小节。读者认可过一版后，以后只修读者指出的那一处。
   - 形态：开篇 → 各幕（`###`，标题带讲次）→ 各集（`####`，标题带课件页；小块、加粗引子、列表 / 编号 / 表格 / 引用框穿插；集末"还没解决的"）→ 回头看。自足（不写"老师说 / 课件里"），回指前文；向后只用括号指到 §小节。
   - 正文用 `<!-- md -->` … `<!-- /md -->` 包起来，按普通 Markdown 渲染；`##` 进目录一级、`###` 进二级（目录去掉标题末尾的课件页括号），`####` 不进目录。不算卡片，不进 check.py 的覆盖与 forward.py 的超前检查。
2. **幕 = 书的卷**：`## 第X幕　<标题>（卷X）`。幕首一句"这一幕要解决什么"，幕末一句收束。
3. **集 = 书的块**（2–5 章同一个问题），块太大可以拆两集：`### 第 N 集　<情景>`。一集是一个情景或挑战，开业了，遇到问题，后面遇到更多问题，引出新情景。
4. **每集三段**：
   - 开场 2–4 句：出了什么新麻烦、为什么旧办法不够了（接住上一集的钩子）；
   - 本集的五列表；
   - 收尾 1–2 句：解决了什么，留下什么新问题（下一集的钩子）。
5. **出场顺序 = 书的章序**（依赖序）。概念第一次出场时，它依赖的东西已经在前面出现过；不为了故事好看提前抛出后面的概念。
   **不超前引用**：一行的五列（包括 ⚠️、边界、计算样例）只能用到这一章及以前讲过的概念、公式、记号。三种写法都算超前：
   - 点名后面才讲的概念或公式（哪怕加了括号解释）；
   - 指向后面的位置（"见后面某卷""§<后面的节>""后面会讲"）；
   - 用后面的结论来解释眼前的现象。

   陷阱要靠后面的概念才说得清时，只说眼下能说清的那一半（现象和"不能这样算"），把"为什么、正确的关系是什么"留给讲到那个概念的那一行，由它回头点名（"这就是 §<前面的节> 那个错"）。往回引用随便用。由 `scripts/forward.py` 列候选，作者逐条判：
   - 书在这一章以前已经讲过这个概念，只是表里定义写晚了 → 把 `名称（English）：解释` 挪到这里第一次用的地方；
   - 书在后面才讲 → 删掉，或改写成不依赖它的说法。

## B. 表格
6. 五列：`| 在哪 · 性质 | 故事 | 技术要点 | 和故事的联系 | 计算样例 |`。不用算的行，第 5 列留空。
7. **一行只讲一个叙事拍子，基本一节（§）一行**。一格里不塞几段叙事；清单类小节也各占一行，只是写短。同一章的行连着放。一节内容太多（关键公式、考点装不下）时拆成几行，第 1 列写 `§N.M（1/3）`、`§N.M（2/3）`……故事格也接成连续的几拍。
8. **覆盖 100%**：书里每个 `## §N.M` 都出现在某一行的第 1 列，由 `scripts/check.py` 核对，缺 0。

## C. 各列写什么
9. **第 1 列**：`**第N章** 卷X §N.M · <性质>`。**节名**（卡片标签，英文原题照旧并列在后）：
   - 这一节讲的东西**有标准名**（领域里通行的概念、定律、方法、工具、图型名，如"<某定律>""<某种图>""<某展开>"）→ 用标准名，在节号后写 `「<标准名>」` 覆盖书里的中文标题；书里那句理解向的标题不丢，变成技术要点第一行的 `💡`（第 11 条）；
   - 一节讲几样东西 → 标准名用"与"并列（最多三个），还多就取统摄它们的那个名字；
   - **没有标准名**（案例、步骤、某个具体问题）→ 不写 `「」`，沿用书里理解向的标题。
   
   性质记号可以多个：🧠 重理解（机制，要提前懂）· 🧮 重数学（要会算）· 📋 列举可查（清单、步骤、工具名，考场现查）· 🎯 样卷或往年题考过。
10. **故事**：**老师的例子优先进故事**——讲者脉络里老师用来推进这一节的例子（例：油表与电池、水果盒、鸡生蛋……），故事里直接出现它本身，世界只提供场景和角色（例：侦探就去查那块油表），不另造一个结构相同的替身；老师的推进方式（例：悬案 → 反例、"NO!" 式反转）也照着演。只有老师这一节没有例子、或原例撑不起故事时才另造，并在 world.md 意象表的"老师原例"列写明原因。有情景、有"你以为…其实…"的转折，60–120 字（拆成 1/2、2/2 的半格可以短到 30 字），通俗，只用世界里的说法。**每个意象**第一次出现时用括号注对应概念，写成"<意象>（<概念>）"，物件和动作都注，一行有几个就注几个。专业词不在故事里堆，留给右边两列。
11. **技术要点**：这一行真正要学会的知识（心智模型或机制详解），通俗简洁。开头固定两行，再写下面几样：
    - `💡 <洞察>`：这一节最核心的那个想法，一句话说透，不是标题复述。书里理解向的标题（"<一个问句或画面>"）是起点，要把它答出来："<问句>：<答案里那个机制>"；
    - `↩ 承接：<前面哪一节给了什么> → <这一节因此能问 / 能做什么>`：说清这一节是从前面哪个结果的哪一部分长出来的（换个角度读、推广、反过来用、补上它的缺口……），一句话，点名 §。依据 `scripts/links.py` 给出的线索：科技树依赖、正文回指、书的开场过渡。最常见是接上一节；机制上真正靠的是更早某节时，点那一节。只往回指（第 5 条）——书的开场里提到后面的章，不照抄。全书第一节、以及（2/2）这类接自己前半的行，可以写得很短；
    
    其余必须点出的（这一节有的话）：
    - 核心结论与**关键公式**（书里该节的公式卡、书尾公式墙里属于这一节的，一条不漏）；
    - **推导**：由前面的东西推出来的公式，紧跟一组 `推导：<br>1. …<br>2. …`，每步一行、只做一件事（代入、移项、取对数、换求和下标……），2–5 步，读者不翻书也能跟下来。放在公式和"符号"之后；渲染成单独的小方块（HTML 默认折叠、读者选看，PDF 展开），所以推导里不放结论以外的新知识。步骤里用到的工具必须是本行或前面讲过的（第 5 条）。纯定义不推，写"（定义）"加一句为什么这样定义；书里也不推的结论，写"（不推，直接用）"；
    - **考过的知识**：往年题、速查册 🎯 只用来找出这一节哪些知识被考过，确认它们写进了技术要点；行首标 `🎯`，后面直接写知识本身（不写题号、答案字母）；
    - `• 前提：…`（公式或结论成立要满足的条件：书里写的假设、适用范围、口径）；
    - `⚠️ …` 陷阱（书里的 ⚠️ 块、往年题的坑）；
    - `• 边界：…`（什么时候失效，是上界还是下界）。

    **每个概念名词都要提到、都有英文、都有解释**：凡是术语（概念、指标、工具、模型名、缩写），在本幕第一次出现时都写成 `名称（English）：解释`，或者在句中写成 `名称（English，一句白话）`。缩写给全称：`<缩写>（<英文全称>，<一句白话>）`。故事括号里注过的概念，技术要点里必须出现。由 `scripts/concepts.py` 核对。**公式里每个字母都要解释并带单位**，公式后紧跟 `• 符号：<字母> = <含义>（<单位>），…`。
    **每张卡自足**（读者会按复习路线跳着看）：
    - 不写"见上""同上"，这张卡用到的每个字母都在这张卡里解释一遍，哪怕前一张卡刚解释过；
    - 用到别的节推出的公式，在式子后注出处 `（§N.M）`，即第一次推出它的那一节，读者要回看就知道去哪；
    - 字母第一次在全书出现的那张卡之外，解释后也注出处：`S = 服务时间，每次服务多久（秒/次，§11.4）`。
11a. **前置准备节**（为后面打底的数学或概念工具，书里常标"材料外"，如概率规则、极限、积分、级数）：读者要知道"为什么准备它"，而且是从机制上懂，不是"后面要用"。技术要点开头先答三问，再写工具本身：
    `<br>• 它原来解决什么问题：<这个工具当初为什么被发明>`
    `<br>• 核心思想：<一句话>`
    `<br>• 为什么正好用得上：<本课眼下手里有个什么结构或难处（只用已讲过的东西说），这个思想恰好怎样化解它>`

    第三问从机制讲，不点名后面的概念（第 5 条）。故事也要带出这个"难处 → 工具"的转折。
12. **和故事的联系**：两部分。
    - **映射**（必有）：这一行故事里每个意象 ↔ 技术概念，一对一行：`• <意象> ↔ <概念>`。物件、动作、情节都要映射（"谁在等什么、谁让出了什么"对应到机制里的那一步）；故事里有几个意象就列几对。
    - **推理**：
      - 共同的工作结构：用一句因果说清；
      - **最重要的那条前提或陷阱，用 ∵∴ 推出"为什么非这样不可，违反了会怎样"**：∵ 写公式或结论靠的那一步推导 ∴ 由此要求的前提 ∴ 前提不成立时结论怎样失效（数不存在、偏大还是偏小、换成什么才对）；
      - 失效处：比喻在哪里不成立，没有就不写。
12a. **计算样例**：让读者对一遍"我看完技术要点，理解的流程对不对"。🧮 行必写；技术要点里有能代数的公式的行也写；纯概念、清单的行留空。一道口算题，四步，格式固定：
    `题：<场景与已知数，带单位，问什么><br>1. 公式：<用哪条、为什么是这条><br>2. 代入：<把数放进去><br>3. 结果：<算出来，带单位，一句话说这个数意味着什么>`
    - 场景用这门课的真实对象（不用故事世界，好让题和考题同一种说法），数字口算级（整数、整十、0.5、0.8 这类），一步一步能心算；
    - 公式只用这一行和前面讲过的（第 5 条），符号和技术要点里一致；
    - **样例自足**：`1. 公式：` 那步写出式子、出处和每个字母：`R = S/(1 − U)（§14.4）；R = 响应时间（秒），S = 每次服务时间（秒），U = 利用率（0–1）`。只看这一格也能算；
    - 结果后可加一行 `⚠️ 易错：…`，写最常见的算错法（单位、用错分母、忘了前提）；
    - 一行最多两道（`题2：` 接着写），第二道只在换个问法能暴露另一种误解时写；
    - 数要自己验算一遍（可以跑 Python），结果必须对。

## D. 格内写法（Notion 风格短笔记：有文字、有排列、有递进）
13. 并列 → `<br>• 项`
14. 先后顺序（步骤、流程、推导）→ `<br>1. …<br>2. …`
15. 因果、递进 → `<br>∵ 原因<br>∴ 结论<br>∴ 结论`（∵、∴ 各一到几行，多级推导就是 ∴ 接 ∴）
16. 概念诠释 → `<br>• 名称：解释`
17. 陷阱 → `<br>⚠️ …`；考过的知识 → `<br>🎯 <知识本身>`
18. 背景、过渡、承接、叙述 → 直接写句子
19. **不全是 bullet**：一格通常是"一两句叙述 + 0–1 组列表或 ∵∴"；bullet 只留给真正并列的东西，不为结构而结构。

## E. 保真
20. 数、公式、结论只取自书（计算样例的数可以自编，公式和口径取自书）；每章的故事结论与该章 🧠 心智卡"一句话"一致。比喻推不出来的地方，在故事里直说真话，不编一个会误导的比喻。
