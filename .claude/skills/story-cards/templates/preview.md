# preview — 前瞻章节：全课脉络，按幕和集走一遍

> 调度者填好 `{…}` 发给一个 agent（或自己做）。产物：`O/parts/1-preview.md`（排在目录之后、第一幕之前，SPEC 第 1a 条），工作文件 `O/src/work/preview-plan.md`。
> 动笔前调度者先跑 `python3 scripts/preview_index.py <O> <book_dir>`（只要 `world.md` 的集表在就能跑），得到 `O/src/work/section-index.md`：每集覆盖的 §小节和课件页。

根目录 R = `{R}`，书 B = `{B}`（`src/book`，各章 §小节的正文），讲者脉络 LF = `{LF}`（`L*.md`），产物目录 O = `{O}`，小节索引 = `O/src/work/section-index.md`，集表 = `O/world.md` 的「集表」（每集接住什么、留下什么），读者画像 P = `O/src/reader.md` 的「读者」。

## 这一章要做成什么
读者对这门课一无所知，还没读故事。前瞻沿着课程的顺序、用故事的幕和集走一遍全课：每一集碰到了什么，课件拿出了什么，它在大图里起什么作用，之后又冒出什么新问题。每集标题带课件页，读者随时能跳去课件或故事。

前瞻只有两个目的：

1. **全**：所有要点都在，每一个都能在后面的集、§小节和知识点上对号入座。
2. **关联大图**：像一张思维导图，每个点之间是什么关系（为谁服务、接着谁、和谁并列、是谁的特例），每个东西是干嘛的、在大图的什么位置、起什么作用。

它不负责把读者讲懂。用零基础的视角顺着思路把所有的点串起来就够了。"为什么"有两种，要分开：**机制的为什么**（它为什么成立、怎么推出来、细节怎么算）是正文和课件的事，括号指过去；**衔接的为什么**（为什么需要它、为什么从上一步走到这一步、它解决了上一步留下的什么）是大图本身的连线，一处都不能省。它是一张**带着理由的地图**：细节留给正文，因果不能断。

## 四个观念

**跟着课件走，不另起炉灶。**一集就是课件的一段连续页面，覆盖几个 §小节。前瞻讲"课件在这里做了什么"，用课件自己的内容和例子（老师开场的应用、课上算过的那道题），而不是把知识点抽出来重新编一条线、再配一个新例子。课件的推进有跳步、缺动机的地方，讲者脉络已经标出来了，就在那里补上。

**按理解的路线排，不按查阅的顺序。**课件是给懂的人回头查的：先列定义，再用（例：先列出有哪几种分布，再讲用到它们的那个方法）。人理解的顺序正好反过来：先从一个他已经接受的具体例子出发，觉得有道理；再发现哪里不够、冒出一个疑问；为了回答这个疑问，才引出新概念；新概念要用到的定义，到这时才回头补；更深的为什么，指到正文。检验办法：像给一个只读过前几集的朋友当面讲，你第一句说什么？他听完下一句会问什么？下一块就回答这一问。这样排，**因果和衔接是同一件事**：每一块回答上一块留下的疑问，块与块的关系（递进、并列，还是换了一个问题）读者不用自己猜。集内块的先后按这条路线排，§编号只做路标；集与集的先后、每集覆盖哪些 §，仍跟课件。

**讲事，不讲词。**每个概念都是一件事：手上的办法在某个例子上不够了，于是有了它，它带来什么，又接上了前面哪件事。名词是这件事的名字，要出现、加粗，第一次出现时给英文和一句人话；字母和符号可以用，但第一次出现时说清它代表什么。只翻译词、不讲事，读者每个词都认得，合起来仍不知道发生了什么。通俗的意思是普通人读来只有一种解释，不是用词短：日常词如果另有常见意思，就用准确的词再加一句白话（"测量的类型"而不是"量的类型"，"一个变量（比如身高）"而不是"一个数"）。

**复杂的机制当黑箱讲。**好比你知道积木能搭成城堡：怎么搭以后再学，但你得先知道它是积木、会被拼成合适的形状，而这是城堡搭得起来的前提。读者对一个复杂机制也该有这样的轮廓：它是流水线上的哪一环，大概吃进什么、交出什么，为什么一定走得通。箭头里面的过程先不展开，括号指到正文（"见 §x.y"）。这是一种看法，不是要填的格子：讲哪几样、讲多少，由这件事的关键决定。后面一路要用、又能用读者已会的基础和前文讲过的东西演明白的事，就带着具体的例子演一遍。

## 流程：五步，每步都有落在纸上的产物

### 1. 拆集 → `preview-plan.md` 的「集表」
按集读：小节索引里这一集的 §小节在书 B 里的正文，讲者脉络里覆盖这几页的步（连同评价和「老师没讲透的地方」）。每集填一行：

| 集 | 课件页 | 接住上一集的什么 | 这一集的目标，和读者的理解路线（一串"……，觉得有道理 → 可是…… → 所以……"） | 按路线分几块：每块一句引子 + §，和上一块的关系（递进 / 并列 / 换问题），演 / 黑箱 | 用课件的哪个例子 | 讲者脉络标的缺口 | 还没解决的 |

一集一般 3–7 块；一块可以对应一个或几个 §小节，块的先后按理解路线，不必按 § 编号。开篇单独拆：老师开场用的应用例子 → 这门课要回答的那一个问题，和为什么要用这门课的方法回答 → 课件怎么把问题写成能处理的形式（用课上那道题走一遍） → 难处在哪 → 各幕各处理什么。

### 2. 补缺口 → `preview-plan.md` 的「补缺口表」
只补集表里标出来的缺口，其余照理解路线。按四类偏离补（定义见 `full-learn/modules/spine/PARADIGM.md` 理论 1a）：没说为什么要做，就补卡住的那个例子；先用后讲，就挪前或一句话先交代；目的放在最后，就挪到开头；理由偏弱，先找课件里算过的那道例子；课件没算过、后面又不靠它的，只补一句黑箱的外形，不自己编算例。要读者换一个层次看问题的地方（例：把原来当作已知的一个量，本身也当成要推断的对象），明说"这里换了一个层次"。

格式：`| 位置 | 缺口 | 类型 | 怎么补 |`

### 3. 写 → `parts/1-preview.md`
从开篇到最后一集，按顺序一次写完；写到第 N 集时，只用前 N−1 集讲过的东西。

骨架：

```
## 前瞻：<一句话标题>

<!-- md -->
（两三句导读：按课程顺序走一遍；标题括号是课件页，"见 §x.y" 指向故事正文）

### 开篇：这门课在解决什么问题
#### <小标题>
…

### 第一幕　<这一幕处理的事>（<讲次范围，如 L1–L3>）
#### 第 1 集　<这一集讲什么>（<课件页，如 L1 Slides p.5–44>）
…
**还没解决的：**<留给下一集的问题>

### 回头看：几个反复出现的思路
<!-- /md -->
```

`##` 进目录一级，`###`（开篇、各幕、回头看）进二级，目录里自动去掉标题末尾的课件页括号；`####`（集）不进目录。幕名、集名说技术内容（例："贝叶斯网络：只记录直接的影响"），不用故事里的情景标题。块内按普通 Markdown 渲染：`>` 是带底色的引用框，列表和表格前后各空一行。

一集的写法：

- **切成小块。**一块讲一件事，开头一句加粗的引子，说这件事本身，后面带 §（例："**参数本身也不确定，怎么办？**""**把这种结构画成图（§2.3–2.5）。**"），不用"问题：/做法："这类到处通用的标签。一块一般不超过 120 字，只引入一个新概念（并列的列表、表格除外）；长了就拆，或者换成列表。拆的时候不要省掉"读者觉得有道理"的那一步：压缩掉的往往正是理解的台阶。
- **形式跟着内容走，穿插着用。**几样并列的东西用列表；有先后的步骤用 1. 2. 3.；要对比、要列数就用表格；课上的例题用引用框；推理链用一两句连贯的话。一集里不要从头到尾只有一种形式。
- **因果和衔接都要。**集首一句说这一集要达到什么、按什么路线走。之后每块回答上一块留下的疑问；上一块的不够，就是下一块的起因。关系写在明处：递进用"可是……""所以……"或编号，并列的几样放在同一个引子下的列表或表格里，换问题时明说"上面解决了……，接下来……"。读者只扫集首和引子句，也能看出这一集的走向。集末"**还没解决的：**"写留给下一集的问题，下一集开头接住它。
- **例子沿用，能自己验证。**课件的例子一路沿用（例：开篇的一道题、一个贯穿的应用场景，后面反复回到它）；演示只用读者已会的基础和前文讲过的东西。同一个词全章只表示一个意思。
- **指路，不预告。**标题括号写课件页，正文指细节写"见 §x.y"（以小节索引为准）。向前可以回指，向后只用括号指路。不写"老师说"。

篇幅一般是每集 600–1000 字。

### 4. 验：查全 + 冷读者画大图 + 整体顺读 → `preview-plan.md` 的「验收记录」
**查全**：跑 `python3 scripts/preview_check.py <O>`。它查每一集都有标题、课件页和小节索引一致、每一个 §小节都在前瞻里被指到；不 PASS 的，回第 3 步把漏掉的点挂到大图上合适的位置。

**画大图**：派一个不带上下文的 agent，只给它这一章，原样发下面这段：

> 你是这样一位读者：{P，调度者从读者画像抄来，并去掉其中对本课内容的已有了解}。只读 `<章节文件>`，不读别的文件，也不用你自己学过的知识。标题括号里的课件页、正文里"见 §x.y"都是路标，不用去读。
> 你读这一章不是为了学懂，而是为了拿到一张全课的大图：每个东西是干嘛的、在大图的什么位置、和别的点是什么关系。某个东西为什么成立、怎么推出来（机制细节），不是这一章的事，没讲不算缺；但为什么需要它、为什么从上一步走到这一步（衔接），没讲就算缺。
> 每一个加粗引子开头的小块算一步。对每一步回答四问，**每个答案都要引用文中原句**；引不出来，就写"缺"：
> 1. 这一块要解决什么？（原来的办法哪里不够）
> 2. 它是干嘛的、起什么作用？（能不能说出它大概吃进什么、交出什么）
> 3. 它在大图的什么位置：属于这一集路线上的哪一步，为谁服务？
> 4. 它和上一块是什么关系：递进、并列，还是换了一个问题？为什么排在这里？（开头几块可写"无"）
>
> 每集开头先答：这一集要达到什么？（引原句）每集读完，用一句话复述这一集的走向；要靠自己补的地方，标出来。
> 另列五类问题：没说它是干嘛的就用了的词、字母、符号；你能读出两种意思的词；要你换一个层次理解、文中却没点明的地方；你得往回翻才看懂的块（一块里塞了几个新概念也记下）；讲得太深的块（在讲机制的为什么、推导或细节，而这对知道"它是干嘛的、在哪"没有帮助）。
> 最后画出你读到的大图：用缩进列出全部加粗的名词，每个后面用一个词标它和上级的关系（为……服务 / 接着 / 并列 / 是……的特例 / 对比），挂不上去的单独列为"挂不上的点"。
> 输出：只列有"缺"或有问题的步，格式为 `| 位置 | 缺哪问 / 哪个词 | 你卡在哪 |`；再列走向断掉的集；再给大图。最后给统计：总步数、缺几处、词几处、歧义词几处、跳层几处、回读几处、太深几处、断点几处、挂不上的点几个。

冷读者只看得见缺了什么，看不见整体变难读了。所以调度者自己再顺读三集（开头、中间、最后各一集），问两句："只读集首和引子句，能不能说出这一集的目标、路线和每块在路线上的位置？""块小不小、形式有没有穿插？"做不到的，回第 3 步重写那一集，不在原文上补。

### 5. 修：只动断掉的那一环
对每一处"缺"，判断断在哪一环（起因、作用、位置或关系），只补那一环；断点补一句过渡；挂不上的点，补一句它为谁服务；讲得太深的块，删到只剩"它是干嘛的"和衔接，机制细节括号指到正文。不要给词加注释了事，也不要把黑箱修成全套机制。修完，派一个新的冷读者只读改过的集，最多两轮，还剩的写进交付。

读者认可过一版之后，那一版就是这门课的底：以后修改只动读者指出的那一处，不借修补重写整体，也不每轮往里加一层解释。修补一层层叠上去，每处更完整，整体却更难读。

## 对照样例（读者实际卡住过的；以后再有读者卡住，就在这里补一对）
以下样例取自一门概率课，只示范写法；换一门课时学的是推法，不照搬内容。
**词没落地**：
- ✗ "给每种变量选一个常见的形状：是/否、几选一、钟形曲线。形状里只留几个待定的数，再从数据里把它们定下来。"
- ✓ 先讲测量有哪几种类型（硬币的正反、身高），再套现成的模板；每个模板只有一两个可调的数，叫**参数**；钟形曲线写成"中心在哪、摊得多宽"；最后量 100 个人的身高，用平均数当中心，演一遍。

**看似通俗、其实有两种读法**：
- ✗ "量的类型"（读者会读成数量；数量只有大小，哪来的类型）→ ✓ "测量的类型"
- ✗ "连续的一个数（身高）"（读者会读成一个具体的身高数值）→ ✓ "连续的一个变量（身高）"

**先后没有理由**：
- ✗ "**先约定'可能的结果'，再把结果换成数。**"为什么先约定？这个先后对读者有什么意义，没说。
- ✓ 集首先说这一集要达到什么，以及为此先做什么、后做什么、为什么是这个先后；之后每块的引子说它在这条路线上的哪一步。目标和路线从这一集的内容里推出来，不同的集各不相同。

**同一件事的四个版本**（共轭先验）：
- ✗ 太薄："给'正面的可能性'这个数本身也画一条曲线……如果选的曲线和数据配套（这种配套关系叫共轭），……看到一次正面就在'正面次数'上加 1。"每个词都解释了，读者仍然不知道发生了什么：没有卡住的例子，没点明换层，没说这就是贝叶斯更新，没给 Beta 这个名字。
- ✗ 太厚：一段 600 多字，从曲线高度、面积一路算到 0.8³ 和 300 正 100 反。每一句都对，读者却抓不住"这一步到底为了什么"。
- ✗ 全了但难读（按课件顺序拆成三小块）："**参数本身也不确定，怎么办？**……这里换了一个层次……先验……后验。**共轭先验让更新只是改几个数。**……共轭……超参数……"两块塞进五个新概念，跳过了"觉得有道理"和"为什么要共轭"的台阶；分布放在共轭前面，读者不知道为什么先学它。
- ✓ 不是某一条固定的路线，而是同一个推法：从读者已经接受的具体情况出发，每一块回答上一块留下的疑问。比如从"3 次正面"出发，读者先会觉得"估成 1 太冒失"，接着会问"那这个可能到底从哪来"，再问"看到数据该怎么改看法"……一路问下去，先验、贝叶斯更新、共轭、要用到的分布，各自在被问到的那一刻出场；为什么配套的分布乘出来还是同一种，指到正文。台阶分几块、先后怎么排，由"读者下一句会问什么"决定，不同的写作者可以排出不同的路线，只要每一步都接得上。

## 交付（≤ 6 行）
篇幅（字数）、集数；查全是否 PASS；补了几处缺口（按类型计）；冷读者第一轮缺几处、词几处、歧义词几处、跳层几处、回读几处、太深几处、断点几处、挂不上的点几个，最后剩几处；顺读三集的结论。
